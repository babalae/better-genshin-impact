# BetterGI 全自动寻路剧情系统 PRD

**产品代号：** 全自动寻路剧情
**文档版本：** v0.1
**目标平台：** BetterGI
**产品定位：** 在用户未提供当前任务完整路径文件的情况下，自动识别任务阶段，利用已有路网与游戏内自动导航指引前往任务目标，并自动处理剧情、剧情战斗、交互和后续任务阶段。

---

## 一、项目背景

BetterGI 当前已经具备多项相互独立的自动化能力：

C#：
* `AutoSkip`：实时识别和推进剧情、选项与部分交互；
* `AutoFight`：执行自动战斗；
* `PathExecutor`：按照预制路径点执行地图追踪；
* `AutoTrackTask`：通过任务文字、任务距离和屏幕任务追踪标记控制角色向目标方向前进；[AutoTrackTask.cs](https://github.com/babalae/better-genshin-impact/blob/main/BetterGenshinImpact/GameTask/AutoSkip/AutoTrackTask.cs)
* PR #2978：通过历史路线和路线遥测构建导航路网，并在已有路网内自动规划临时路径。[#2978]()

JS：
* `process.json` 流程框架：根据任务描述执行地图追踪、对话、战斗、交互、暂停等流程；[自动剧情加载器](https://github.com/LX666-666/BadGI-JsScript/tree/main/%E8%87%AA%E5%8A%A8%E5%89%A7%E6%83%85%E5%8A%A0%E8%BD%BD%E5%99%A8)
* AutoStoryTranscribe：录制地图路径并生成任务流程文件；[自动剧情录制器](https://github.com/duoduo1232/AutoStoryTranscribe)

当前 `AutoTrackTask` 已具备任务距离 OCR、远距离传送尝试、任务导航按键、任务标记识别和前进控制，但缺少地形规划、运动状态判断、卡死恢复和完整任务闭环。

---

## 二、项目目标

最终实现以下闭环：

```text
识别当前任务阶段
→ 获取或估算任务目标
→ 使用路网规划前往目标附近
→ 切换视觉任务导航
→ 跟随屏幕任务标记或地面黄色指引
→ 判断真正到达任务触发区域
→ 处理剧情、交互或剧情战斗
→ 等待任务阶段更新
→ 继续导航
→ 直到任务完成或安全暂停
```

用户不需要为每一个任务阶段提前准备完整的地图追踪路径。

系统可以使用历史路线、遥测路网和人工制作的任务流程提高成功率，在没有专属任务路径时，使用游戏内视觉引导跟随导航与局部脱困模式。

## 三、核心产品原则

### 3.1 PR #2978 为第一优先级自动导航器

PR #2978 提供的 `RouteNavigationPlanner` 和导航路网应作为自动导航的第一选择。

系统优先使用已有路网完成长距离移动，而不是一开始就根据屏幕标记直线前进。

推荐执行方式：

```text
当前位置
→ 搜索可接入的最近路网节点
→ 在路网中规划到目标附近的最优节点
→ PathExecutor 执行规划路线
→ 到达目标附近或路网尽头
→ 切换 AutoTrackTask
```

路网导航负责：

* 长距离移动；
* 选择合适传送点；
* 复用历史成功路径；
* 规避已知山体、道路和障碍；
* 将角色送到目标附近的路网前沿节点。

游戏内视觉引导跟随导航负责：

* 路网节点至任务触发点的最后一段；
* 目标坐标无法直接获得时的方向追踪；
* 城市和部分室内的地面引导追踪；
* 短距离局部修正。

### 3.2 AutoSkip 常驻运行

`AutoSkip` 属于实时触发功能，应在整个任务自动化过程中常驻后台。

导航过程中进入剧情时：

```text
检测到剧情界面
→ 导航控制器释放移动键
→ AutoSkip 自动处理剧情
→ 等待返回主界面
→ 重新识别任务阶段
```

不需要在每次剧情出现时重新启动 AutoSkip，也不应由流程引擎频繁清空和重建全部实时触发器。

### 3.3 不因普通野怪触发 AutoFight

角色前往任务目标的路上可能经过普通野怪或受到攻击。

这类普通遭遇不得直接触发 AutoFight，否则会导致：

* 导航频繁被中断；
* 被无关敌人拖入长时间战斗；
* 偏离任务目标；
* 误判任务已经进入战斗阶段。

AutoFight 只在系统确认进入“剧情战斗”时启动。

## 四、范围定义

### 4.1 产品范围

系统需要支持：

* 识别当前已追踪任务；
* 识别任务描述和距离；
* 根据任务目标选择传送点；
* 基于历史路网规划长距离路线；
* 在路网尽头切换自动导航；
* 跟随屏幕任务导航图标；
* 跟随地面黄色闪光导航指引；
* 判断角色运动状态；
* 检测卡墙、原地踏步和方向错误；
* 执行跳跃、后退、转向、左右试探等脱困；
* 识别对话、交互和剧情战斗；
* 自动推进剧情；
* 自动完成剧情战斗；
* 任务阶段更新后继续执行；
* 不可处理时保存检查点并安全暂停。

### 4.2 第一阶段不要求

基础版本不要求覆盖：

* 所有谜题；
* 所有机关；
* 所有地下多层地图；
* 所有水下三维场景；
* 所有需要特定元素角色的操作；
* 所有特殊移动机制；
* 完全未知地形上的全局自主探索；
* 通过画面直接恢复完整碰撞地图。

## 六、任务状态机

### 6.1 状态定义

| 状态                   | 说明                     |
| -------------------- | ---------------------- |
| `Idle`               | 未启动或任务已经结束             |
| `RecognizeQuest`     | OCR 识别当前任务描述和距离        |
| `ResolveTarget`      | 获取或估算目标位置              |
| `PlanGraphRoute`     | 调用 PR #2978 规划路网路线     |
| `ExecuteGraphRoute`  | 使用 PathExecutor 执行规划结果 |
| `AcquireVisualGuide` | 搜索任务图标或黄色地面指引          |
| `FollowQuestBeacon`  | 跟随屏幕任务导航标记             |
| `FollowYellowTrail`  | 跟随地面黄色闪光路线             |
| `ConfirmArrival`     | 判断是否真正到达目标区域           |
| `ResolveSceneAction` | 判断对话、交互、剧情或战斗          |
| `StoryDialogue`      | AutoSkip 处理剧情          |
| `StoryCombat`        | AutoFight 处理剧情战斗       |
| `WaitQuestAdvance`   | 等待任务描述、距离或目标更新         |
| `RecoverNavigation`  | 执行卡死和丢失目标恢复            |
| `HumanRequired`      | 当前场景不可自动处理，保存状态并暂停     |
| `Completed`          | 任务完成                   |

### 6.2 主要状态循环

```text
RecognizeQuest
→ ResolveTarget
→ PlanGraphRoute
→ ExecuteGraphRoute
→ AcquireVisualGuide
→ FollowQuestBeacon / FollowYellowTrail
→ ConfirmArrival
→ ResolveSceneAction
→ StoryDialogue / StoryCombat / Interact
→ WaitQuestAdvance
→ RecognizeQuest
```

任何导航状态均可进入：

```text
RecoverNavigation
```

恢复失败超过阈值后进入：

```text
HumanRequired
```

## 七、导航优先级

### 7.1 人工精确流程属于强制覆盖

如果当前任务存在人工制作的 `process.json` 或精确路径配置，可以作为强制覆盖方案。

它不属于自动导航器之间的优先级，而是人工定义的任务补丁。

```text
存在精确任务流程
→ 按流程执行

不存在精确任务流程
→ 进入自动导航体系
```

### 7.2 自动导航优先级

#### 第一级：历史路网规划

使用 PR #2978：

* 获取当前位置；
* 获取目标位置或目标附近区域；
* 搜索当前可接入节点；
* 搜索目标附近前沿节点；
* 规划成本最低的路线；
* 必要时先传送；
* 执行生成的临时 PathingTask。

#### 第二级：地面黄色导航指引

在城市、道路、建筑和部分室内任务中，优先识别地面的黄色闪光点或黄色引导轨迹。

黄色地面指引通常比屏幕上的全局目标方向更能表达：

* 应该走哪条街道；
* 应该在哪里转弯；
* 应该进入哪个门；
* 应该沿楼梯还是走廊移动；
* 室内的正确行走路径。

因此，在检测到可靠黄色地面引导时：

```text
黄色地面指引优先于单纯朝任务图标直线前进
```

#### 第三级：任务导航标记追踪

没有可靠黄色地面引导时，使用改造后的 `AutoTrackTask`：

* 按任务导航键；
* 识别屏幕任务标记；
* 调整水平视角；
* 根据运动状态持续前进；
* 根据任务距离变化验证方向是否正确。

#### 第四级：局部自主恢复

当任务标记存在但角色无法继续前进时：

* 后退；
* 左右转向试探；
* 跳跃；
* 冲刺；
* 调整镜头俯仰；
* 尝试攀爬；
* 重新获取黄色引导；
* 重新按任务导航键；
* 重新规划路网；
* 必要时重新传送。

## 八、黄色地面指引识别

### 8.1 功能目标

新增 `YellowTrailRecognizer`，识别任务过程中出现在地面、道路、楼梯或走廊中的黄色闪光导航点。

适用场景：

* 城市任务；
* 建筑入口；
* 室内走廊；
* 楼梯；
* 部分剧情追踪；
* 连续出现黄色闪光点的任务引导。

### 8.2 识别逻辑

建议结合以下特征：

* 黄色或金黄色高亮区域；
* 位于画面下半部分的地面区域；
* 连续数帧存在；
* 闪烁亮度具有周期变化；
* 多个点大致形成向前延伸的序列；
* 相邻帧中位置符合相机运动和角色运动规律；
* 与拾取光柱、元素特效和场景灯光进行区分。

输出内容：

```text
最近引导点坐标
引导方向
引导点序列
置信度
是否发生转弯
是否可能进入门或楼梯
```

### 8.3 导航方式

```text
识别最近的前方黄色点
→ 调整角色朝向
→ 向该点移动
→ 接近后寻找下一个黄色点
→ 连续形成局部路径
```

任务图标提供全局目标方向，黄色引导提供局部可行路径。

两者可以同时存在：

```text
全局任务图标：防止走错大方向
黄色地面指引：决定当前具体怎么走
```

## 九、运动状态判断

改造后的自动导航必须增加 `MovementStateEstimator`。

### 9.1 需要识别的状态

* 正常行走；
* 奔跑；
* 冲刺；
* 跳跃；
* 下落；
* 攀爬；
* 游泳；
* 滑翔；
* 停止；
* 被障碍阻挡；
* 被敌人攻击造成硬直；
* 镜头转动但角色未移动；
* 角色移动但距离目标没有下降。

### 9.2 判断依据

可以组合：

* 小地图坐标变化；
* 连续帧特征位移；
* 角色动作图标；
* 体力条变化；
* 任务距离 OCR 变化；
* 屏幕任务标记位置变化；
* 输入按键状态；
* 当前移动模式；
* 过去数秒的实际位移。

### 9.3 有效前进判定

角色按住 W 不代表正在前进。

系统应判断：

```text
连续输入前进
且
地图坐标持续变化
且
任务距离总体下降
```

如果只满足输入而不满足位移，则进入卡死判断。

## 十、卡死检测与脱困

### 10.1 卡死类型

| 类型    | 表现               |
| ----- | ---------------- |
| 碰墙    | 持续前进但坐标基本不变      |
| 墙角    | 左右微调仍无法移动        |
| 低障碍   | 可以通过跳跃跨越         |
| 可攀爬墙体 | 前进后进入攀爬状态        |
| 悬崖边   | 目标方向可见但无法直接通过    |
| 错误楼层  | 任务方向正确但距离长期不下降   |
| 引导丢失  | 任务图标或黄色点消失       |
| 战斗硬直  | 被路边敌人攻击导致短暂停止    |
| 镜头错误  | 任务图标在屏幕后方或垂直方向异常 |

### 10.2 恢复策略

按成本从低到高执行：

1. 短暂停止并重新识别；
2. 重新调整镜头；
3. 小角度左转或右转；
4. 跳跃并前进；
5. 后退后斜向移动；
6. 扩大角度绕行；
7. 重新寻找黄色地面指引；
8. 重新按任务导航键；
9. 重新规划到附近其他路网节点；
10. 重新打开地图并选择传送点；
11. 保存检查点并暂停。

每种恢复动作都必须记录：

* 执行前位置；
* 执行后位置；
* 任务距离变化；
* 是否恢复成功；
* 失败次数。

## 十一、剧情战斗判定

### 11.1 设计原则

普通野怪不得触发 AutoFight。

AutoFight 只在 `StoryCombatGate` 判断当前是剧情战斗时启动。

### 11.2 剧情战斗确认条件

满足以下任意高置信条件，或多个中置信条件组合：

#### 明确条件

* `process.json` 当前阶段明确包含 `战斗`；
* 当前任务描述包含“击败”“消灭”“清理”“打倒”“保护”等战斗目标；
* 系统已经确认到达任务目标，随后立即进入战斗状态；
* 任务目标触发后出现敌人，且任务导航暂时消失或任务描述切换为战斗目标。

#### 辅助条件

* 当前任务距离小于到达阈值；
* 最近数秒刚触发任务区域；
* 战斗开始前出现剧情、黑屏、区域封锁或任务提示；
* 敌人出现后任务距离不再显示；
* 战斗结束后任务描述发生更新。

### 11.3 普通野怪处理

导航途中出现普通野怪时：

* 不启动 AutoFight；
* 继续导航；
* 必要时冲刺离开；
* 被攻击导致短暂硬直时等待恢复；
* 若长期被阻挡，则执行绕行或重新规划；
* 只有 StoryCombatGate 达到阈值后才切换战斗状态。

### 11.4 战斗执行流程

```text
确认剧情战斗
→ 释放全部导航按键
→ 暂停导航状态机
→ 执行 AutoFight
→ 等待战斗结束
→ AutoPick 短时处理掉落物
→ 返回主界面
→ OCR 检查任务是否更新
→ 继续下一任务阶段
```

## 十二、剧情与交互处理

### 12.1 AutoSkip

AutoSkip 全流程常驻。

进入剧情时导航器只需要：

* 释放移动键；
* 将状态切换为 `StoryDialogue`；
* 等待 AutoSkip 完成；
* 检查是否返回主界面。

### 12.2 NPC 对话

到达目标后：

1. 识别 F 交互提示；
2. OCR 识别 NPC 名称；
3. 优先选择匹配任务目标的 NPC；
4. 触发交互；
5. AutoSkip 接管对话；
6. 返回后重新识别任务描述。

### 12.3 普通交互

支持：

* 调查；
* 开门；
* 拾取任务道具；
* 启动机关；
* 进入指定区域；
* 按任务阶段配置点击图像或文字。

无法确认的交互应进入有限次数尝试，不能无限按 F。

## 十三、process.json 的定位

新框架继续保留，并承担三类职责。

### 13.1 精确任务模板

对已制作完成的任务，提供最稳定的：

* 路径；
* 对话；
* 战斗；
* 交互；
* 特定角色；
* 特定机关操作。

### 13.2 自动系统补丁

只为自动系统难以处理的环节配置，例如：

```text
进入特殊门
切换特定角色
点击指定文字
执行特殊键鼠脚本
手动暂停
```

其余普通移动仍由自动导航完成。

### 13.3 录制数据输出

AutoStoryTranscribe 继续生成：

* 路径片段；
* 对话指令；
* 战斗指令；

## 十六、异常处理

系统必须保证：

* 所有状态均支持取消；
* 所有导航结束均释放 W、A、S、D、Shift、空格和鼠标键；
* AutoFight 启动前释放导航输入；
* AutoSkip 不应通过清空全部触发器影响其他模块；
* 任意恢复策略均有次数限制；
* 任意状态均有超时；
* 无法判断时优先安全暂停，而不是盲目继续；
* 暂停时输出当前任务、当前状态和失败原因；
* 重启后能够读取检查点继续。

## 十九、最终产品定义

本项目不是简单地把 AutoSkip、AutoFight 和地图追踪顺序调用。

它需要形成一个真正的分层任务执行系统：

```text
PR #2978 负责长距离和已知道路
黄色地面指引负责城市和室内局部道路
AutoTrackTask 负责最终任务方向追踪
运动状态判断负责确认角色是否真正前进
卡死恢复负责处理局部障碍
StoryCombatGate 负责区分剧情战斗与路边野怪
AutoSkip 负责常驻剧情处理
process.json 负责精确任务和特殊场景补丁
AutoStoryTranscribe 负责持续生产任务和路网数据
```

第一版重点不是实现全提瓦特无障碍自主探索，而是证明：

> 在没有当前任务专属完整路径文件的情况下，系统能够利用已有路网接近任务目标，再根据任务图标和黄色地面引导完成最后一段移动，并自动处理剧情或剧情战斗，持续进入下一个任务阶段。
