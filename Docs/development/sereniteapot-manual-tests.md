# 尘歌壶手动测试

测试入口位于「一条龙」页面右侧配置区顶部的「尘歌壶单独测试」。打开页面不会执行测试，只有点击测试按钮才会操作游戏。

## 使用

1. 在要测试的 Windows 会话中退出旧 BGI，打开包含本修复的测试版。使用独立目录时，要保留完整的 Assets、GameTask、运行库和 User 目录。
2. 手动启动原神，进入大世界，并在测试版启动页开启截图器。查看测试卡片上的会话编号和进程号，确认这是当前远程会话中的程序。
3. 打开「一条龙」，点击「背包进壶测试」或「地图进壶测试」。不需要修改一条龙任务列表、默认进壶方式或完成后操作。
4. 默认仅验证进壶，成功后停留在壶内。再次测试前，先手动返回大世界。
5. 需要复现邮件之后的进壶流程时，勾选「先领取邮件」。日志会区分实际领取与没有邮件奖励，邮箱为空的样本不等同于实际领取后的样本。
6. 需要继续定位后续故障时，勾选「继续测试阿圆与奖励流程」。它会寻找阿圆、尝试领取宝钱和好感，然后返回枫丹。此测试不会购买洞天商店物品；不会执行其他一条龙任务或完成后关机/关游戏操作。
7. 可点击「停止测试」，或使用自己配置的「停止当前任务」快捷键。停止按钮只取消本次测试。5 分钟时会请求取消；实际停止需等待当前同步识别或复用的公共操作响应，不是强制终止线程。

测试必须在没有其他任务控制该游戏时进行。同一 BGI 中的测试与独立任务共用互斥锁；此锁不能阻止另一个 Windows 进程控制同一游戏。

## 查看记录

点击「打开测试记录」可直接进入最近一次测试的文件夹：

```text
测试版目录/log/sereniteapot-tests/<测试编号>/
  result.json
  test.log
  ...test-start....png
  ...test-end....png
  ...失败阶段....png
```

- `result.json`：结果、原始失败阶段、起止时间、入口/选项、BGI 与游戏进程、Windows 会话、版本和运行程序集 SHA-256。
- `test.log`：本次测试调用链中的详细日志，包括异步子任务；其他实例和无关任务不会混入此文件。
- 截图：开始、结束、失败阶段；测试奖励时另存奖励操作前后的画面。游戏关闭或截图器失效时，可能只有日志而没有截图。
- 地图切区：记录累计耗时与候选文本；保存前几轮及命中时实际参与识别的截图，文件名带重试编号。切区失败会先恢复主界面，再重新开图，最多尝试 3 次。地图打开、区域菜单识别、选择生效各自设定 30 秒截止时间；同步 OCR 超时后会在其返回时停止继续识别。
- 地图切区后与背包进壶后共用洞天名称检查：在 30 秒内重新截图，确认大地图已打开后才识别名称；连续 3 次读到非空名称才继续，超时或取消不使用此前的识别结果。地图入口失败时不会继续点击住宅和传送，也不会进入阿圆与奖励流程。
- 程序提前崩溃时，结果可能仍是 `created`，不能据此视为成功。测试启动前或收尾过程中出现的问题还应结合普通 BGI 日志。

结果含义：

| 状态 | 含义 |
|---|---|
| `entry-confirmed` | 主界面与壶内标识已稳定确认，进壶流程完成 |
| `reward-flow-finished` | 阿圆与奖励操作及收尾已结束；是否实际领到奖励仍需核对画面，奖励已领空不等于进壶失败 |
| `failed` | 识别/流程检查失败，查看 `FailureStage` 和截图 |
| `cancelled` | 手动取消或任务正常中断 |
| `timed-out` | 超过测试时限 |
| `error` | 执行异常 |
| `not-started` | 未取得任务锁或初始化未完成，没有执行本次测试主体 |

先分别测试背包和地图入口各一次，再根据记录决定需要重复的场景。测试期间不要运行日常一条龙。

## 开发验证

应用应能完整编译。离线回归项目无需启动 WPF、BGI 或原神：

```powershell
dotnet test Test/SereniteaPot.Regression/SereniteaPot.Regression.csproj
```

回归覆盖十秒界面卡顿、旧截图的 OCR 耗时十秒后重新取帧、加载等待、识别闪烁、取消、截止时间、窗口关闭、焦点恢复失败上限及独立测试日志的异步作用域。它们不替代实际图像识别与游戏交互测试。

副作用回归还覆盖：暂停取消后归还自动拾取计数及组件状态、保留其他调用方原有暂停、PostMessage 按键在取消/异常后释放、当前页找到壶时不滚动、无效图像不被当作列表边界，以及截图的数量/大小/期限/并发限制。

秘境兼容性测试在每次构建时通过 Windows PowerShell 从当前生产源码提取 `TaskControl.Sleep`、`AutoDomainTask.StartFight` 和 `DomainEndDetectionTask`。这些方法体保持不变，只替换窗口、输入、OCR 和战斗动作依赖。测试检查局部战斗结束后能返回调用方、父任务取消仍有效、真实错误不会被吞掉；不会实际领取秘境奖励。

入口回归同时提取当前 `GoToSereniteaPotTask` 的地图入口、背包入口、洞天名称检查与 `Execute` 方法体。使用模拟时间、界面和后续奖励操作，验证两个入口在慢加载、名称缺失、地图未就绪及识别中取消时的实际分支；失败不能进入移动和领奖操作。这仍不验证真实 OCR 准确率和游戏领奖结果。

使用 `Test/SereniteaPot.Regression/Verify-Scope.ps1 -BaseRef <比较基线提交>` 核对公共文件：`TaskControl`、普通 `TpTask`、秘境、RunnerContext、TaskRunner 和公共滚动逻辑应与基线相同。公共声明仅允许 `TpTask` 的 `partial`；App 仅允许添加没有手动测试作用域时不工作的日志接收器。项目依赖仅允许 `BetterGI.Assets.Other` 的精确 `1.0.25 → 1.0.27` 差异：PR 共同祖先使用前者，上游 `main` 的 `42e1c0e7` 已使用后者；其他版本或依赖变化仍失败。尘歌壶长等待由专用入口显式调用。

普通运行的自动诊断截图写入 `log/sereniteapot`，最多保留 32 张、64 MiB、14 天；只清理本功能生成的文件，跨进程写入互斥。手动测试目录是主动生成的测试记录，不随自动截图清理。

实机验收需额外覆盖两种入口、已经打开的背包、背包不在顶部、暂停中取消，以及一条龙中尘歌壶完成后连续刷本并领取奖励。离线测试与编译通过不能替代这些验收。
