# 库存数据管理备忘

## 已确认的处理规则（2026-10-29）

- 没有确认库存时仍保留有符号 delta，表格仅显示增减量，不建立零库存。JSON 导出仍仅包含确认库存。
- 失败 delta 可以重新校验；相同失败合并次数，修正或外部条件变化后成功接收则归档对应错误。已接收事件的同内容重传去重，内容变化报冲突，不覆盖、不重复累加。
- 上报使用实际发生或采集时间，保留足够精度，不以批量发送时间替换。总库存必须严格晚于它覆盖的 delta；相同时间提示先后不明。
- 到期信息是内置、默认隐藏的可选字段，不通过补充字典控制。已有到期信息时在现有编辑弹窗内展开数量与到期时间批次编辑；允许部分库存未注明到期时间，批次数量合计不得大于总数。
- 去重凭证暂不拆独立文件。历史 ID 在归档清理成功后删除；确认库存严格覆盖的 delta 凭证可清理，旧 delta 重放可能改为过早拒绝。未覆盖的有效 delta 仍保留去重。失败完整库存上报指纹暂保留。
- 旧版 delta 凭证为不可逆哈希；有对应事件时可迁移，已失去事件的凭证保守保留，不能猜测时间后删除。

## 历史错误核实后的提示

- 正常接收新的有效总库存后，该物品未归档 Error 转为历史证据，移除当前错误对象，并合并为 `VerifiedErrorWarning` 橘灯。
- 提示当前数量已核实，但不表示原错误正确。Warning 可确认归档；后续新错误仍亮红灯。重复旧库存不触发核实。

## 多事件展示

- 卡片捕获事件内容摘要；归档和舍弃在存储锁内整体校验展示版本，任何内容变化均拒绝整次操作。舍弃仅作用于卡片捕获的错误，后来新增的错误保留。
- 有合法发生时间的增量错误，仅由严格更晚的确认库存解除；缺失、非法或超前的增量时间不作为永久阻塞条件，仍可由有效库存核实。旧事件按原始时间证据兼容判断。

- 表格状态灯继续按错误、过期待核实、提醒、其他待核实、完成的优先级显示。
- 底部在限高滚动区展示当前物品全部未归档事项；错误、提醒分别合并，其他状态按事件类型分卡展示。
- 卡片操作固定账号、物品和事件 ID；刷新或切换目标后旧卡片请求失效。待核实不能归档，完成事件仍保留原有阻塞规则。
- step 09～11 构造同一须臾树脂五类事件同时存在，供手工检查覆盖和独立操作。

## 本轮审查修复

- UID 切换保留公共设置，设置修改前读取最新值；重复采集失败合并并保留错误关联；添加 UID 的界面校验与服务层一致。
- `ResolveAsync` 已移除无用的 `displayedEventId` 参数，保留 `eventVersions`；拒绝接受异常的检查移至锁外，以失败 Task 返回，并更新测试名称。
- 所有页面设置命令在存储锁内读取、修改和保存最新设置；保留上限从磁盘读取后供确认，提交时锁内比较该值，变化则拒绝保存及裁剪。
- 批量增量上报只读取一次物品字典。归档保存仅合并变更日期，裁剪日期随主库存记录，清理及备份删除完成后再撤销恢复依据；加载历史仍用于去重和保留上限判断。

## 暂缓事项

- 补充字典可考虑增加仅供记录的扩展参数，不自动生成到期式分组管理，也不在本轮实现通用动态表头。
- 需求验证以后可利用增量（例如 +5）判断达标；涉及负数时报错的细则留待需求模块，本轮不实现。
- 本轮不改变 JSON 交换文件只导出确认库存的用途，不把导出视为完整状态备份。
