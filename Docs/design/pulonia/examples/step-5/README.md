# 步骤 5：新增任务与资源选择验收说明

[返回开发计划](../../development-plan.md) · [添加体验设计](../../user-interface.md)

本步骤不要求启动游戏。请从主菜单“自动化 → 任务计划”验收配置体验、按需资源索引与版本保护；不再设置独立“任务库”菜单。真实路线、JS 和录制执行结果仍按步骤 4 的分类样例验收。

## 1. 创建前配置

1. 在任务计划的树空白处或节点上打开右键菜单，分别选择路线、JS、录制回放、Shell、C# 和内置任务。
2. 核对任务树在弹窗确认前没有新增节点；不同类型展示对应资源选择和参数字段，内置任务可先选择具体能力。
3. 修改名称和参数后确认，核对只新增一次；再次打开并取消，核对树和撤销历史没有变化。
4. 新增分组，核对必须先输入名称，取消不创建“新分组”占位项。
5. 对普通分组、目录引用、计划引用和各类叶子任务分别双击、按 `F2` 或右键“编辑配置”，核对都能打开配置弹窗；任务页不应再常驻节点配置栏。

## 2. 单资源与预览

1. 在路线弹窗核对左侧是可折叠的目录树；搜索部分名称或相对路径时，命中项应保留祖先目录，命中目录应可继续浏览其完整子树。连续输入时树应在短暂停顿后刷新，界面不应逐键卡顿。
2. 在路线、JS 与录制回放的类型专用弹窗中，核对只索引当前类型；选择单个路线或录制文件，详情只展示轻量摘要。
3. 选择 JS 项目，核对右上详情只使用项目原生 Markdown 样式渲染 `README.md`，不再显示拼接的清单元数据或原始 Markdown 文本；缺少 README 时显示明确空状态。
4. 选择带 `manifest.settings_ui`（通常为 `settings.json`）的 JS 项目，核对右下按脚本定义显示文本、单选、开关、多选或级联设置；修改后确认，重新编辑节点 JSON 时 `settings` 应保留相应类型和值。无自定义设置的脚本显示空状态，不再出现通用 `settings` JSON 输入框。
5. 确认后弹窗关闭，节点只在当前插入位置出现一次。

## 3. 整个目录

1. 选择包含子目录的路线或录制目录，先用默认“引用目录”添加，核对树中只有一个引用组且来源包含固定版本。
2. 分别用“展开为任务并保留目录”和“展开为扁平任务”添加同一目录，核对前者保留子目录分组、后者全部放在一个分组中，文件总数一致。
3. 取消“包含子目录”后再次添加，核对只包含所选目录的直属 JSON 文件。
4. 整批添加应只产生一次可撤销编辑；执行一次撤销，整组内容应同时消失。

## 4. 资源版本保护

1. 添加一个单文件任务或目录引用并保存计划，记下右侧展示的固定资源版本。
2. 修改对应资源内容后尝试运行计划，核对应提示资源与固定版本不一致，不能静默执行新内容。
3. 在节点右键选择“确认并更新资源版本…”，核对弹窗同时展示旧、新指纹；取消时计划不变，确认后版本更新并自动保存。

## 5. 资源获取与原工具入口

1. 路线录制与编辑、JS 工具和录制回放继续从原有专用页面进入，核对其入口未受新增任务流程影响。
2. 在资源型任务的新增弹窗中点击“获取更多资源”，核对可使用现有来源更新、在线下载与离线导入；关闭仓库后，当前类型自动刷新并显示新安装资源。

## 6. 大目录边界

使用接近一万项的固定测试目录检查对应类型弹窗的首次索引、搜索和整目录添加。列表滚动应保持可响应；未打开该类型弹窗时不得预扫描其目录。索引超过安全上限时必须显示截断提示，确认整目录添加若超过上限必须整体失败，不能生成不完整任务树。
