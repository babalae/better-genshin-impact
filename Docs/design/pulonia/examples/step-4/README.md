# Pulonia 步骤 4：游戏能力适配验收

[返回开发计划](../../development-plan.md) · [执行设计](../../execution.md)

步骤 4 将需要游戏的节点统一接入同一个会话与输入所有权边界。运行前不要求先打开启动页或脚本页；协调器会按需启动 `GameRuntimeService`，等待现有 `TaskSemaphore`，进入任务模式。节点返回、失败、超时或取消后，会先释放全部按键、退出任务模式并归还任务锁，再更新最终结果或运行下一节点。相邻游戏节点可复用已经启动的游戏会话；会话不会被纯 `shell`、`csharp` 节点启动。

以下四类适配分别验收，均在主菜单“任务计划”中新建节点、填写资源路径或参数后，从“运行”页签提交。

## 4.1 地图追踪

新增“地图追踪”，`path` 默认相对于 `User\AutoPathing`，也接受绝对路线文件路径。可填写：

```json
{
  "party_name": "",
  "skip_party_switch": false,
  "auto_pick_enabled": true,
  "auto_fight_enabled": true,
  "auto_skip_enabled": true
}
```

验收正常路线时，节点结构化结果应包含 `success_end: true`、实际完成的战斗次数及提交时资源指纹；路线未走完必须为失败，不能因方法正常返回而误判成功。运行中取消后，等待当前路线退出并确认移动键、鼠标键均已释放，再允许下一节点取得输入。

JS 中 `pathingScript.Run*` 现在返回路线的 `SuccessEnd` 布尔结果，异常不再只写日志后伪装成功；直接路线和 JS 子调用共用同一取消令牌。

## 4.2 JS 项目

新增“JS 脚本”，`path` 指向 `User\JsScript` 下的项目目录。参数中的 `settings` 原样注入脚本，其余字段建立脚本内部路线使用的队伍配置：

```json
{
  "settings": {},
  "party_name": "",
  "auto_pick_enabled": true,
  "auto_fight_enabled": true
}
```

Pulonia 在 V8 创建前安装当前节点令牌。`genshin`、`dispatcher`、`pathingScript`、`keyMouseScript` 以及脚本组兼容入口均读取这个异步上下文；普通旧入口没有 Pulonia 上下文时仍回退到原全局令牌。取消会中断 V8，并在脚本及子任务真正退出后释放输入。

旧 JS 未声明资源需求，因此本步骤按游戏脚本处理。纯计算 JS 的显式能力声明仍是后续能力清单工作，不影响 `shell`、纯计算 `csharp` 的无游戏路径。

## 4.3 键鼠宏

新增“录制回放”，`path` 默认相对于 `User\KeyMouseScript`。默认不额外倒计时；需要人工观察时可配置：

```json
{
  "with_delay": true
}
```

取消宏后，执行器会确认令牌并由游戏租约统一 `InputHub.ReleaseAll()`。验收时可录制包含长按的短宏，在长按阶段取消，确认键位没有持续按下，下一游戏节点可以正常取得任务锁。

## 4.4 内置任务

右键“添加内置任务”会先选择具体能力，而不是建立不可执行的占位类型。本步骤接入：返回主界面、领取邮件、领取纪行、领取历练点、领取每日奖励、合成浓缩树脂、领取尘歌壶奖励。

每日奖励支持 `country` 和可空 `party_name`；合成浓缩树脂支持对应路线已有的国家。适配器调用会抛出错误的 `DoOnce`/底层方法，避免原 `Start` 包装吞掉异常。JS 的邮件、纪行、历练点、尘歌壶入口也使用相同的可观察异常方法。

大型参数化任务（秘境、首领、地脉、幽境）已经能在旧 JS `dispatcher` 中继承本次取消上下文，但其 Pulonia 专用强类型表单和稳定参数合同尚未在本步骤伪造；这些能力要随新增任务流程和迁移清单逐项接入、验收。

## 共同回归

1. 未启动截图器时先运行一个纯计算 C# 节点，确认不会出现找窗或启动游戏行为。
2. 再运行任一游戏节点，确认无需先打开启动页即可按需准备会话。
3. 游戏节点执行中点击取消，确认界面先保持“停止中”，输入释放和执行器退出后才进入“已取消”。
4. 紧接着运行纯 C# 或 Shell，确认不会再次请求游戏输入锁，也不会因前一节点留下按键而受影响。
5. 同一 JS 内依次调用路线、宏或 `dispatcher` 内置任务，取消父 JS，确认所有子调用观察同一令牌。

本步骤只提供进程内运行状态；历史、CD、节点续跑和高价值动作的后置核验属于步骤 6 及后续步骤。
