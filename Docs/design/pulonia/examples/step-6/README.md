# 步骤 6：CD、历史与节点续跑验收说明

[返回开发计划](../../development-plan.md) · [结果与存储设计](../../results-and-storage.md) · [执行与续跑设计](../../execution.md)

步骤 6 使用 `User/Pulonia/state.json` 统一保存当前队列、活动运行、未决操作和 CD/额度；结束结果写入 `User/Pulonia/history/<planId>/<runId>.json`。主导航“执行记录”和任务计划内“执行记录”标签复用同一浏览器，同时列出当前状态与跨重启历史。全局入口不依赖现存计划，删除计划后仍可查看旧历史。

## 1. 历史与节点续跑

1. 运行一个包含多个纯 C# 或 Shell 节点的计划，让中间节点失败或取消运行；重新启动 BetterGI，确认历史、节点结果、结构化完成程度和证据仍可查看。
2. 选中该历史并点击“继续未完成节点”，确认沿用历史快照、跳过已经成功的节点，从第一个未完成节点继续。
3. 在节点结果列表选中任一节点，点击“从选中节点开始”，确认新运行显示关联的原运行 ID，并按原快照的节点顺序从该地址开始。
4. 修改原计划后再继续历史，确认续跑仍使用旧参数；修改或删除旧路线、JS、录制资源后继续，确认资源指纹不一致时明确拒绝精确续跑。

## 2. 日、周、月、滚动 CD 的受控样例

新增“进程内 C#”节点，在参数中把 `operation` 分别设为：

- `sample.ledger.daily`：账号作用域，每日 4 点重置，额度 1。
- `sample.ledger.weekly`：世界作用域，每周一 4 点重置，额度 1。
- `sample.ledger.monthly`：账号作用域，每月 1 日 4 点重置，额度 1。
- `sample.ledger.rolling`：世界作用域，确认后滚动冷却 60 秒。

可附加 `event_key`、`units`、`occurred_at`、`report_twice` 和 `delay_milliseconds`。第一次运行后，“当前 CD”详情标签应显示作用域、确认时间、证据来源和下次可执行时间/周期；同一作用域再次运行会按规则跳过。`report_twice: true` 会连续提交相同事件，账本及历史的 `confirmed_effects` 都只能增加一次。

进程内调用可以分别填写 `AccountId`、`WorldOwnerAccountId`、`Server` 和 `ServerUtcOffsetMinutes`。用两个已绑定账号提交相同日/月样例应各自计数；两个账号填写同一世界拥有者运行周/滚动样例应共享限制。计划名、节点 ID 和计划复制不参与 CD 身份。

## 3. 部分成功与崩溃窗口

1. 将 `operation` 设为 `sample.ledger.partial`。样例会先同步保存确认事件，再返回“部分成功”；确认计划失败但该局部事实仍保留，重新运行不会重复消费。
2. 将任一账本样例的 `delay_milliseconds` 设为较大值。节点进入运行后直接结束 BetterGI 进程，再启动；确认遗留活动运行变成“待处理”，未决操作阻止“继续未完成节点”自动重放。
3. 核验游戏/样例状态后，在历史中选定节点并点击“从选中节点开始”。界面必须再次确认；确认后才释放该未决占用并建立关联运行。

## 4. 文件一致性与恢复

1. 正常结束运行后确认历史文件已写入，且 `state.json` 中不再保留对应 `pending_archives`；归档期间中断后重启，应按同一 `runId` 幂等补写，不能再次执行任务。
2. 人为破坏 `state.json`、保留有效 `state.json.bak` 后启动，确认界面提示发生备份回退，并要求核验遗留操作。
3. 同时破坏正式状态和备份，或制造状态写入失败，确认服务停止新增自动运行，不把账本重置为空继续执行。

旧 JS、路线和录制回放目前只会报告“执行结束但未核验”，不会仅凭正常返回写入游戏资源 CD。真实拾取、奖励、消耗等高精度完成事件仍需相应能力在后续识别覆盖中逐项接入。

## 5. 执行记录 UI/UX 补充验收

1. 全局“执行记录”默认展示全部计划，计划内入口可勾选“只看所选计划”。搜索计划名、节点名、任务类型（支持中文名称）、运行/请求 ID，配合活动、失败、取消、中断及待核验状态筛选。没有记录与筛选无结果应有不同的空状态说明。
2. 选中历史和任一节点尝试，再启动另一个计划；自动刷新不得把选择切换到新运行，所选地址和尝试次数应保持。列表和节点区域支持键盘选择、虚拟化与拖动分隔条，工具栏在窄宽度下换行。
3. “结果与证据”显示本次尝试的时间、耗时、完整消息和证据；“执行输入”展示原快照的参数、来源、资源路径/指纹与策略，不读取当前编辑内容或依赖资源仍在磁盘。“运行信息”展示请求/运行 ID、账号/世界、来源和续跑关联，并可复制完整原快照。
4. 类型专属内容：Shell 展示退出码、标准输出/错误及各路截断标记；路线展示完整执行/战斗标记，不能冒充采集数量；JS 展示项目、设置与队伍选项；录制回放展示宏文件与延时选择；C# 展示操作、计算输入/返回值及确认事件；内置任务展示当次国家/队伍等参数并说明领取/合成数量未核验。未知返回字段保留，未返回的退出码/bool 不显示成 0/false。所有详情文本可选择复制。
5. “已完成”是计划执行状态，“已执行，未核验”“部分成功”是业务完成程度，必须分别展示；待核验记录有明显提示。从选中节点开始会重新执行其后节点，始终弹出确认，未决副作用另作风险说明。
6. `confirmed_effects` 包含节点地址、尝试次数和完整确认事实，和 CD 账本同次原子提交并随运行归档；即使能力随后失败或进程中断也可在“运行信息”追溯。“当前 CD”明确标注为当前全局账本而非历史时刻快照。旧历史缺少 `confirmed_effects` 时兼容加载，不反推或补造确认事件。
