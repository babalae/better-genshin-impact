# Pulonia：地图追踪文件级采集 CD

2026-10-10 按已确认方案实现。最小单位为单个地图追踪 JSON，同一材料目录内的文件分别计时；材料目录只用于选择规则。适用于 Pulonia 地图追踪节点及目录展开、计划引用、定时、手动和续跑入口。旧入口与 JS 内部调用不接入。

## 成功与失败

全部路径段完整执行后，以文件结束时间估算采集完成；不验证实际拾取数量，也不保存文件内部分成功。提前放弃、结束条件中断、重试耗尽、准备失败、取消和超时均不生成新的采集成功记录。2026-10-12 按用户确认将成功语义统一为“整份路线文件被成功执行”，删除执行器上的结束状态，`Pathing()` 返回 `Task<PathingResult>`；所有成功判断读取本次结果对象的 `IsSuccess`。

新结果直接序列化对象字段，不再生成两套独立结束标记。旧历史中的 `success_end`、`fully_executed` 等字段仅保留展示，不迁移、不回填采集事实，也不参与当前运行资格或成功判定。

## 路线执行结果

`PathingResult` 是每次调用独立返回的不可变对象，所有字段有明确语义：

| 字段 | 当前内容 |
| --- | --- |
| `IsSuccess` | 整份文件成功执行为 true，任一路径段提前退出或重试耗尽为 false |
| `SuccessFightCount` | 本次执行已确认的成功战斗次数，不是实际击杀数；每次开始重新统计 |
| `ErrorMessage` | 空路线、准备失败、提前结束或重试耗尽等已知原因；成功时为空 |
| `ReviveCount` | 为后续完整统计预留，当前为 null；只有已统计且无复活时才为 0 |
| `CollectedItems` | 为后续拾取统计预留的物品名称与数量映射，当前为 null；已统计但无拾取时才为空集合 |

拾取明细在构造结果时复制并只读，后续运行或统计来源修改不能污染已经返回的结果。失败、复活和拾取信息随对象序列化到 Pulonia 运行记录，宿主仍只根据明确成功的完成状态提交文件级 CD。未处理异常和取消仍按原有异常与令牌通道传播，不改变输入清理流程。

## 路线返回值改造影响评估（2026-10-12）

仓库内核对到 8 个实际 `Pathing()` 调用入口，没有发现方法组、反射或其他完整执行属性调用依赖：

| 调用入口 | 返回值处理 | 行为边界 |
| --- | --- | --- |
| Pulonia 地图追踪执行器 | 接收对象，以 `IsSuccess` 转换 `PuloniaTaskOutcome` | 成功才记录 CD，统计和报错原样保留 |
| JS 路线宿主 | 对外返回对象的 `IsSuccess` | JS 返回类型仍为 bool，失败放弃不再误报成功，保留取消检查 |
| 旧配置组 | 使用 `IsSuccess` 输出路线失败提示 | 旧执行记录和锄地规划已移除，不再保存锄地计数或核验战斗次数 |
| 地图编辑器 | 显式忽略返回对象 | 仍只等待试跑结束 |
| 自动首领 | 显式忽略返回对象 | 保留原有寻路后识别与战斗流程 |
| 自动地脉花 | 显式忽略返回对象 | 保留原有花朵识别与运行流程 |
| 前往合成台 | 显式忽略返回对象 | 找到交互目标后允许结束条件提前退出，后续核验合成界面 |
| 前往冒险家协会 | 显式忽略返回对象 | 找到凯瑟琳后允许结束条件提前退出，后续核验对话界面 |

底层返回每次独立的对象：空路线和准备失败返回失败对象；文件内每段的完成状态仍为本次调用局部变量，任一段提前退出或耗尽重试后整份文件不算成功，并保留首个已知失败原因；重试后成功的段不报告过期的重试错误。已有取消捕获、异常传播、路径段重试和按键 finally 释放保留。返回类型为 `Task<PathingResult>`，各宿主随解决方案一起编译。

本次不改变 CD 规则、材料匹配、参数继承、快照、账号作用域、账本身份、原子提交及资源文件格式。定向验证覆盖失败对象不写 CD、成功与统计信息传递、对象序列化往返、拾取明细隔离、未知和零统计展示、取消与超时、跨计划共享和写盘失败。

执行前从账本查询该文件最后成功时间，按本次规则重新计算；在 CD 内将节点标为跳过并继续后续任务。完整成功的节点结果、文件成功事实和运行内确认记录在同一次 `state.json` 原子替换中保存，成功落盘后才推进。事件键为 `pathing.file:<运行 ID>:<节点地址>:<尝试次数>`，资源键为 `pathing.file:<文件身份原文>`，都不做摘要，重复结算不会重复记账。

本能力不提前写入未决采集占用。崩溃发生在成功提交前，按未成功处理，可重跑整份文件；提交后则保留 CD。写盘失败停止运行并阻止新增自动执行，不把采集成功当作普通失败自动重试。

## 身份与规则

- 仓库文件：仓库 ID 与规范化相对文件路径；材料从原始路径识别，不能从提取缓存位置识别。
- 传统文件：规范化绝对文件路径。身份不含计划、节点、版本或内容哈希。
- 同文件跨计划共享，内容更新保留 CD；移动、重命名、复制到新位置为新文件。不同文件的点位重叠不去重。
- 沿用请求的服务器和世界作用域；世界拥有者、已核验 UID、账号及默认作用域按现有账号模块优先级选择。本能力不增加自动识别账号。

目录从文件向上精确匹配最近的材料名或明确别名。运行时使用集中规则表，来源为 [采集物刷新文档](../../technical/genshin-collectable-respawn.md)，不解析 Markdown。特产默认 46 小时，明确植物、食材和生物采用文档对应的 12／24／46 小时，钓鱼类别 72 小时；晶核及明确怪物类别采用下一次服务器 04:00。不确定数据在说明中标为参考规则。

矿石按成功的服务器日期加 1／2／3 天取 00:00，显示“午夜保守估算”；缺少矿点周期锚点，不能宣称是精确刷新日。石珀、夜泊石、清水玉仍按特产 46 小时。明确一次性类别成功后不再自动执行。圣遗物、木材、摩拉盒等混合类别及未知材料不自动限制，允许手动设置；不实现木材循环刷新及调查、击杀、领奖全局额度。

## 设置和记录

`pathing` 参数 `collection_cd` 整体参与默认值、预设、分组、节点和调用覆盖，不深合并字段。缺省为 `{ "mode": "auto" }`。模式包括 `auto`、`disabled`、`rolling`（`hours`）、`daily`（`reset_hour`，默认 4）、`calendar_days`（`days`）、`weekly`（`reset_hour`、`reset_weekday`，周一为 1，周日为 7，默认周一 4 点）和 `once`。数值及日期可表示范围在保存和运行准备时校验。

新增任务提供独立表单；节点及分组设置通过独立草稿确认或恢复继承，变更支持撤销和自动保存，取消不改变模型。表单显示材料、有效规则和来源。准备快照固定规则，排队期间修改设置不改变本次运行。

关闭限制及未匹配规则时，完整成功仍保存时间。下一次提交使用新规则从该时间重新计算；不重写历史规则及历史下次可执行时间，也不从旧“已执行、未核验”记录回填采集成功。运行结果展示材料、规则、最后成功时间、下次可执行时间及“按整份文件执行成功估算采集完成”的依据。
