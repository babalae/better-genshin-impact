## 新手路径

首期体力计划采用绑定路径：选择账号与已有任务计划 → 选择近期培养目标、培养方面优先级与最终兜底 → 绑定方案 → 在任务支持的字段中选择“体力计划” → 查看本次预计安排 → 开始执行。一条龙也是任务计划，采用同一规则；全部计划默认不指定体力方案。

2026-10-12 确认的术语、字段来源组合、无状态规划、预计算与 UI / UX 以[体力计划设计](resin-plan.md)为准，本文保留托管和调度的整体边界。一个账号可保存多套方案；连续或嵌套执行使用输入方方案，子计划不自行替换。自定义树脂用量优先预留，托管只使用剩余资源。

绑定模式的规划器输入为体力方案、已有任务的有效配置与字段来源、实际账号状态和游戏规则，输出对应原任务的有效参数、执行段、树脂分配和解释。不会新增任务树节点、启用关闭的任务或改变顺序；缺少对应能力时显示不能承接的需求。预览与执行使用同一规划器，配置变化不自动操作游戏。

自动生成任务计划是后续能力，本期不提供。后续独立托管入口可以采用“选择账号 → 选择角色及目标练度/物品数量 → 选择运行时间 → 查看今日安排 → 一键托管”的完整路径；内置任务目录按角色、材料、用途检索并维护精选资源包，后台下载、依赖解析和版本锁定让用户无需理解仓库订阅。缺失资源仍需显示下载/不可用状态，来源、版本和权限可在详情中查看。该后续路径不改变当前绑定模式的能力边界。

首期角色培养默认同级，按培养方面分配预算，并优先考虑今日真正受轮换限制的目标材料。合并相同副本和兼容配置的需求，集中备齐有限目标，再安排最终兜底；长期圣遗物刷取不能阻塞其他有限目标。树脂预算贯穿整个账号计划，共享库存只扣除一次，不能每个目标独立分配一份总树脂。

账号状态刷新属于执行准备阶段，不写成新增任务节点。开始时固定配置与方案版本并刷新实际状态；执行中仅重算尚未执行部分，留下本次版本和原因，不改写已执行结果。每次新运行重新读取练度、库存和树脂，不按历史刷取次数、完成标记或轮转游标推算培养进度；单次运行记录只用于追溯。已有资源 CD 与活动资格仍由各自的规则核验。

不能依赖昨天的快照决定今天一定有多少树脂；花费前核验关键数量。读取不到材料数量不等于材料为 0。游戏规则表、材料来源和开放条件需要版本维护，不能由调度器凭空推断。

物品目标必须明确口径：“库存补到 N”使用最新库存计算缺口；“本周期新采 N”使用该周期已确认产出；“角色培养到指定练度”从当前练度与目标重算剩余材料，再扣除可用库存。用户手动使用、合成或消耗材料后刷新相关状态，不能沿用旧总数持续补货，也不能用静态材料阈值假装已经完成角色培养。相关观测缺失时显示待刷新/待确认，不默认目标清零或无限刷取。这三种口径是目标上的字段，不各建一套规划系统。

原粹树脂、浓缩树脂及补充道具分别计算用途、可用预算和用户选择，预算不足时换兼容候选或结束；原石自动补充不进入首期。方案资源偏好仅约束跟随方案的用量，自定义任务明确开启的道具按自身配置处理。圣遗物随机收益和偏好意味着“最佳”应表达为“符合当前目标与预算的推荐安排”，并允许改培养方面优先级。

## 自动识别的实施边界

已有角色接口主要读取指定角色的属性/武器/天赋；背包计数主要面向目标物品。完整 box 枚举、全背包/圣遗物资产建模、装备评估和可靠增量更新仍需独立实现和验证。

分层落地：先用户选目标 + 扫描必要字段；再完善角色集合和物品缺口；最后扩展圣遗物与更复杂培养策略。这个顺序不影响同一执行引擎最终承接全部场景。

## 托管阶段的拟新增实体

以下类型在代码中尚不存在，原列于 `task-model.md`，2026-10-24 移入本提案。

| 实体 | 主要内容 |
| --- | --- |
| `PuloniaPlayerSnapshot` | 账号状态快照：角色、武器、物品、树脂等。每个字段记录观测时间、来源、可信程度；未识别不等于 0 |
| `PuloniaDevelopmentGoal` | 角色或物品目标、目标口径（培养 / 库存达到 / 周期内新增）、目标等级/数量；体力计划内的角色默认同级，培养方面优先级由方案保存 |
| `PuloniaResinPlan` | 按账号保存的具名体力方案，包含培养目标、培养方面优先级、最终兜底和资源偏好；任务计划通过可空引用选择 |

圣遗物逐件属性、配装优化等可后续扩展快照内容，不把这部分复杂度放进执行引擎。体力规划的执行段、分配和预计算结果属于对应原节点的本次运行内容，不写入 `PuloniaTask.Children`，不持久化跨次角色刷取进度。
