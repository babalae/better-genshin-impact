## 1. 定位

体力计划是独立任务 `resin_plan`（任务计划类型 `solo.resin_plan`），放进一条龙中运行。它在一次运行里调度五个已有的独立任务：合成浓缩树脂、自动秘境、自动首领讨伐、自动幽境危战、自动地脉花。每个子任务刷什么、刷几次、用哪种树脂，都由体力计划根据预算决定。任务返回本次消耗树脂得到的全部奖励。

- **账号**：由一条龙负责切号与 UID 核验（见[多账号](../accounts.md)）。体力计划只在当前登录的账号上执行，不保存任何账号数据。
- **培养目标**：以游戏内养成计划为准，体力计划不另设角色选择。秘境需求通过提升指南读取。
- **无状态**：每次运行都重新读取树脂、活动和提升指南，不保存跨运行的培养进度。参数只保存在节点上。
- **子任务是内部步骤**：不写入 `PuloniaTask.Children`，也不新增任务计划节点。

| 术语 | 含义 |
| --- | --- |
| 预算 | 本次允许消耗的树脂点数。原粹按实际点数计，浓缩每枚计 60 |
| 阶段 | 体力计划内部按固定顺序执行的步骤，每个阶段调用一个子任务 |
| 移涌活动 | 地脉移涌、盛材移涌、祝圣移涌。活动期间每天有 3 次双倍奖励 |
| 双倍次数 | 移涌活动详情中的“今日剩余多倍产出次数”，记为 r。原粹 20 档领取一次用掉 1 次，40 档用掉 2 次 |
| 移涌领取 | 在活动适用的内容里先用原粹领取几次，把当天的双倍次数用掉，见 [7.3](#73-各活动的执行方式) |
| 紊乱爆发期 | 幽境危战的奖励阶段，只有在这个阶段才能在危战中消耗树脂 |
| 提升指南 | 冒险之证中的“秘境 → 提升指南”，按游戏内养成计划列出可刷的材料秘境 |
| 剩余承接 | 养成结束后剩下的预算，由第一个开启且可用的子任务全部用掉 |

## 2. 范围

包含：

- 设置：体力用量上限、优先合成浓缩、参与任务开关、活动优先、活动严格用量；
- 五个子任务的调度；
- 秘境养成沿用提升指南方案；
- 识别并优先处理移涌活动和紊乱爆发期；
- 汇总全部奖励。

不包含：

- 须臾树脂、脆弱树脂和原石；
- 周本；
- 按角色选择秘境或首领；
- 自动升级、突破和材料合成；
- 圣遗物评分；
- 跨运行或跨账号共享预算；
- 自动生成任务计划；
- 危战勋望进度识别：本期只预留执行类，见 [7.9](#79-危战勋望进度识别预留)。

## 3. 参数

| 参数 | 字段 | 默认 | 说明 |
| --- | --- | --- | --- |
| 体力用量 | `max_resin` | `0`（全部） | `0`：用完当前全部原粹和浓缩；大于 0：本次最多消耗这么多点 |
| 优先合成浓缩树脂 | `craft_condensed_first` | 否 | 是：刷取前先把可用原粹合成浓缩，见 [5.3](#53-合成浓缩) |
| 参与任务 | `domain.enabled`、`boss.enabled`、`stygian.enabled`、`ley_line.enabled` | 秘境开、首领关、危战开、地脉花开 | 首领战斗不稳定，默认不开启 |
| 优先满足活动 | `event_priority` | 是 | 移涌活动和紊乱爆发期优先使用树脂，见[第 7 节](#7-活动优先)（11.2 加入）。已有节点参数为空时按默认值开启 |
| 严格使用 60 树脂 | `event_strict_resin` | 否 | 只在移涌领取中生效。r=3 时，关闭：40 档领取 2 次，消耗 80 原粹；开启：20 档领取 3 次，正好 60 原粹。其他 r 见 [7.4](#74-移涌领取的用量)（11.2 加入） |

每个子任务的设置沿用它现有的参数类，嵌套在节点参数中（`ResinPlanSubTask<TParam>`：`enabled` 与 `param`）。下表中的字段在运行时由体力计划改写，因此在子任务设置里隐藏。其余字段照常生效，例如队伍、战斗策略、国家、提升指南选项、备选秘境、超时。

| 子任务 | 由体力计划决定的字段 |
| --- | --- |
| `domain`（`AutoDomainParam`） | `resin_usage`、`domain_name`、`sunday_selected_value`、`training_guide_calculate_runs_enabled`、`reward_recognition_enabled`、`target_items`、`training_targets_json` |
| `boss`（`AutoBossParam`） | `reward_recognition_enabled`、`target_items`；`combat_strategy_path` 隐藏，修改战斗策略时与 `strategy_name` 同时写入。`resin_usage` 保留，只取其中的次数（见下文） |
| `stygian`（`AutoStygianOnslaughtParam`） | `resin_usage`，以及 [7.9](#79-危战勋望进度识别预留) 新增的 `dire_prestige_target`；`combat_script_bag_path` 隐藏，修改战斗策略时清空 |
| `ley_line`（`AutoLeyLineOutcropParam`） | `resin_usage`、`target_items` |
| `craft`（`CraftCondensedResinParam`） | `min_resin_to_keep`，以及新增的 `craft_count`（合成浓缩树脂的设置页也不显示它） |

战斗策略的联动方式与该任务专属设置页一致，避免任务优先读取的隐藏字段让修改不生效。

秘境设置中由用户选择、体力计划会读取的三个秘境（设置弹窗中都是按国家分组的秘境选择框）：

| 字段 | 名称 | 用途 | 可选秘境 | 空值的含义 |
| --- | --- | --- | --- | --- |
| `training_guide_fallback_domain_name` | 备选秘境 | 阶段 5 的剩余承接 | 全部材料与圣遗物秘境 | 不承接，保留剩余树脂 |
| `material_overflow_domain_name` | 盛材移涌秘境 | 阶段 2 的盛材移涌领取 | 精通秘境、炼武秘境 | 跟随培养计划：按提升指南选择秘境 |
| `blessing_overflow_domain_name` | 祝圣移涌秘境 | 阶段 2 的祝圣移涌领取 | 祝圣秘境 | 跟随培养计划：刷提升指南中养成角色推荐圣遗物所在的秘境 |

- 两个移涌活动秘境字段新增在 `AutoDomainParam` 中（只增不改），只在体力计划中生效。选择框的首项是“跟随培养计划”，选中或清空都保存为空字符串。
- 普通自动秘境节点不读取、也不显示这两个字段（列入 `AutoDomainSettingsViewModel.EditedParameterNames`，与合成浓缩的 `craft_count` 相同）。
- 地脉移涌没有秘境，沿用自动地脉花子设置的国家与类型。
- 备选秘境与移涌活动无关，见 [7.3](#73-各活动的执行方式)。

参数示意（子任务字段省略）：

```json
{
  "max_resin": 0,
  "craft_condensed_first": false,
  "event_priority": true,
  "event_strict_resin": false,
  "domain": { "enabled": true, "param": { "party_name": "养成队", "training_guide_fallback_domain_name": "",
              "material_overflow_domain_name": "", "blessing_overflow_domain_name": "" } },
  "boss": { "enabled": false, "param": { "boss_name": "", "resin_usage": { "mode": "RunCount", "run_count": 1 } } },
  "stygian": { "enabled": true, "param": { "boss_num": 1 } },
  "ley_line": { "enabled": true, "param": { "country": "蒙德", "ley_line_outcrop_type": "启示之花" } },
  "craft": { "country": "枫丹" }
}
```

首领的讨伐次数沿用首领自己的树脂使用设置，不另设参数：

- 指定次数：每次运行最多讨伐该次数；
- 刷至耗尽：不设次数上限，只受体力用量与原粹限制；
- 体力计划只使用原粹，首领设置中的须臾、脆弱补充不生效。首领设置弹窗中的树脂编辑器不提供这两项（能力 `ResinPlanBudget.BossCapability`）；
- 体力计划内的首领默认“指定次数 1 次”，避免开启后在养成之前用光树脂。

体力计划不使用节点编排参数 `total_run_count_limit`。

## 4. 执行流程

```mermaid
flowchart TD
    P[0 准备：读树脂，识别活动] --> C{优先合成?}
    C -- 是 --> C1[1 合成浓缩]
    C -- 否 --> E
    C1 --> E{优先满足活动且有活动?}
    E -- 是 --> E1[2 活动：地脉移涌 → 盛材移涌 → 祝圣移涌 → 紊乱爆发期]
    E -- 否 --> B
    E1 --> X{爆发期危战要求暂停养成?}
    X -- 是 --> R
    X -- 否 --> B
    B[3 首领：固定次数] --> D[4 秘境养成：提升指南]
    D --> R[5 剩余承接：危战 → 地脉花 → 备选秘境 → 保留]
    R --> S[6 汇总奖励与消耗]
```

| 阶段 | 执行条件 | 内容 |
| --- | --- | --- |
| 0 准备 | 总是 | 1. 回到主界面，在大地图顶栏读取原粹当前值、上限和浓缩数量（`ResinRecognition.RecognizeInBigMapTopBar`），计算预算。原粹读不到时任务失败（`resin_unknown`），不消耗树脂。<br>2. 开启“优先满足活动”或危战开启时，打开活动页识别活动，见 [7.2](#72-识别方式) |
| 1 合成浓缩 | 开启优先合成，且读到了浓缩数量 | 按 [5.3](#53-合成浓缩) 算出份数后合成，完成后重新读取顶栏 |
| 2 活动 | 开启“优先满足活动”，且识别到移涌活动或紊乱爆发期进行中 | 按 [7.3](#73-各活动的执行方式) 依次执行移涌领取，再按 [7.5](#75-紊乱爆发期) 执行危战。危战在爆发期用掉树脂后暂停阶段 3、4 |
| 3 首领 | 首领开启，且未被紊乱爆发期暂停 | 按首领自己的树脂使用设置讨伐（指定次数或刷至耗尽），只用原粹 |
| 4 秘境养成 | 秘境开启，且未被紊乱爆发期暂停 | 按[第 6 节](#6-秘境养成沿用提升指南)执行。提升指南的全部候选需求满足，或预算用尽时结束 |
| 5 剩余承接 | 预算仍有剩余 | 依次检查危战、地脉花、备选秘境，由第一个开启且可用的任务用掉全部剩余预算；都不可用时保留剩余树脂。危战：活动页显示爆发期已结束时跳过（`event_ended`）；阶段 2 已执行过危战时不再执行；其余情况照常尝试，由危战任务自己判断是否已结束 |
| 6 汇总 | 总是 | 合并各步骤的奖励与消耗，见[第 8 节](#8-返回结果) |

- 子任务执行后，持有量标记为已变化；下一个需要树脂的阶段开始前重新读取顶栏树脂。没有执行子任务的阶段不重复读取。
- 剩余预算按子任务报告中 `ResinUsageReport.Consumed` 折算的点数扣减（原粹按点数，浓缩及战前补充每个 60 点）。
- 预算不足一次领取时，后续阶段跳过，原因为 `budget_reached`；预算足够但持有量不足时，原因为 `resin_exhausted`；读不到树脂时只跳过当前阶段，原因为 `resin_unknown`。
- 子任务在体力计划内直接创建并通过 `ExecuteAsync` 调用（与“领取每日奖励”组合子任务的方式相同），共用体力计划的 `GameRuntime` 和取消令牌。参数先按 `SoloTaskJson` 复制一份再改写，节点参数不受影响。

## 5. 预算与树脂

### 5.1 点数口径

- 只使用原粹和浓缩。子任务允许的树脂种类会被改写为这两种，首领的战前补充（须臾、脆弱）强制关闭。
- 原粹按实际花费的点数计（20、40）。浓缩每枚计 60 点，一次领取可得 3 份奖励。
- 全部模式：不设点数上限，每个阶段只受当时读取的持有量限制；运行期间自然恢复的原粹由后续“刷至耗尽”的阶段顺带用掉。
- 限定模式：预算 B = `max_resin`，每个阶段同时受剩余预算和当时的持有量限制。只计领奖花掉的点数；合成浓缩是转换，不计入。
- 浓缩图标已显示但数量识别失败时，视为“至少有 1 个”：全部模式照常刷至耗尽，限定模式不安排浓缩次数，也不合成。

### 5.2 各阶段的树脂设置

R 为本阶段开始时的剩余预算，O、C 为当前估算的原粹和浓缩数量。

| 情况 | 子任务的 `resin_usage` |
| --- | --- |
| 移涌领取 | `PerType`：只用原粹（浓缩次数为 0），次数与档位按 [7.4](#74-移涌领取的用量) 计算。r=3 时，严格关闭为 40 档 2 次（80 原粹），严格开启为 20 档 3 次（60 原粹） |
| 首领 | `RunCount = min(首领设置的次数, ⌊min(R, O)/40⌋)`；首领为刷至耗尽时取 `⌊min(R, O)/40⌋`。只允许原粹 |
| 限定模式下的其他阶段 | `PerType`：浓缩 `c = min(C, ⌊R/60⌋)`，原粹 `min(⌊O/20⌋, ⌊(R − 60c)/20⌋)`，档位 `Only20` |
| 全部模式下的秘境养成、紊乱爆发期、剩余承接 | `Exhaust`，允许原粹和浓缩，档位按任务默认 |

次数算出为 0 时跳过该阶段，原因为 `budget_reached`。

### 5.3 合成浓缩

开启“优先合成浓缩树脂”时，在刷取之前合成：

```text
可合成原粹 X = 全部模式：O；限定模式：min(O, B − 60 × C)
X = X − 活动预留 − 首领预留
份数 k = min(5 − C, ⌊X / 60⌋)
```

- 限定模式下已有的浓缩先占用预算，避免合成本次用不上的浓缩。
- 活动预留：本次会执行的每个移涌领取都按 [7.4](#74-移涌领取的用量) 预留原粹：严格关闭为 40 × ⌈r/2⌉，严格开启为 20 × r（r=3 时分别为 80、60）。“会执行”指前提满足且 r > 0（见 [7.3](#73-各活动的执行方式)）。双倍只对原粹生效，所以要先留出来（11.2 加入）。
- 首领预留：首领开启、且未被紊乱爆发期暂停时，预留 40 × 首领设置的次数；首领为刷至耗尽时保留全部原粹，不合成。开启优先满足活动且爆发期进行中时，首领会被暂停，不预留。
- 两项预留按饱和加法相加，首领刷至耗尽（`int.MaxValue`）时结果仍为“全部保留”，不会溢出。
- 浓缩数量未识别时不合成。
- k 大于 0 时，调用合成任务并传入新增的 `craft_count = k`。指定份数后，合成任务按份数合成，忽略 `min_resin_to_keep`。
- 关闭“优先合成”时不合成，已有的浓缩照常使用。

## 6. 秘境养成：沿用提升指南

秘境调度直接使用自动秘境现有的“根据提升指南选择秘境”方案（#3729），行为不做限制：

- 需求来自游戏内养成计划。提升指南列出当天可刷的材料秘境，入口浮窗给出“培养需求 X/Y”。
- 一个秘境的需求满足后，继续刷提升指南中的下一个候选秘境，直到全部满足或预算用尽。
- 次数计算、合成收益预留、按识别到的奖励更新库存、识别失败时按固定预算继续、低冒险等阶适配、诊断记录，这些设置都留在 `domain` 子设置中。
- 只规划天赋书和武器突破材料。圣遗物秘境不在养成范围内。

体力计划运行这一阶段时，改写以下字段：

- `domain_name` 设为提升指南选项，`training_guide_calculate_runs_enabled = true`，`reward_recognition_enabled = true`；
- 本次调用中清空 `training_guide_fallback_domain_name`，备选秘境改到阶段 5 执行，保证剩余承接的顺序固定。用户保存的值不变。

盛材移涌的双倍次数在阶段 2 单独领取（见 [7.3](#73-各活动的执行方式)），本阶段照常运行，不新增参数。原方案在本阶段新增 `TrainingGuideEventClaims` 和 `TrainingGuideEventOriginalTier`，限制前 N 次领奖只用原粹，现已取消，原因见 [7.10](#710-设计取舍与待确认)。

## 7. 活动优先

### 7.1 活动与规则

| 活动 | 适用内容 | 双倍奖励 |
| --- | --- | --- |
| 地脉移涌 | 地脉之花 | 摩拉、角色经验书 |
| 盛材移涌（旧名精通移涌） | 精通秘境、炼武秘境 | 天赋培养素材、武器突破素材。天赋和武器合并在同一个活动中 |
| 祝圣移涌 | 祝圣秘境 | 圣遗物。有幽境危战后大概率不再开放，仍保留支持 |
| 幽境危战·紊乱爆发期 | 幽境危战 | 不是固定双倍。爆发期内满足条件后，可以消耗树脂领取圣遗物，并累计「危战勋望」以获得额外圣遗物奖励 |

移涌活动的通用规则：

- 每个移涌活动每天 3 次双倍，按服务器游戏日（凌晨 4 点）重置。
- 双倍由游戏自动生效：在适用内容中用原粹领取时，游戏按当天剩余次数给双倍，体力计划不需要额外操作。
- 只有原粹享受双倍。浓缩既不享受双倍，也不消耗双倍次数。
- 20 档领取一次用掉 1 次双倍，40 档用掉 2 次。只剩 1 次时用 40 档，只有一半享受双倍，另一半按普通奖励结算。
- 当天剩余的双倍次数读不到，一律按完整 3 次安排。当天已经用过的话，多出的领取按普通奖励结算，树脂不会浪费。
- 体力计划的用法（严格开关）见 [7.4](#74-移涌领取的用量)。

### 7.2 识别方式

识别在阶段 0 读完树脂后进行，满足任一条件时执行：开启“优先满足活动”；危战开启（需要知道紊乱爆发期是否已结束）。两者都关闭时不打开活动页。

识别步骤（`ResinPlanEventDetector.DetectAsync`，已实现）：

1. 回到主界面，按 F5（`GIActions.OpenTheEventsMenu`）打开活动页，确认左上角出现“活动一览”。没打开时再按一次。
2. 按住 W 约 4 秒回到列表顶部，读取顶部可见的一屏。新活动排在最上面，所以只读这一屏；不在这一屏的活动按“没有”处理。
3. 对列表中出现关键词的移涌活动逐个点开，读取详情中的“今日剩余多倍产出次数”（例如 `3/3`、`已用完`）。
4. 在列表中点开幽境危战（看不到时按 S 逐项下移，最多 15 次），读取页面中部的紊乱爆发期提示。
5. 回到主界面。

| 判定结果 | 关键词 |
| --- | --- |
| 地脉移涌 | 「地脉移涌」 |
| 盛材移涌 | 「盛材移涌」或旧名「精通移涌」 |
| 祝圣移涌 | 「祝圣移涌」 |
| 紊乱爆发期 | 幽境危战页面出现「紊乱爆发期」；同时出现「已结束」为已结束，否则为进行中 |

识别结果（`ResinPlanEventReport`）：

| 字段 | 内容 |
| --- | --- |
| `recognized` | 是否打开了活动页并读到了列表；为 false 时其余字段不代表游戏状态 |
| `overflows` | 每个移涌活动一项：种类、剩余次数 r（“已用完”为 0，读不到为空，调度时按 3）、每日上限 |
| `stygian_burst` | 进行中、已结束、未识别（进入了危战页但没读到提示）、未找到危战 |

- 关键词集中定义在 `ResinPlanEventDetector` 中。只支持简体中文界面，与提升指南一致；其他语言识别不到活动，按“没有活动”处理。
- 识别失败时也按“没有活动”处理，不暂停养成。
- 危战任务现有的“紊乱爆发期已结束”识别继续生效。活动页误判时，危战返回 `Skipped(event_ended)`，体力计划随后恢复阶段 3、4。

### 7.3 各活动的执行方式

移涌领取是阶段 2 中单独执行的一次子任务：在活动适用的内容里先用原粹领取几次，把当天的双倍次数用掉。领取完成后，阶段 3—5 照常执行。

| 活动 | 前提 | 阶段 2 执行的子任务 | 前提不满足时 |
| --- | --- | --- | --- |
| 地脉移涌 | 地脉花开启 | 自动地脉花。国家、类型、队伍等沿用地脉花子设置，树脂按 [7.4](#74-移涌领取的用量) | 记为跳过，`event_task_disabled` |
| 盛材移涌 | 秘境开启 | 自动秘境。盛材移涌秘境跟随培养计划时按提升指南选择秘境，参数改写与阶段 4 相同（见[第 6 节](#6-秘境养成沿用提升指南)）；指定秘境时刷该秘境，周日入口由游戏决定。树脂按 [7.4](#74-移涌领取的用量) | 秘境关闭：`event_task_disabled`。指定的秘境不是精通或炼武秘境：`event_domain_missing` |
| 祝圣移涌 | 秘境开启 | 自动秘境。祝圣移涌秘境跟随培养计划时，先读取提升指南，刷列表中第一个祝圣秘境；指定秘境时刷该秘境。树脂按 [7.4](#74-移涌领取的用量) | 秘境关闭：`event_task_disabled`。指定的秘境不是祝圣秘境，或跟随培养计划时提升指南中没有祝圣秘境：`event_domain_missing` |
| 紊乱爆发期（进行中） | 危战开启 | 自动幽境危战，用掉全部剩余预算，见 [7.5](#75-紊乱爆发期) | 记为跳过，`event_task_disabled` |

- 执行顺序固定：地脉移涌 → 盛材移涌 → 祝圣移涌 → 紊乱爆发期。限定模式下预算不够时，排在前面的先用。
- 剩余次数 r 为 0 时记为跳过，原因 `event_claims_used_up`。
- 秘境类型的判断：`MapLazyAssets.Get().DomainPositionMap` 中该秘境的类型。祝圣秘境为 `BlessDomain`，`tp.json` 中共有 22 个，例如罪祸的终末、虹灵的净土；精通秘境为 `MasteryDomain`，炼武秘境为 `ForgeryDomain`。荒坠的圣迹是精通秘境（掉天赋书），不是祝圣秘境。
- 祝圣移涌“跟随培养计划”的做法：
  1. 先按 [7.4](#74-移涌领取的用量) 算出领取次数。树脂不够领取时直接跳过，不打开提升指南。
  2. 调用自动秘境新增的只读方法 `ScanTrainingGuideArtifactDomainsAsync`：打开冒险之证 → 秘境 → 提升指南，从上到下读完列表，按顺序收集其中的祝圣秘境，结束后回到主界面。它复用材料秘境的扫描（`ScanGuideDomains`），原来只用于证明页面识别成功、随后丢弃的祝圣秘境名称改为收集起来，不进入材料规划。
  3. 取第一个祝圣秘境，作为本步对象刷取。没有祝圣秘境、提升指南提示暂无培养素材或识别失败时，记为跳过（`event_domain_missing`），说明请用户把角色加入养成计划或指定祝圣移涌秘境。
- 合成浓缩前的活动预留：盛材移涌和祝圣移涌跟随培养计划时都按会领取预留（祝圣移涌要到领取时才知道提升指南里有没有祝圣秘境）。没有领取时，预留的原粹由后续阶段照常使用，只是少合成浓缩。
- 阶段 4、5 进入同一类内容时，如果双倍次数还有剩余，游戏仍会自动给双倍，体力计划不再干预。
- 提升指南当天没有可刷的需求时，盛材移涌这一步没有领奖，双倍次数不转用到其他秘境（首版不处理）。

关闭“优先满足活动”时：

- 不执行阶段 2，合成时不做活动预留；
- 识别结果只用于阶段 5：活动页显示爆发期已结束时跳过危战，进行中时危战作为剩余承接的第一项；
- 识别到移涌活动时，日志提示一次“未开启优先满足活动，移涌活动不单独领取”。

### 7.4 移涌领取的用量

```text
r = 今日剩余双倍次数（读不到按 3）
P = 本次可用于领取的原粹：全部模式为 O，限定模式为 min(R, O)

严格关闭：n = ⌈r / 2⌉
    P ≥ 40 × n：原粹领取 n 次，档位 Prefer40
    P < 40 × n：改按严格开启计算
严格开启：n = min(r, ⌊P / 20⌋)，原粹领取 n 次，档位 Only20
n = 0：跳过；预算不足记 budget_reached，原粹不足记 resin_exhausted
```

子任务的 `resin_usage` 为 `PerType`：`counts.original = n`、`counts.condensed = 0`、`original_tier` 按上面的结果。PerType 的次数是领奖次数，一次 40 档领取算 1 次、消耗 40 点。浓缩不享受双倍，所以不允许。

| 剩余次数 r | 严格关闭（默认） | 严格开启 |
| --- | --- | --- |
| 3 | 40 档 × 2，80 原粹，打 2 次 | 20 档 × 3，60 原粹，打 3 次 |
| 2 | 40 档 × 1，40 原粹，打 1 次 | 20 档 × 2，40 原粹，打 2 次 |
| 1 | 40 档 × 1，40 原粹，一半享受双倍 | 20 档 × 1，20 原粹 |
| 0 | 跳过 | 跳过 |

- 严格关闭以少打几次为先，允许最后一次只有一半享受双倍。严格开启保证每点原粹都享受双倍，但要多打一次。
- 原粹或预算不够 40 × n 时，改用 20 档尽量多用双倍。例如 r=3 但只剩 60 原粹：20 档 × 3。
- 子任务切不到 40 档时会自动改用 20 档（现有行为），实际消耗只会更少，不会超出预算。
- 合成浓缩前的活动预留按同一口径：严格关闭为 40 × ⌈r/2⌉，严格开启为 20 × r（见 [5.3](#53-合成浓缩)）。

纯计算放在 `ResinPlanBudget`：

| 方法 | 作用 |
| --- | --- |
| `BuildOverflowUsage(int? remaining, ResinPlanStock stock, int doubles, bool strict)` | 按上面的规则生成移涌领取的树脂设置；n 为 0 时返回 null |
| `OverflowReserve(int doubles, bool strict)` | 合成前为一个移涌领取预留的原粹点数 |

### 7.5 紊乱爆发期

条件：开启“优先满足活动”，危战开启，活动页显示紊乱爆发期进行中。

1. 阶段 2 的移涌领取全部结束后执行危战。`resin_usage` 与剩余承接相同：全部模式为刷至耗尽，限定模式按剩余预算生成 `PerType`。
2. 危战结束后，按结果决定是否继续阶段 3、4：

| 危战结果 | 阶段 3 首领、阶段 4 秘境养成 |
| --- | --- |
| `Skipped(event_ended)`：活动页误判，危战任务自己发现爆发期已结束 | 照常执行 |
| `Failed`，或子任务抛出业务异常 | 照常执行 |
| 结束原因为 `TargetReached`：勋望达到目标（[7.9](#79-危战勋望进度识别预留) 实现后才会出现） | 照常执行 |
| 其他结果 | 记为跳过，原因 `stygian_burst` |

3. 阶段 5 不再执行危战。地脉花、备选秘境在预算仍有剩余时照常承接，例如运行期间自然恢复的原粹。
4. 合成浓缩时不为首领预留原粹（首领会被暂停）。危战可以使用浓缩。

### 7.6 运行顺序

`ResinPlanTask.RunAsync` 改动后的顺序：

```text
0  读取树脂；开启优先满足活动或危战开启时识别活动（7.2）
1  开启优先合成：合成浓缩，预留 = 活动预留 + 首领预留（爆发期优先时首领预留为 0）
2  开启优先满足活动：
     2.1 地脉移涌 → 盛材移涌 → 祝圣移涌：识别到才处理；前提满足且 r > 0 时按 7.4 领取，否则记为跳过
     2.2 爆发期进行中：危战用掉剩余预算，按 7.5 决定是否暂停阶段 3、4
3  首领（未暂停时）
4  秘境养成（未暂停时）
5  剩余承接：危战（已结束跳过；阶段 2 已执行则不再执行）→ 地脉花 → 备选秘境
6  汇总
```

- 每个阶段开始前沿用现有的 `PlanUsageAsync`：上一个子任务执行过就重新读取顶栏树脂，再按剩余预算生成树脂设置。
- 阶段 2 的子任务参数复用阶段 4、5 的改写方法，只替换 `resin_usage`。秘境参数改写提取成两个私有方法：`BuildTrainingDomainParam` 生成提升指南参数（阶段 2 盛材移涌跟随培养计划、阶段 4 共用）；`BuildManualDomainParam` 生成指定秘境参数（阶段 2 指定的移涌活动秘境与祝圣移涌、阶段 5 备选秘境共用）。
- 自动秘境的领奖流程和自动地脉花不修改。`AutoDomainParam` 只新增两个移涌活动秘境字段（见第 3 节），自动秘境只新增只读方法 `ScanTrainingGuideArtifactDomainsAsync`，JS 宿主合同只增不改。

### 7.7 执行记录与原因码

阶段 2 的每一项都记为一个步骤，阶段为新增的 `ResinPlanStage.Event`（追加在枚举末尾；`SoloTaskJson` 按枚举名保存，不影响旧记录）。前提不满足时也记为跳过步骤，执行记录里就能看到“为什么没有领取活动”。

| 步骤名称 | 对象 |
| --- | --- |
| 地脉移涌·地脉花 | 国家·类型 |
| 盛材移涌·秘境养成 | 根据提升指南选择秘境（跟随培养计划） |
| 盛材移涌·指定秘境 | 指定的盛材移涌秘境 |
| 祝圣移涌·祝圣秘境 | 指定的祝圣移涌秘境；跟随培养计划时为提升指南选出的秘境，没有选出时为“跟随培养计划” |
| 紊乱爆发期·幽境危战 | 首领 N |

新增原因码（`ResinPlanReasons`）：

| 原因码 | 含义 | 执行记录中的说明示例 |
| --- | --- | --- |
| `event_claims_used_up` | 今日双倍次数已用完 | 祝圣移涌今日双倍次数已用完，不再单独领取 |
| `event_task_disabled` | 活动对应的子任务未开启 | 地脉移涌需要开启自动地脉花 |
| `event_domain_missing` | 移涌活动没有可用的秘境：指定的秘境类型不符，或祝圣移涌跟随培养计划时提升指南中没有祝圣秘境 | 祝圣移涌跟随培养计划，但提升指南中没有圣遗物秘境：请先在游戏内把要培养圣遗物的角色加入养成计划，或在自动秘境设置中指定祝圣移涌秘境 |
| `stygian_burst` | 紊乱爆发期优先使用树脂，本阶段不执行 | 紊乱爆发期优先，跳过秘境养成 |

- 这些原因不算“树脂已用完”。`ResinPlanResults.IsExhausted` 只认 `resin_exhausted` 和 `budget_reached`，整次结果的判定不变。
- `events` 字段只保存识别结果，处理结果看活动步骤。执行记录中“活动识别”一行（已实现）不变。

### 7.8 示例

以 2026-10-29 的一次真实运行为例：全部模式，严格关闭，原粹 182，浓缩 0；活动页显示“祝圣移涌 3/3”，紊乱爆发期已结束；提升指南只有一个候选秘境「荒坠的圣迹」。

| 祝圣移涌秘境 | 执行记录 |
| --- | --- |
| 跟随培养计划（默认），提升指南中有祝圣秘境 | 1. 祝圣移涌·祝圣秘境：读取提升指南，刷列表中第一个祝圣秘境，40 档 × 2，80 原粹，3 份双倍。<br>2. 秘境养成：荒坠的圣迹，按需求使用剩余的 102 原粹。<br>3. 幽境危战：跳过（`event_ended`）。<br>4. 剩余承接：原粹不足 20 时不再承接。 |
| 跟随培养计划，提升指南中没有祝圣秘境 | 1. 祝圣移涌·祝圣秘境：跳过（`event_domain_missing`），说明请把角色加入养成计划或指定祝圣移涌秘境。<br>2. 秘境养成：荒坠的圣迹，按需求使用 182 原粹。<br>3. 幽境危战：跳过（`event_ended`）。 |
| 指定罪祸的终末 | 1. 祝圣移涌·祝圣秘境：罪祸的终末，40 档 × 2，80 原粹，3 份双倍；不读取提升指南。<br>2. 之后与第一行相同。 |

同样条件下如果活动是“盛材移涌 3/3”：

1. 盛材移涌·秘境养成：打开提升指南，在第一个候选秘境（荒坠的圣迹）用原粹 40 档领取 2 次，80 原粹。
2. 秘境养成：重新打开提升指南，按剩余需求继续刷，浓缩和原粹按自动秘境原有的选择方式使用。

### 7.9 危战勋望进度识别（预留）

最终方案：紊乱爆发期内，危战累计到 1200 危战勋望即视为活动需求已满足，剩余预算回到阶段 3—5 继续分配。

本期只预留执行类和调用点，识别留空，待用户提供截图后单独实现：

- 新增 `GameTask/AutoStygianOnslaught/StygianDirePrestigeReader.cs`：
  - 方法 `Task<StygianDirePrestigeProgress?> ReadAsync(GameRuntime runtime, CancellationToken ct)`，本期固定返回 `null`；
  - `StygianDirePrestigeProgress` 包含 `Current` 和 `Target`；
  - 类注释写明：识别位置为危战界面的勋望进度，预期在领奖前调用，返回 `null` 表示未识别，调用方必须当作“未知”而不是 0，需要的截图由用户提供。
- `AutoStygianOnslaughtParam` 新增 `DirePrestigeTarget`（`dire_prestige_target`，0 表示不限制）。紊乱爆发期优先时，体力计划传入 1200（常量 `StygianDirePrestigeReader.CommendationPrestige`）。
- 危战任务每次领奖前调用 `ReadAsync`：
  - 读到 `Current ≥ DirePrestigeTarget` 时停止，结束原因为 `TargetReached`；
  - 返回 `null` 时继续，与本期“用完全部预算”的行为一致。
- 识别实现完成后只替换 `ReadAsync` 的内部逻辑，参数、调用点和体力计划都不需要再改。

### 7.10 设计取舍与待确认

以下取舍已由用户确认（2026-10-29），11.2 按此实现：

| 编号 | 取舍 | 理由 | 代价 |
| --- | --- | --- | --- |
| E1 | 盛材移涌在阶段 2 单独跑一次提升指南秘境，不在阶段 4 内限制“前 N 次只用原粹” | 三种移涌领取的做法一致；不改自动秘境的两条树脂选择路径，也不给领奖流程加“前 N 次只用原粹”的参数 | 阶段 4 会再打开一次提升指南、再传送一次，约多 1 分钟 |
| E2 | 祝圣移涌秘境和阶段 5 的备选秘境是同一个秘境时，分两次进入，不合并 | 阶段 2 与阶段 5 各自独立，阶段 5 可能根本轮不到 | 多传送一次 |
| E3 | 严格关闭、剩余 1 次时用 40 档 | 与 r=3 的规则一致：严格关闭以少打几次为先 | 多出的 20 原粹按普通奖励结算 |
| E4 | 提升指南当天没有需求时，盛材移涌的双倍次数不转用到备选秘境 | 首版聚焦主流程 | 这种情况下双倍次数作废 |
| E5 | 只读活动列表顶部一屏 | 新活动排在最上面；已实现的识别如此 | 排在下面的移涌活动识别不到 |
| E6 | 开启优先满足活动或危战开启时才识别活动 | 两者都关闭时识别结果没有用处 | 无 |

以下取舍按用户 2026-10-30 的要求（在自动秘境设置中选择活动秘境，默认跟随培养计划）新增，待验收：

| 编号 | 取舍 | 理由 | 代价 |
| --- | --- | --- | --- |
| E7 | 移涌活动秘境与备选秘境分开设置，祝圣移涌不再使用备选秘境 | 剩余树脂刷什么和移涌活动刷什么互不影响；备选秘境的说明不再一词两用 | 多两个设置项；之前把备选秘境设成祝圣秘境的用户，祝圣移涌改为跟随培养计划 |

| E9 | 盛材移涌指定秘境时不另设周日奖励序号 | 首版聚焦主流程 | 周日或限时全开时使用游戏默认入口 |

## 8. 返回结果

任务返回 `SoloTaskResult<ResinPlanData>`。在 Pulonia 中，它作为节点结果的 `Data`，随运行历史保存。

| 字段 | 内容 |
| --- | --- |
| `rewards` | 全部步骤识别到的奖励，按名称合并为一个 `RewardSummary` |
| `resin` | 各阶段合计的 `ResinUsageReport`（领奖次数、各类领奖次数与消耗），执行记录与单个子任务一样显示为“树脂使用” |
| `budget` | 体力用量、开始时的原粹与浓缩、领奖消耗的合计点数、合成的浓缩份数 |
| `events` | 活动识别结果（`ResinPlanEventReport`，见 [7.2](#72-识别方式)）。处理结果（执行、跳过及原因）记录在 `steps` 的活动步骤中，见 [7.7](#77-执行记录与原因码)（11.2 加入） |
| `steps` | 每个阶段一项：阶段、名称、子任务 ID、对象（秘境、首领、地脉类型）、是否执行、结果类型、原因码、消息、`ResinUsageReport`、本步奖励、奖励是否已识别、合成份数 |

执行记录中，`budget` 显示为一行“体力预算”，`steps` 每个阶段显示一行“第 N 步 · 名称：结果（对象）：说明；奖励：…”，不展示原始 JSON。

各子任务的奖励识别：

| 子任务 | 奖励识别 |
| --- | --- |
| 自动秘境、自动首领 | 已有，体力计划强制开启 |
| 自动幽境危战、自动地脉花 | 新增：在领奖结果页调用 `RewardResultRecognizer.RecognizeMultiPage`，写入 `ResinClaimData.Rewards` |
| 合成浓缩 | 不产生奖励，只记录合成份数 |

奖励结果页的识别目前只支持 1920×1080。其他分辨率下，这些步骤标记为“奖励未识别”，领奖次数和树脂消耗照常返回。

结果类型的判定：

| 结果 | 条件 |
| --- | --- |
| `Failed` | 准备失败；或有步骤失败，且本次没有任何领奖 |
| `Partial` | 有步骤失败，但已有领奖 |
| `Skipped(resin_exhausted)` | 没有领奖，且有阶段因预算或树脂不足而跳过 |
| `Skipped(nothing_claimed)` | 没有领奖，但树脂仍有剩余，例如养成计划没有需求且其余任务都未开启 |
| `Unverified` | 没有失败步骤，但存在 `Unverified` 步骤 |
| `Success` | 其余情况 |

## 9. 一条龙接入

- 任务声明为 `[SoloTaskInfo("resin_plan", "体力计划", Group = "树脂与战斗", Order = 200, Scopes = SoloTaskScopes.Plan, OneDragonOrder = 2)]`。
  - 只出现在任务计划与一条龙中。独立任务页的参数来自全局配置，体力计划没有对应配置，因此不在独立任务页提供。
- 新建一条龙时，默认清单改为：领取邮件 → 体力计划 → 领取每日奖励 → 尘歌壶。
  - 五个子任务的 `OneDragonOrder` 改为 0，仍可单独添加。
  - 已有的一条龙配置不会被自动修改。
- 同一计划同时启用体力计划和任一子任务时，一条龙清单的配置摘要中提示共用树脂（体力计划一行显示“⚠ 计划中另有消耗树脂的任务，会与体力计划共用树脂”，子任务一行显示“⚠ 与体力计划共用树脂”），不阻止运行。
- 一条龙清单中体力计划的配置摘要显示体力用量、是否优先合成和参与的任务。

## 10. 失败、取消与续跑

- 子任务返回 `Failed` 或抛出业务异常（例如提升指南识别失败）时，该步骤记为失败。体力计划返回主界面，重新读取树脂，然后继续后面的阶段。
- 取消和运行环境停止直接向外抛出，与其他独立任务一致。此时本次结果不返回，已领取的奖励只记录在日志中。
- 续跑会重新执行整个体力计划。因为无状态，会按当前的树脂、活动和提升指南重新计算，已满足的需求不会重复刷。
- 防止重复领奖由各子任务自己的领奖流程负责，体力计划不增加账本。

- “优先满足活动”卡片放在“参与的任务”之后、“执行顺序”之前，样式与“优先合成浓缩”相同：头部开关绑定 `event_priority`，展开内容中的“严格使用 60 树脂”绑定 `event_strict_resin`，并在 `event_priority` 关闭时禁用。

- 秘境需求来自游戏内养成计划。界面提示用户先在游戏内把要培养的角色加入养成计划；剩余承接使用秘境设置中的备选秘境，移涌活动使用秘境设置中的盛材移涌秘境与祝圣移涌秘境（见第 3 节）。
- 子任务卡片的摘要列出已填写的关键设置（队伍、备选秘境、手动指定的移涌活动秘境、首领、国家等）；跟随培养计划时不显示。首领卡片同时显示树脂使用，例如“领奖 1 次 · 原粹”。
- 移涌活动秘境的选择框与备选秘境相同（按国家分组），只列出对应类型的秘境，首项为“跟随培养计划”。选项由字段视图模型按 Schema 标记 `x-domain-picker`（`fallback`、`material_overflow`、`blessing_overflow`）提供。
- 子任务的“设置”打开体力计划的子任务设置窗口：按该任务参数 Schema 生成与一条龙通用卡片相同的设置项，第 3 节表中由体力计划决定的字段不显示，窗口顶部说明这些字段由体力计划决定。确定时按 Schema 校验，取消丢弃草稿。
  - 不复用各任务的专属设置页，因为专属页会编辑树脂使用和秘境选择，这些在体力计划中不生效或不支持。
  - 提升指南相关字段（刷取偏好、合成收益预留、奖励识别、低冒险等阶适配、备选秘境等）补充了中文名、说明与选项，普通自动秘境节点的通用卡片同样受益。
- 执行记录按阶段显示：对象、领奖次数、树脂用量、奖励，以及跳过原因。
- 修改设置不会操作游戏。新页面沿用项目的 MVVM、Behaviors 和 `ThemedMessageBox` 规范。

## 14. 分步交付与验收

每个子步骤分别提交、分别等待用户验收。危战勋望进度识别不在 11.1—11.3 之内，用户提供截图后单独排期。

| 子步骤 | 交付 | 验收重点 |
| --- | --- | --- |
| 11.1 骨架 | 参数与设置视图、读取树脂、预算、合成浓缩（含 `craft_count`）、首领、秘境养成（提升指南）、剩余承接、结果汇总、一条龙默认清单 | 预算上限生效；首领默认不执行；提升指南可以刷多个秘境；剩余树脂按顺序承接；结果包含全部步骤的奖励和消耗 |
| 11.2 活动优先 | `ResinPlanEventDetector`（识别已完成）、地脉移涌、盛材移涌与祝圣移涌领取（[7.3](#73-各活动的执行方式)、[7.4](#74-移涌领取的用量)）、严格 60 选项、紊乱爆发期（[7.5](#75-紊乱爆发期)）、活动步骤与原因码（[7.7](#77-执行记录与原因码)），以及 `StygianDirePrestigeReader` 的预留类与调用点 | r=3 时，关闭严格用 40 档刷两次共 80 原粹，开启用 20 档刷三次共 60 原粹；不用浓缩领取双倍；合成前先为活动预留原粹；爆发期暂停养成；识别不到活动时正常养成；前提不满足时执行记录写明原因 |
| 11.3 奖励识别补齐 | 危战与地脉花的奖励识别 | 四个子任务的奖励都出现在结果中；分辨率不支持时有明确标记 |

验收场景（用户使用真实数据，按当前子步骤选取）：

1. 全部模式下树脂用完；限定为 120 点时，实际消耗不超过 120 点。
2. 开启优先合成时，合成份数为后续首领和移涌活动留出了原粹；关闭时不合成。
3. 提升指南的第一个秘境满足后，继续刷下一个候选秘境；全部满足后，剩余预算进入地脉花或备选秘境。
4. 首领默认不执行；开启后按首领自己的树脂使用设置讨伐（指定次数或刷至耗尽），不使用须臾或脆弱。
5. 地脉移涌期间，严格关闭时领取 2 次 40 档，开启时领取 3 次 20 档；没有活动时不受影响。
6. 盛材移涌期间，阶段 2 先在提升指南秘境按第 5 条的规则只用原粹领取，之后秘境养成恢复正常选择。
7. 祝圣移涌期间，祝圣移涌秘境跟随培养计划时，读取提升指南并刷其中第一个祝圣秘境；提升指南中没有祝圣秘境时，执行记录显示 `event_domain_missing` 及说明。指定祝圣秘境时直接刷该秘境。两种情况都按第 5 条的规则领取。
7a. 盛材移涌秘境指定为某个精通或炼武秘境时，阶段 2 刷该秘境；跟随培养计划时与第 6 条相同。普通自动秘境节点的设置中不出现两个移涌活动秘境字段。
8. 活动页显示紊乱爆发期进行中时，危战先用树脂，并暂停首领与秘境养成；爆发期结束后自动恢复养成。
9. 某个子任务失败后，后续阶段继续执行，结果为 `Partial`，并附带失败原因。
10. 一条龙切换账号后，体力计划按新账号的提升指南重新计算。
11. 同一计划同时启用了体力计划和单独的自动秘境时，有共用树脂的提示。

实现遵循项目 MVVM、中文注释及 UTF-8 无 BOM 规范，编译验证按 AGENTS.md 执行。新增参数类属性只增不改，保持 JS 宿主合同兼容。
