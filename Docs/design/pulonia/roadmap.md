## 验收规则

1. **逐步验收。** 每一步（含子步骤）的流程固定为：确定范围 → 实现和自查 → 提交验收材料 → 等用户明确验收通过 → 才开始下一步。需要修改时留在当前步骤，不跨步推进；调整顺序或扩大范围先更新本文并经用户确认。
2. **用户用真实数据验收。** 由用户自行选择真实配置、真实资源和实际使用场景，并明确给出结论。不提供或维护验收用的 `examples` JSON、预制计划或特制成功数据。
3. **自查不等于验收。** 编译、单元测试、静态检查和代理构造数据的通过只属于开发自查，不证明真实数据兼容、界面可用或业务正确，不能把“待验收”改为“已通过”。代理不启动程序或游戏；编译按 AGENTS.md 的命令执行，程序占用时记录未验证原因。
4. **提交材料四项。** 本步完成了什么、如何验收、编译与检查结果、已知限制。
5. **开发期不兼容旧格式。** Pulonia 尚在开发，格式变化（删除字段、调整结构）不写读取升级或剔除代码，除非另有说明；旧文件读取失败时由用户删除或手工修正。
6. **不能用“后续优化”掩盖缺失。** 未做完的部分标为未交付；远程 HTTP、多机联机编排和任意并行工作流不在本路线图内。

## 2026-10-24 改造摘要

依据 `Docs/tmp/pulonia-architecture-review.md` 及用户对 D1（选 B：只派发不并行）、R1（删除通用额度框架）、D4（一条龙设置即时生效）等的决定实施。各项现状已写入对应基线文档，这里只列要点。

**执行与状态**（[执行](execution.md)、[存储](results-and-storage.md)）

- 所有执行实例共用一个串行队列和唯一 `active_run`，跨实例只派发；state.json 格式版本改为 4，旧版本文件不升级，需删除后重建。`pulonia.node.report` 删除，子实例结束回报不重试，`CancelledByTarget` 停止整次运行。
- `PuloniaTaskRunStateStore` 成为 state.json 唯一写入入口；最终状态集中在 `ResolveFinalStatus`；运行锁并入 `_runsGate`，`QueueReady` 删除，队列唤醒改为信号量；当前节点地址不再落盘。
- 坏的历史文件与计划文件跳过并提示，文件不删除；常驻历史只保留摘要，快照按需读取。
- 每次节点尝试重新取游戏租约后核验 UID（`PuloniaLocalNodeRunner`）；`AcquireAsync` 检测嵌套获取，获取后等待订阅脚本自动更新（最长 10 分钟）。
- `CheckTriggersAsync`、`FireHotkeyAsync`、`GetTriggerStatuses` 进入 `IPuloniaTaskService`，DI 只注册接口一份。

**CD 与时间**（[存储](results-and-storage.md)、[多账号](accounts.md)）

- 删除通用额度框架（可用性规则、操作意图、完成事件报告、未决操作），文件级采集 CD 是唯一 CD。账本每个（作用域，文件）只保留最新一条。
- 作用域键 `cn/world/{身份}`：未切换账号为 `default`，切换到指定账号为核验 UID；部分旧账本键因此失效，相关文件可能多跑一次。
- 服务器时区入队时由 `PuloniaServerTime` 统一填写（未初始化按 UTC+8），采集 CD 日/周边界与独立任务每周安排共用 `GetGameDate`。请求字段 `Server`、`WorldOwnerAccountId` 删除。

**参数与模型**（[模型与配置](model.md)）

- `PuloniaParameterResolver` 成为唯一的有效参数解析实现，Builder 与界面预览共用；`PuloniaTaskPreparedTask` 保存冻结副本，快照 JSON 形状不变。
- Schema 子集新增 `minimum`；能力说明合法性改由 `ValidateDefinitions` 与单元测试保证，Builder 不再每次复验（此前 AutoBoss 的 `minimum` 让所有计划准备失败）。校验器删除对象环检测与若干重复 null 检查，保留 Windows 保留名检查。
- `IsExpanded` 移出计划，折叠状态存于 `plan-view-state.json`。
- 按验收规则 5 删除了本轮写的全部旧格式兼容代码（state.json 2、3 版升级、已停用字段剔除、账本压缩、展开状态迁移、旧路线结果展示）；旧的 state.json、历史、计划和账号文件需要用户删除或手工修正。

**调度**（[触发与热键](scheduling.md)）

- 触发游标只持久化四个字段，运行反馈在内存维护；热键去抖改为内存单调计时；孤儿游标每轮剔除，停用的定时触发器保留游标。
- 未启用补触发时的迟到判定：首轮 5 秒容差，持续轮询（两轮间隔不超过 30 秒）期间到点不算遗漏。时区改为三个固定偏移，删除夏令时规则、二次忙碌复核、“已提交”复核和 `TriggerBusyException`。
- 热键键位规则移到 `PuloniaTaskHotkeyValidator`；应用热键冲突的反射预检保留。计划重载改为本进程保存后下一轮重读，另每 30 秒比较文件修改标记。

**仓库与资源**（[脚本仓库与任务资源](repository-resources.md)）

- 资源指纹只有 `PuloniaTaskResourceFingerprint` 一份实现，输出与旧值逐字节一致；JS 指纹范围未扩大（D11 待定）。
- 来源锁按目录，registry 锁只用于写，selection 锁删除；配置写入改用 `File.Replace`；JS 工作目录锁 10 秒超时。文件式来源的代次删除，改用 `repo_updated.json` 写入时间计入修订（`file-v3`）。
- 资源检查按仓库批量，声明版本先查缓存，损坏的 manifest 或路线 JSON 不再中断整轮检查；更新保存失败时保留草稿与 `LastSaveError`，可撤销，不再自动回滚。

**账号**（[多账号](accounts.md)）

- 凭据由存储层管理：先保存账号目录再提交凭据；凭据名按账号固定；移除账号或改用无密码方式时删除旧凭据；续跑使用当前凭据。账号图片每次新建，删除图片版本冻结与 SHA 复核；删除 B 服 `config.ini` 检测。

**界面**（[界面](user-interface.md)）

- `PuloniaPlanEditingSession` 单例编辑会话承担两页共用的文档、加载、自动保存、增删导入、资源检查与运行提交；页面 VM 只保留选择、菜单和弹窗输入。
- 一条龙右侧设置即时生效，去掉“应用设置”“重置草稿”；两页共用 `PuloniaTaskTriggerView` 与 `PuloniaPlanTriggersViewModel`；“运行账号”常驻显示。
- 高级设置由 `PuloniaTaskNodeAdvancedSettingsViewModel` 按需计算，公共设置等窗口由视图层 `PuloniaTaskSettingsDialogs` 创建；一条龙执行记录窗口使用独立的历史 VM 实例。参数中文名、结果解释、状态归类各只有一份（`PuloniaTaskFieldNames`、`PuloniaTaskResultInterpreter`、`PuloniaTaskRunClassifier`）；新增任务由 `PuloniaTaskCreationService` 构建；仓库添加与移除只走“仓库管理”。

开发自查：全部改动合并后，全解决方案 Debug 编译通过（运行中的程序锁定默认输出目录，使用独立输出目录编译）；Pulonia 单元测试 382 项全部通过，连跑两次结果一致。此前 12 项仓库资源相关的既有失败已在本轮查明并修复（4 项测试过时、4 项为损坏 manifest/路线 JSON 中断整轮资源检查的缺陷、3 项断言写反、1 项随文件式来源代次删除改写）。全量测试中另有 74 项失败，集中在依赖测试图片资源的识别类测试，与 Pulonia 无关。未启动程序或游戏，界面与真实运行效果待用户验收。

## 验收场景索引

以下是用户按当前步骤自选真实数据验收时可参考的场景，不要求每次重复全部验证；部分场景依赖尚未实现的能力（步骤 8、12），届时再验收。

1. **V01** 同一路线在两个计划出现，第一条成功后第二条显示剩余 CD；换账号后不串记录。任务树标记、运行预览、执行记录的“路线 CD”页签与实际跳过一致；官方仓库的魔物路线当天第二次运行时跳过；清除记录后照常执行。
2. **V02** 20:00 到点提交；若按策略排队至 20:10，开始前复核截止时间，超时则过期。
3. **V03** 运行时手动取消，等待执行器退出并释放输入后完成停止；续跑前重新准备环境。
4. **V04** 奖励已经领取、记录尚未提交时崩溃，重启后进入核验而不是直接重领（依赖步骤 12 的领奖证据）。
5. **V05** 日切前开始、日切后完成，以及失败前已采到部分素材，账本归属正确。
6. **V06** 修改计划或设置方案不改变正在执行的快照；资源版本变化不会静默影响续跑。
7. **V07** 任意入口调用同一动作都显示相同的有效参数和来源。
8. **V08** 大资源目录按需加载和批量保存，用实际目录记录首次打开、搜索和整目录添加耗时。
9. **V09** 旧任务不响应取消时，不得启动下一账号或节点争用输入。
10. **V10** 未知界面、被顶号、验证码、UID 错误都能有限结束并留下明确的待处理原因。
11. **V11** 状态替换前后崩溃、归档前后崩溃、磁盘写入失败、备份回退时，进度和 CD 不出现相互矛盾的记录。
12. **V12** 目录引用更新只影响新快照；关闭再开启分组不丢失子项禁用；拖拽与重命名不破坏历史对应关系。
13. **V13** 休眠恢复、时钟回拨、重复热键不会无界补任务或重复占用输入。
14. **V14** 带数组和布尔值的 JS 配置跨计划复制后无需重启即可编辑和执行；误删、误拖可以撤销，粘贴继承差异有提示。
15. **V15** 同一路线由任务树和 JS 子调用启动，结果原因一致；未完整执行不更新 CD。
16. **V16** “库存补到 N”“今日新增 N”“角色培养到目标”分别计算（步骤 11）。
17. **V17** 背包满、计划总时限到达、公共月卡中断及切号失败都有明确终态；旧任务未停止时，次日请求不能抢占输入。
