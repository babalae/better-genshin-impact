# Pulonia：菜单、任务树与添加体验

[返回总览](../automation-system.md) · [用户故事](requirements.md) · [开发与验收计划](development-plan.md)

沿用 d-v3 有价值的树表交互，用同一计划和参数编辑器服务高级编辑与简洁一条龙视图。具体 UI 是开发步骤 2、5、9 的独立验收对象。

## 新菜单与添加体验

页面沿用 d-v3 的列表与树表组织，在“自动化”下提供以下入口：

| 页面 | 用户看到的内容 |
| --- | --- |
| 托管 | 账号、培养目标、今日计划卡片、下次执行、缺失条件、一键开始 |
| 任务计划 | 左侧计划列表；右侧“任务、执行记录、触发方式”页签；任务树为主要工作区域，选中项参数按需显示 |
| 任务库 | 内置功能、材料采集、刷怪路线、JS、宏、Shell、C#；按用途和目标筛选 |
| 运行记录 | 各计划运行的汇总，复用计划内执行记录组件，不再做一套状态模型 |

保留 d-v3 中“最近运行结果、可续跑位置”的摘要，当前运行显示固定状态条。成功率、平均耗时放进记录详情，不占任务树默认空间；运行监控和历史使用同一个详情组件。全局触发管理只汇总计划内触发器，定时与热键分开展示。

任务树表列沿用“名称、类型、启用、最近结果、操作”，按需增加“下次可运行/剩余 CD”。右键支持添加、复制、删除、从此开始；拖拽以明确插入线/分组高亮反馈位置，禁止环路。选中分组时向组内添加，选中叶子时默认插在其后，不强迫用户先返回父目录。

对应 US-12，支持跨计划复制/粘贴子树和编辑撤销。复制默认保留参数值与显式预设引用，为新节点生成 ID，重映射子树内部引用；不会同时复制原触发器或历史进度。父组继承值可能在目标位置变化，粘贴前显示差异并提供“保留当前有效设置”选项，避免无提示改用另一支队伍。删除、拖动、批量添加作为一次可撤销的编辑；用当前编辑会话内有上限的变更前后快照实现即可，不引入通用事件溯源。撤销只作用于配置，不撤销已经发生的游戏操作。

分组禁用时整棵子树不执行，但不覆盖子任务原本的勾选；重新启用后保留原来的选择。“启用全部子任务”作为独立命令。这吸收 d-v3 父子联动的便利，同时避免一次关闭/开启分组抹掉用户对部分节点的禁用配置。

参数编辑采用同一组件，宽窗口显示侧栏，窄窗口用抽屉/对话框；避免常驻三栏挤压树表。账号管理由托管页和计划绑定页进入。路线录制、路线编辑、JS 开发作为任务库的工具入口，原页面的有效功能迁入。

一条龙卡片使用树节点的同一参数编辑器，直接显示“队伍、策略、次数、来源预设”等有效配置，不再要求用户去另一个独立任务页面寻找被暗中复用的设置。高级树无法简化的节点显示为可展开步骤，不能在切换简洁视图时丢失节点。

### 添加任务与整个目录

沿用 d-v3 的“左侧搜索/目录，右侧说明预览”。JS 展示名称、简介、作者和版本，默认预览 README，源码放高级页签；路线目录展示说明和任务数量，文件展示路线摘要，JSON 放高级页签。来源切换、版本和下载在这个窗口内完成，不要求跳转脚本订阅页面。

目录添加保留两种模式，默认引用目录：

| 模式 | 保存与编辑方式 |
| --- | --- |
| 引用目录 | 保存 `Source` 中的目录定位及所选资源版本；树上显示一个可展开的引用组，子项按需预览。运行前生成固定清单；用户要逐项改动时“展开为可编辑任务” |
| 展开为任务 | 将当前选中文件批量写成普通任务节点；默认保留目录结构，可选择扁平添加 |

引用目录不是“永远运行最新内容”：默认固定版本，更新后显示数量/清单差异，由用户选择更新。开始运行时再冻结实际文件清单与指纹，续跑沿用它；内容版本缓存缺失时明确提示不可精确恢复。引用展开的任务 ID 按来源项稳定映射，并保存在运行快照中；不要每次查看目录都生成随机 ID。目录引用与展开模式均能添加整目录，不需要逐个点选。

- 后台维护轻量目录索引，只读清单、文件属性及可用元数据；不在打开选择窗口时解析全部路线内容或初始化全部脚本引擎。
- 搜索走缓存索引，输入防抖并取消过时查询；只有可见项创建 UI 容器，文件详情按需读取。
- 引用目录仅在用户展开预览或运行准备时解析；后台索引支持按目录统计和检索。展开模式在确认后批量生成节点，不能在每次勾选时先构建全目录控件。
- 展开为普通任务后不随仓库静默变化；引用目录的版本更新与计划更新均留痕。不要在转换任务时全量复制资源仓库，选定资源按版本缓存、按需读取。
- 批量添加按一次模型变更、一次保存处理，不逐节点触发序列化与磁盘写入。

优先验证 d-v3 已用的 `ui:TreeListView` 在当前控件版本中的支持情况和性能；保留树表交互，不保证原样复制控件就能处理大目录。必要时用原生虚拟化控件实现同样的树表表现，不新增第三方树组件。WPF 的虚拟化、容器回收以及外层布局需要一起检查。[微软文档](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/controls/how-to-improve-the-performance-of-a-treeview)

新页面继续使用 `ObservableObject`/项目 `ViewModel`、`[ObservableProperty]`、`[RelayCommand]`、Behaviors 和现有拖拽框架。简单提示使用 `ThemedMessageBox`，领域实体不承担 UI 命令。
