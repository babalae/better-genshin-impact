# Pulonia：菜单、任务树与新增任务体验

[返回总览](../automation-system.md) · [用户故事](requirements.md) · [开发与验收计划](development-plan.md)

沿用 d-v3 有价值的树表交互，用同一计划和参数编辑器服务高级编辑与简洁一条龙视图。具体 UI 是开发步骤 2、5、9 的独立验收对象。

## 新菜单与添加体验

页面沿用 d-v3 的列表与树表组织，在“自动化”下提供以下入口：

| 页面 | 用户看到的内容 |
| --- | --- |
| 托管 | 账号、培养目标、今日计划卡片、下次执行、缺失条件、一键开始 |
| 任务计划 | 左侧计划列表；右侧“任务、执行记录、触发方式”页签；任务树为主要工作区域，选中项参数按需显示 |
| 运行记录 | 各计划运行的汇总，复用计划内执行记录组件，不再做一套状态模型 |

保留 d-v3 中“最近运行结果、可续跑位置”的摘要，当前运行显示固定状态条。成功率、平均耗时放进记录详情，不占任务树默认空间；运行监控和历史使用同一个详情组件。全局触发管理只汇总计划内触发器，定时与热键分开展示。

任务树表默认只保留“名称、类型、启用”等状态列，按需增加“最近结果、下次可运行/剩余 CD”，不为每行常驻重复的操作按钮。`PuloniaTaskPlan.RootTask` 是计划级配置和顶层任务容器，属于持久化实现细节，不在树中重复展示计划名称；树直接展示 `RootTask.Children`。在树空白区域右键时，新增、粘贴和计划引用固定追加到当前计划根级；在可见节点上右键时，选中分组向组内添加，选中叶子默认插在其后。

新增分组、具体任务、计划引用以及复制、粘贴、删除、撤销、启用全部子任务统一收口到右键菜单；常用编辑同时支持 `Ctrl+C`、`Ctrl+V`、`Ctrl+Z` 和 `Delete`。节点配置不在页面右侧常驻：双击节点、按 `F2` 或右键“编辑配置”打开统一弹窗，普通分组、目录引用、计划引用和全部叶子任务都可以再次编辑。固定重复不是一种任务类型，不提供“新增重复节点”：在分组配置弹窗中填写 1—10000 的“执行次数”，表示每轮按顺序完整执行该分组的全部子项。这样调整次数不改变树结构，也不会为一个简单配置额外制造包裹层。右键首先选中鼠标所在节点，确保命令目标明确。由于 WPF `ContextMenu` 位于独立可视树，页面级命令通过绑定代理访问，不能依赖模板元素的临时 `Tag` 传递；所有新增、粘贴和引用命令必须显式携带右键节点，并通过该节点所属文档修改数据，不能再次查询可能尚未同步的全局选择。空白区域菜单则显式携带当前文档的内部根节点，同样不依赖树的历史选中项。拖拽以插入线/分组高亮反馈位置并禁止环路。

左侧计划列表是计划级操作入口：右键支持新建、重命名和重新加载，双击或 `F2` 也可重命名。计划可直接拖拽排序；显示顺序作为独立的编辑器目录元数据保存，不进入任一计划的执行内容、不增加计划修订号，也不改变稳定计划 ID。名称仅用于展示，重命名不会破坏其他计划引用或历史定位。计划内容采用自动保存：一次结构或配置操作完成后短暂防抖，同一计划串行写入，保存成功只推进修订和检查点，不重建树、不清空撤销历史。正常的等待、保存中和保存成功保持静默，不能覆盖最近一次用户操作提示，计划列表也不展示短暂的“未保存”黄色标记；只有写入失败才更新状态并保留错误提示和内存草稿，下一次真实编辑后重试。界面不再保留手动保存按钮。

对应 US-12，支持跨计划复制/粘贴子树和编辑撤销。复制默认保留参数值与显式预设引用，为新节点生成 ID，重映射子树内部引用；不会同时复制原触发器或历史进度。父组继承值可能在目标位置变化，粘贴前显示差异并提供“保留当前有效设置”选项，避免无提示改用另一支队伍。删除、拖动、批量添加作为一次可撤销的编辑；用当前编辑会话内有上限的变更前后快照实现即可，不引入通用事件溯源。撤销只作用于配置，不撤销已经发生的游戏操作。

计划引用候选包含当前编辑会话中的全部其他计划，不以是否已经保存过滤。若目标计划仍在自动保存防抖窗口中，添加引用时先等待或立即完成目标计划的串行保存，以保证引用立即指向可读取版本；该过程不再要求用户额外确认，保存失败则不创建引用。新增引用前检查打开计划之间的直接和间接依赖，拒绝形成循环。计划引用在模型中是带计划来源的分组，不增加独立任务类型；引用分组只保存目标稳定 ID，后续重命名不破坏关系。

分组禁用时整棵子树不执行，但不覆盖子任务原本的勾选；重新启用后保留原来的选择。“启用全部子任务”作为独立命令。这吸收 d-v3 父子联动的便利，同时避免一次关闭/开启分组抹掉用户对部分节点的禁用配置。

参数编辑采用独立配置弹窗，不在任务树页面常驻第三栏；创建时按任务类型展示专用表单，再次编辑时由统一弹窗承接名称、启用、重复、资源版本、共享预设、显式参数、策略和引用来源。账号管理由托管页和计划绑定页进入。路线录制、路线编辑、JS 开发继续保留原有专用页面，不再额外建立聚合菜单。

一条龙卡片使用树节点的同一参数编辑器，直接显示“队伍、策略、次数、来源预设”等有效配置，不再要求用户去另一个独立任务页面寻找被暗中复用的设置。高级树无法简化的节点显示为可展开步骤，不能在切换简洁视图时丢失节点。

### 添加任务与整个目录

沿用 d-v3 的“左侧搜索/目录，右侧说明预览”，但只在用户选择具体任务类型后打开对应的新增弹窗。JS 展示名称、简介、作者和版本，默认预览 README，源码放高级页签；路线目录展示说明和任务数量，文件展示路线摘要，JSON 放高级页签。新增弹窗提供“获取更多资源”入口，复用现有脚本仓库完成来源更新、在线下载和离线导入，关闭仓库后只刷新当前任务类型。

目录添加保留两种模式，默认引用目录：

| 模式 | 保存与编辑方式 |
| --- | --- |
| 引用目录 | 保存 `Source` 中的目录定位及所选资源版本；树上显示一个可展开的引用组，子项按需预览。运行前生成固定清单；用户要逐项改动时“展开为可编辑任务” |
| 展开为任务 | 将当前选中文件批量写成普通任务节点；默认保留目录结构，可选择扁平添加 |

引用目录不是“永远运行最新内容”：默认固定版本，更新后显示数量/清单差异，由用户选择更新。开始运行时再冻结实际文件清单与指纹，续跑沿用它；内容版本缓存缺失时明确提示不可精确恢复。引用展开的任务 ID 按来源项稳定映射，并保存在运行快照中；不要每次查看目录都生成随机 ID。目录引用与展开模式均能添加整目录，不需要逐个点选。

- 后台维护轻量目录索引，只读清单、文件属性及可用元数据；不在打开选择窗口时解析全部路线内容或初始化全部脚本引擎。
- 搜索走缓存索引，输入防抖并取消过时查询；只有可见项创建 UI 容器，文件详情按需读取。
- 引用目录仅在用户展开预览或运行准备时解析；后台索引支持按目录统计和检索。展开模式在确认后批量生成节点，不能在每次勾选时先构建全目录控件。
- 展开为普通任务后不随仓库静默变化；引用目录的版本更新与计划更新均留痕。不要在转换任务时全量复制资源仓库，选定资源按版本缓存、按需读取。
- 批量添加按一次模型变更、一次保存处理，不逐节点触发序列化与磁盘写入。

优先验证 d-v3 已用的 `ui:TreeListView` 在当前控件版本中的支持情况和性能；保留树表交互，不保证原样复制控件就能处理大目录。必要时用原生虚拟化控件实现同样的树表表现，不新增第三方树组件。WPF 的虚拟化、容器回收以及外层布局需要一起检查。[微软文档](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/controls/how-to-improve-the-performance-of-a-treeview)

新页面继续使用 `ObservableObject`/项目 `ViewModel`、`[ObservableProperty]`、`[RelayCommand]`、Behaviors 和现有拖拽框架。简单提示使用 `ThemedMessageBox`，领域实体不承担 UI 命令。

## 步骤 2 实现入口

主菜单“任务计划”现已接入 `PuloniaTaskPlanPage`。页面左侧保存多个计划编辑会话，计划支持右键重命名和拖拽排序，顺序写入 `User/Pulonia/plan-order.json`。右侧“任务”页签使用 `TreeView`、GongSolutions 拖拽和可双向绑定选中项的 Behavior 编辑同一配置树。树结构命令集中在节点右键菜单，不保留顶部新增工具条、手动保存按钮或行内复制/删除按钮；结构变更以有上限的变更前快照撤销，不引入事件溯源。自动保存期间仍可继续编辑，新变更不会被较早的保存副本覆盖；撤销恢复内容时沿用最新磁盘修订，避免后续自动保存产生伪冲突。

节点配置弹窗使用严格 JSON 保真处理数组、布尔值、null 和数值；分组执行次数属于明确的结构配置，使用独立数字输入框，不混入公共参数 JSON。共享参数预设是一份按任务类型、可选资源 ID 和参数格式版本约束的命名参数集合，用于让多个节点或多个计划复用同一套配置；它不包含任务结构、执行顺序或计划引用。有效来源预览按共享预设、祖先分组覆盖、节点显式参数的顺序合并，因此局部显式设置始终优先。步骤 2 页面只负责为兼容节点选择和刷新已有预设，预设的创建、重命名与编辑入口仍待后续参数管理界面，不应让空下拉框看起来像任务模板功能。能力默认值要等执行器或资源清单注册后纳入，不在界面中猜测。执行记录和触发方式页签仅保留后续入口，本步骤不创建运行状态或调度逻辑。

## 步骤 5 实现入口

“任务计划”的新增菜单直接打开 `PuloniaTaskCreationDialog`，不再设置独立“任务库”菜单或全量资源聚合页。任务树右键只表达“要创建哪类任务”，具体内置能力、资源、名称、目录方式和参数都在类型专用弹窗中完成；确认结果作为一次编辑写入，取消不会先插入占位节点。弹窗使用注册能力的 Schema 生成布尔、枚举、文本与 JSON 字段，只保存相对能力默认值真正变化的显式覆盖。

资源索引只在用户选择路线、JS 或录制回放任务后扫描当前类型的目录结构、文件属性和 JS 项目清单位置，最多索引一万项并跳过重解析点；不会在进入主页面时扫描全部资源。搜索只过滤缓存且带短防抖，详情在选中后读取。JS 预览按需加载清单、作者、版本、说明和最多 16000 字符的 README；路线与录制资源不在列表阶段解析 JSON 正文。列表启用 WPF 容器回收，刷新由用户显式触发。“获取更多资源”复用现有脚本仓库，关闭后自动刷新当前类型；路线录制编辑、JS 和录制回放工具仍从各自原页面进入。

路线与录制目录默认建立固定版本的目录引用，也可确认后一次性展开为保留目录结构或扁平的普通任务；展开过程先完成有限完整枚举，超过安全上限时整体拒绝，不能静默只添加部分文件。单资源、展开叶子和目录引用均保存内容指纹，运行准备检测到变化后拒绝执行；用户可在任务树节点菜单查看旧、新指纹并显式更新。这样吸收 d-v3 “先选资源再创建”和集中预览的优点，同时保留 Pulonia 的单一任务模型、版本快照和原子编辑基线，没有把旧 GearTask 流程复制进来。
