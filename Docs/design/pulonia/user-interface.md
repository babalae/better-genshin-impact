# Pulonia：界面

[返回总览](README.md) · [用户故事](requirements.md) · [路线图](roadmap.md)

“任务计划”沿用 d-v3 的树表交互，“新一条龙”沿用旧 `OneDragonFlowPage` 的左右布局。两者是不同界面，共用 `PuloniaPlanEditingSession`、计划模型、[有效参数解析规则](model.md#有效参数解析规则)和执行服务。2026-10-24 按当前代码核对；步骤 2、5 的实现记录原文见[归档](archive/user-interface-step-notes.md)。

## 页面与分工

| 页面 | 内容 |
| --- | --- |
| 任务计划（`PuloniaTaskPlanPage`） | 左侧计划列表（只列 `purpose` 为 General 的计划）；右侧“任务、执行记录、触发方式、路线 CD”四个页签，任务树为主要工作区 |
| 新一条龙（`PuloniaOneDragonPage`） | 左侧平面任务清单，右侧配置选择与选中任务的设置；执行记录、定时与热键、导入、账号管理为次级窗口 |
| 执行记录（`PuloniaTaskHistoryPage`） | “运行记录”页签为全部计划的运行汇总，与计划页“执行记录”页签共用一个 `PuloniaTaskHistoryViewModel` 实例；“路线 CD”页签为全部计划的 CD 总览（独立实例） |
| 托管 | 未实现，见[目标托管提案](proposals/managed-hosting.md) |

**编辑会话。** `PuloniaPlanEditingSession` 是 DI 单例，两个页面共用：持有全部计划文档（普通计划与一条龙配置分两个集合），负责首次加载（两个入口复用同一次读盘）、自动保存、计划增删复制与导入、资源版本检查和运行提交。页面 VM 只保留选择、菜单和弹窗输入。`PuloniaTaskPlanDocumentViewModel` 代表一份计划：节点树、30 步快照撤销（调用方可传合并键，一条龙设置区据此把同一字段的连续输入合并为一步）、有效参数预览和保存状态。

**自动保存。** 一次结构或配置操作后防抖约 350 ms 写盘；每份文档有一把专用的保存门，同一计划串行写入，写入期间的新编辑继续保留，保存成功不重建树、不清空撤销历史。正常保存保持静默；只有失败才显示错误并保留草稿（`LastSaveError`），下一次编辑后重试。界面没有手动保存按钮。

**坏文件。** 读不出的计划文件被跳过，进入页面时弹出提示，文件保留在磁盘上，修复后重新进入即可加载。

**窗口与分层。** 节点高级设置窗口的状态由 `PuloniaTaskNodeAdvancedSettingsViewModel` 按需计算（任务参数、共享设置、策略、来源的原始 JSON 与共享设置摘要）；共享设置、设置方案管理、路线 CD、运行预览和 JS 脚本设置等窗口由视图层 `PuloniaTaskSettingsDialogs`（接口 `IPuloniaTaskSettingsDialogs`）创建，文档 VM 不创建窗口、不读全局配置（“从全局配置创建”方案只在视图层读取 `AllConfig`）。参数中文名只有 `PuloniaTaskFieldNames` 一份；节点结果的解释在 `PuloniaTaskResultInterpreter`，运行与子树状态归类在 `PuloniaTaskRunClassifier`。仍存在的越界见[总览的已知偏差](README.md#已知偏差)。

## 任务计划页

### 计划列表

右键新建、重命名、复制、删除、重新加载，双击或 `F2` 重命名。新建时弹窗填写名称并选择设置方案（默认不使用方案），所选方案挂在计划根节点上，取消不创建计划。拖拽排序的结果写入 `plan-order.json`，不改计划内容和修订号。计划卡片在名称下显示计划根节点的设置方案（未使用、方案名或方案缺失警示），不显示修订号。每张计划卡片有“新执行此计划”按钮（默认不限时，不续跑历史），有待更新资源时显示“更新此计划任务资源”，命令都显式携带该卡片的计划。

### 任务树

- 树直接展示 `RootTask.Children`，不重复显示根节点。空白处右键的新增、粘贴和引用固定追加到当前计划根级；在节点上右键时，分组向组内添加，叶子插在其后。
- 节点右键菜单：编辑配置（`F2`、双击）、共享设置…、添加分组、添加独立任务、添加地图追踪 / JS 脚本 / 录制回放 / Shell / 进程内 C# 任务、引用已有任务计划…、复制子树（`Ctrl+C`）、粘贴（`Ctrl+V`）、删除（`Delete`）、撤销上次编辑（`Ctrl+Z`）、启用全部子任务、更新此任务资源…。Shell 与进程内 C# 常驻菜单，是否只在开发模式显示待定 D14。
- 右键先选中鼠标所在节点；`ContextMenu` 通过绑定代理访问页面命令，所有新增、粘贴和引用命令显式携带目标节点，并通过该节点所属文档修改数据。
- 树空白处右键另有“计划共享设置…”（编辑计划根，传给全部任务）和“设置方案…”；计划卡片右键菜单提供同样两项。
- 节点行尾的共享设置标记：挂了方案时显示方案名（方案缺失时用警示色并显示“方案缺失”），本节点有覆盖时显示设置图标和覆盖项数；悬停列出方案和覆盖的设置项与值。
- 拖拽以插入线或分组高亮反馈位置，禁止形成环路。
- 固定重复不是任务类型：在分组配置中填写 1—10000 的“执行次数”，不改变树结构。
- 分组关闭时整棵子树不执行，但不改写子节点自己的开关；“启用全部子任务”是独立命令。

### 节点配置

双击、`F2` 或“编辑配置…”打开统一的节点设置弹窗，可编辑名称、启用、执行次数、资源版本、任务参数、策略和引用来源。任务参数按能力 Schema 生成表单，共享设置绑定的参数不在表单中出现；JS 的 `settings` 通过“脚本自定义设置”卡片的按钮打开独立窗口（`PuloniaJsScriptSettingsDialog`），按脚本自己的 `settings_ui` 生成表单，确认后立即生效并可撤销。分组、计划根、引用和使用共享设置的叶子显示“共享设置”卡片：摘要为所挂方案和本节点修改的项数，按钮打开共享设置窗口。高级区直接暴露任务参数、共享设置、策略、来源四段 JSON（来源 JSON 能改变节点种类），是否只在开发者模式显示待定 D10。

### 共享设置与设置方案

规则见[有效参数解析规则](model.md#有效参数解析规则)，设计见[共享设置与设置方案](proposals/shared-settings.md)。

- **共享设置窗口**（`PuloniaSharedSettingsWindow`，模态）：左侧类别导航，右侧设置项卡片，每项显示当前有效值、来源（默认、计划、分组「…」、方案「…」（分组「…」）、本节点）和值的来历（悬停）。修改即时写入节点并自动保存，同一节点同一项的连续输入合并为一次撤销。
- 窗口顶部选择方案、“另存为方案”（带上原方案内容，改用新方案后有效值不变）和“管理方案”；支持搜索、只看本节点修改、显示高级项、单项恢复继承、全部恢复继承、移除与继承值相同的覆盖。依赖条件不满足的项禁用并说明原因。
- 分组的类别标题下显示受影响的任务数；叶子只列出其能力使用的设置项，能力没有绑定的叶子不提供共享设置入口。
- **设置方案管理窗口**（`PuloniaSettingsProfileManagerWindow`）：新建、复制、重命名、删除、从全局配置创建（按条件选队，并取当前全局自动战斗与地图追踪条件配置中与默认值不同的项，即旧调度器未启用配置组设置时的行为；之后修改全局配置不影响方案）。方案内容在草稿上编辑，显式保存或放弃；保存被使用的方案前列出受影响的节点并确认。仍被已保存计划使用的方案不能删除，列出使用位置。

### 复制、粘贴与引用（US-12）

- 跨计划复制子树保留任务参数（数组、布尔、null 与数值类型不变）、每个节点的共享设置和所挂方案，为每个节点生成新 ID；不复制触发器或历史进度。
- 粘贴位置的外层共享设置可能不同，粘贴前显示有效值差异，并提供“保留当前有效设置”：把与复制来源外层不同的设置项写到粘贴的子树根上（根节点自身或其方案已设置的项不写）。
- 跨分组拖动后若有任务的有效共享设置改变，页面底部显示非模态提示“移动后 N 个任务的 M 项设置已改变”：“查看”展开逐项明细，“保留原值”把移动前的值写到被移动的子树根上并与移动合为一步撤销，“忽略”接受新位置的继承。移动后已有其他编辑或撤销时，“保留原值”不再写入；切换计划时提示关闭。
- 删除、拖动、批量添加各为一次可撤销编辑；撤销只作用于配置，不撤销已发生的游戏操作。
- 引用候选是会话中的其他普通计划，不以是否已保存过滤。目标计划仍在自动保存防抖中时，先完成其保存再建立引用，保存失败则不建立。添加前检查直接和间接依赖，拒绝形成循环。

### 资源更新

- 资源名称后显示更新标签：声明版本号不同时显示 `1.1 → 1.2`；版本号相同、缺失或不可读但资源指纹变化时显示“有更新”；读取失败显示“资源不可用”，悬停看原因。JS、路线、录制回放、目录引用和计划引用都参与检查，重复引用只算一次。
- 进入页面、手动刷新和提交运行前检查一次；页面可见期间每 10 秒复查，仓库同步事件只检查引用该仓库的节点；离开页面停止。检查按仓库批量读取，不增加计划修订。
- 计划列表头部三个图标按钮：“一键同步并更新”（同步全部计划实际引用的仓库再更新所有可用资源，不同步没有引用的仓库）、“更新所有任务计划”、“检查任务资源更新”。合并为一个入口待定 D13。
- 确认更新前重新核对候选集合；按计划合并为一次可撤销的修改并保存。单项失败不阻止其他项。保存失败时新版本留在草稿中并显示 `LastSaveError`，可撤销或稍后重试，不自动回滚。
- 参数、开关和已有执行记录不变；禁用的任务仍可查看和更新。
- 提交运行时，启用中的本地路径资源若有未确认的更新，拒绝提交。

JS 的资源指纹只读取项目根目录的 `manifest.json` 和 `main.js`，其他文件（模块、`packages`、`settings_ui`、README、assets、运行数据）变化都不提示更新（改用项目子树身份待定 D11）。两个必需文件缺失或不可读时显示资源不可用，不能确认部分或空版本。

## 新一条龙页

### 布局

- **左列**：上方开始、停止和“更多”按钮，其下是平面任务清单。每行有拖拽图标、状态点、任务名和开关；清单只支持根级排序，分组和引用各占一行，不能拖入分组内部。
- **右列**：“配置”标题、运行账号按钮、配置下拉框（只列 `purpose` 为 OneDragon 的计划）及新增、重命名、删除；下方只展示左侧选中任务的设置，用 `ui:CardControl` / `ui:CardExpander` 呈现，战斗对象为嵌套卡片，树脂优先级为有序下拉框。不提供按星期覆盖参数或跳过的每周安排。
- 有可用子实例时显示“运行于”下拉框，选择执行实例，见[跨实例派发](execution.md#跨实例派发)。
- 主页面不放页签、计划侧栏、树/卡片切换或按类型划分的大工具栏。

“更多”菜单：引用已有任务计划…、添加任务、执行记录、账号管理、显示账号切换步骤、定时与热键、撤销最近编辑、配置共享设置…（配置根节点，传给清单中的全部任务）、设置方案…、导入旧配置、查看导入报告。任务卡片右键：引用已有任务计划…、添加任务、删除任务。

清单行在开关前显示与任务树相同的共享设置标记（设置图标与覆盖项数，悬停看明细）。选中分组、引用或使用共享设置的任务时，右侧设置区显示“共享设置”卡片，摘要为方案和本任务修改的项数，点击打开共享设置窗口；没有内嵌编辑器。

新建一条龙配置默认按旧顺序包含 8 项：领取邮件、合成树脂、自动秘境、自动首领讨伐、自动幽境危战、自动地脉花、领取每日奖励、领取尘歌壶奖励（由能力说明的 `OneDragonOrder` 生成）。清单可加入所有已注册任务类型和已有普通计划，可重复添加、增删和排序。

### 状态点

状态由 `PuloniaTaskRunClassifier` 按该行子树最近一次运行的节点结果归类，颜色使用主题语义资源：

| 状态 | 文字 | 主题资源 |
| --- | --- | --- |
| NotRun | 尚未执行 | `TextFillColorTertiaryBrush` |
| SkippedOrStopped | 已跳过或停止 | `TextFillColorTertiaryBrush` |
| Running | 执行中 | `AccentFillColorDefaultBrush` |
| Failed | 执行失败 | `SystemFillColorCriticalBrush` |
| NeedsVerification | 待核验 | `SystemFillColorCautionBrush` |
| Completed | 已完成 | `SystemFillColorSuccessBrush` |

### 右侧设置即时生效

- 专属视图与通用卡片的每次输入立即换算为该节点的显式参数并自动保存：修改的字段写入新值，改回原值的字段恢复打开设置区时的显式值或继承状态，其他显式参数不变。对象字段的写回方式见[有效参数解析规则](model.md#合并语义)。
- 写入前按能力 Schema 校验。无法解析的输入（如逐字输入中的不完整内容）只跳过该字段，并在设置区提示“以下输入未生效，仍使用上次的值”；整体 Schema 校验失败时本次修改都不生效。
- 同一组字段的连续输入合并为一次撤销，换字段另起一步。没有“应用设置”和“重置草稿”，恢复修改用撤销。
- 设置区只在选中行变化、撤销或其他入口改写该节点参数时重建，自身提交不重建，不打断输入焦点。
- 开始运行直接使用已生效的参数；未生效的无效输入不阻止运行。名称和执行次数同样即时生效。
- 高级设置窗口只保留来源、继承、共享设置入口和原始 JSON，不再重复一套参数表单。

### 运行账号

- 绑定非默认账号时，“配置”标题旁常驻“运行账号：<名称>”按钮；账号资料被删除或绑定无效时提示重新选择。
- “显示账号切换步骤”只控制清单首位是否显示“切换账号”准备项；绑定始终生效。
- 账号规则见[多账号](accounts.md)。

### 次级窗口

- **定时与热键**：与任务计划页共用 `PuloniaTaskTriggerView` 与 `PuloniaPlanTriggersViewModel`，每次打开新建一个触发设置 VM 直接编辑共享文档，关闭时释放，不克隆页面 VM。
- **执行记录**：使用独立的 `PuloniaTaskHistoryViewModel` 实例，只显示当前配置，不影响全局执行记录页的筛选。
- **导入旧配置**：见[重构与迁移](migration.md#旧数据导入)。

## 触发设置

两页共用 `PuloniaTaskTriggerView`：

- 卡片上的开关直接启用或停用并保存，不提交右侧尚未保存的草稿；启用“停止当前”策略需要二次确认。
- 右侧是独立草稿，显式保存或取消。“新增定时触发”与“新增快捷键触发”（默认键鼠监听 `F8`）；列表支持右键删除。
- “补触发”复选框只对定时触发器显示；热键模式切换时清空原键值，重新捕获后保存。
- 一条龙显示“运行账号”说明（触发器使用配置绑定的账号）；普通计划显示“账号参数资料（不会自动切换账号）”下拉框。
- 触发规则见[触发与热键](scheduling.md)。

## 执行记录

列出排队、运行中和已归档的运行。全局执行记录页分“运行记录”和“路线 CD”两个页签；单次运行的详情不再附带当前账本，路线 CD 见下节。详情显示实际核验 UID、“来源 / 作用域”（作用域只显示账号）、执行实例、触发器与执行范围、节点结果、已确认事实和下次可执行时间。续跑只从执行记录发起：“继续上次”或“从选中节点开始”；包含未核验结果或显式起点时要求确认，见[续跑](execution.md#续跑)。

## 路线 CD

2026-10-28 按[路线 CD 提案](proposals/cooldown-visibility.md)实现，主要影响任务计划页；新一条龙的任务清单与状态点不变（用户决定）。规则与判定见[结果、CD 与存储](results-and-storage.md#文件级路线-cd)。

| 位置 | 内容 |
| --- | --- |
| 任务树叶子行尾 | “CD 中 · 剩 5 小时 12 分”“CD 中 · 明天 04:00”“已完成”；未识别刷新规则时显示“未识别 CD”（提示色）；可执行与不检查不显示。悬停列出规则、上次成功与下次可执行时间 |
| 分组、计划引用 | 汇总“2/5 CD 中”或“3 项未识别 CD”，悬停给出最早可执行时间；只统计启用的路线 |
| 目录引用 | “N 项 CD 中”：不展开目录，只按该组规则判定账本中目录下的记录 |
| “任务”页签顶部 | 当前计划的摘要“路线 CD：本次 3 项会因 CD 跳过 · 1 项未识别刷新规则”，右侧“预览本次执行”按钮；计划卡片右键也有“预览本次执行…” |
| 运行预览窗口（`PuloniaTaskRunPreviewWindow`） | 按执行顺序列出每个叶子：执行、已关闭、跳过 · CD 中、跳过 · 已完成、跳过 · 本次重复；可只看跳过项、多选清除记录后刷新，或直接“开始执行” |
| “路线 CD”页签（任务计划页、全局执行记录页、一条龙执行记录窗口） | `PuloniaCollectionCooldownOverviewViewModel`：按账号、计划（含目录与计划引用）、状态和关键词筛选，按材料分组；显示路线名与目录、记录时规则、上次成功、下次可执行；可清除选中记录或当前列表全部记录。剩余时间按记录时规则，列表说明“计划中的节点按当前规则判定，以任务树标记为准” |
| 共享设置行、路线 CD 表单 | 行内显示规则摘要；表单三选一（自动识别 / 不检查 / 自定义周期），显示识别结果；叶子顶部显示当前账号的状态、上次成功与下次可执行时间和“清除记录”；分组显示下属路线的识别分布；同一文件在别处规则不同时提示 |
| 地图追踪添加弹窗 | 资源详情上方显示识别结果：文件为“落落莓 · 成功后 46 小时”或“未识别刷新规则”，目录为“120 个路线文件，识别 112 个（…），8 个未识别” |
| 运行中与运行后 | 跳过时当前消息为“已跳过“…”：仍在 CD，…后可执行”；运行汇总单列“路线 CD 跳过 N”；结果字段中的时间按本机时间显示 |

标记由编辑会话计算（`PuloniaPlanEditingSession.Cooldowns`）：任务计划页可见时订阅 `LedgerChanged`，编辑后防抖 500 ms 重算，每分钟刷新剩余时间，离开页面停止。普通计划与一条龙默认账号按当前登录账号计算；一条龙绑定指定账号时按账号资料的 UID。清除记录前用 `ThemedMessageBox` 确认，说明不影响运行历史且不能撤销。

## 新增任务与整个目录

- 右键选择具体任务类型后打开对应弹窗（`PuloniaTaskCreationDialog`；独立任务为 `PuloniaSoloTaskCreationDialog`），确认后才一次插入任务树，取消不留占位节点。弹窗只收集输入，任务构建、参数校验、资源保留和目录展开由 `PuloniaTaskCreationService` 完成。
- 资源索引只在选择对应类型后建立，只读当前类型的目录结构、文件属性和 JS 清单位置，最多一万项，跳过重解析点；搜索只过滤缓存并防抖，详情按需读取，路线和录制在列表阶段不解析正文。
- 地图追踪用可折叠目录树，搜索命中时保留祖先链；JS 详情用原生 `MarkdownView` 渲染 `README.md`；项目声明了 `manifest.settings_ui` 时，任务计划在点击“添加任务”后弹出脚本设置窗口填写节点 `settings`，取消则不添加（新一条龙的添加弹窗仍内嵌该表单）。
- 任务计划的添加弹窗不填写地图追踪与 JS 的运行设置（队伍、拾取、战斗、路线 CD 等），新任务沿用所在分组或默认值，添加后在节点“编辑配置”中修改；只保留目录添加方式和录制回放的“按录制延时回放”。地图追踪资源只显示路线 CD 的识别结果。
- 资源区顶部是仓库下拉框和“管理仓库”按钮；仓库的添加、同步、移除只在仓库管理窗口进行，见[脚本仓库与任务资源](repository-resources.md)。添加任务只读本机内容，不访问远端。

目录添加有三种方式（`PuloniaTaskDirectoryImportMode`），只对路线与键鼠录制目录可用：

| 方式 | 保存与编辑方式 |
| --- | --- |
| 引用目录（默认） | 分组的 `source` 保存目录定位与目录指纹；运行前在固定版本上列出 JSON 清单，展开节点 ID 按相对路径稳定生成 |
| 保留结构展开 | 一次批量写成保留目录层级的普通任务节点 |
| 扁平展开 | 一次批量写成同一层的普通任务节点（去掉此方式待定 D12） |

引用目录不是“永远运行最新内容”：默认固定版本，内容变化后提示更新，由用户确认。展开时先完成有限的完整枚举，超过上限整体拒绝，不静默只添加部分文件。批量添加是一次模型变更、一次保存。

## 技术约定

- ViewModel 继承 `ObservableObject` 或项目 `ViewModel`，使用 `[ObservableProperty]`、`[RelayCommand]`、Behaviors 和 gong-wpf-dragdrop；简单提示用 `ThemedMessageBox`。
- 树和列表启用虚拟化与容器回收；不新增第三方树组件。
- 体力计划的界面设计见[提案](proposals/resin-plan.md#4-ui--ux-设计)，未实现。
