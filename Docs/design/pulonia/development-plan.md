# Pulonia：开发与逐步验收计划

[返回总览](../automation-system.md) · [用户故事](requirements.md)

每一步都需用户明确验收通过后才能进入下一步。实现时优先阅读[需求基线](requirements.md)，再查本步对应专题。

## 当前状态与验收规则

当前仅完成设计文档整理，**步骤 0 待用户验收；步骤 1—13 均未开始**。这份计划不表示已经授权连续实施全部步骤。

**每一步的流程固定为：确定本步范围 → 实现和自查 → 提交验收材料 → 等待用户明确验收通过 → 才能开始下一步。** 编译通过、自动检查通过或代理自行判断完成，都不能替代用户验收。需要修改时留在当前步骤修正并重新提交，不跨步推进。

每次提交只附四项：本步完成了什么、如何验收、编译/检查结果、已知限制。验收材料包含可定位的代码/界面入口或示例；代理默认不启动游戏，游戏内效果由用户验收。实现阶段按项目要求执行 `dotnet build BetterGenshinImpact.sln -c Debug`，程序占用时记录未验证原因，不伪报成功。

若某一步仍过大，在开始该步前列出更小的交付项，**每个子步骤也分别等待用户验收**，不能通过拆子步骤绕过门槛。下表中的步骤依次推进；调整顺序或扩大范围时先更新计划并交由用户确认。

## 开发顺序

| 步骤 | 本步交付 | 请用户验收的重点 | 关联故事 |
| --- | --- | --- | --- |
| 0. 设计基线 | 总览、专题设计、本计划；列出待定选择 | 需求未偏离，分层和开发顺序可接受；认可在步骤 1 用样例决定可执行树形式 | 全部 |
| 1. 模型与最小存储 | `PuloniaTask`/计划、稳定 ID、参数对象、JSON 读写与校验；引用/目录/重复的样例；运行准备原型 | 树格式、ER、命名和参数类型清晰；保存再读取不丢失内容；比较快照直执行与只读执行树，确认一种方案后固定合同 | 04、05、09、11 |
| 2. 树编辑与配置 | 新“任务计划”页，分组、拖拽、启用、跨计划复制、撤销；参数编辑和有效来源预览 | 父组开关不覆盖子项选择；复制参数保真；预设切换立即正确显示；编辑与保存失败可恢复。此步不接真实游戏执行 | 04、09、12 |
| 3. 最小可运行链路 | 串行执行、请求与状态、运行快照、有限超时/取消；Shell、纯计算 C# 和进程内 C# 调用 | 用无游戏样例完成“提交→运行→结果→取消”；不启动截图器；编辑不影响正在运行的快照；Shell 子进程正确收尾 | 04、05、06 |
| 4. 游戏能力适配 | 按需准备会话、输入所有权、真实结果；依次接入路线、JS、宏和需要替代的内置任务；JS 子调用统一上下文 | 同一能力直接启动和 JS 调用结果一致；取消后释放输入；启动不依赖页面；纯任务仍不依赖截图。**每类适配单独作为子步骤验收** | 03、04、05、07 |
| 5. 任务库与批量添加 | 搜索索引、README 预览、目录引用/展开、资源版本；路线录制编辑和 JS 工具的新入口 | 快速找到材料并加整目录；大目录操作可响应；不需复制资源或运行脚本生成菜单；原资源编辑功能可从新入口到达 | 10 |
| 6. CD、历史与节点续跑 | 账号/世界作用域、日周月额度、结构化证据、状态文件一致保存、历史详情、从节点继续 | 用受控样例验证部分成功、重复事件、日切与崩溃；未确认不能记成功；跨计划共享 CD、跨账号隔离；旧快照可续跑 | 03、06、11 |
| 7. 定时、热键与空闲 | 结构化日程、热键、空闲准入、过期/补触发、运行忙碌策略；Windows 任务计划启动入口 | 到点不空闲则等待；用户回来停止新增输入；重复热键不重复执行；应用未启动时能按条件唤起；不引入 Quartz | 02、08 |
| 8. 有界恢复 | 已知月卡/网络等中断处理、总时限、未知界面待处理与诊断；恢复与业务交接输入 | 已知场景在预算内恢复；未知界面、背包满和顶号明确停止/待处理；不无限重试，不在旧任务未结束时启动下一项 | 07 |
| 9. 一条龙视图与旧数据迁移 | 同计划的简洁视图、有效配置直显、旧配置组/一条龙/d-v3 导入、兼容差异清单 | 简洁与树视图来回切换不丢数据；代表性旧配置导入结果一致；新入口覆盖旧任务、路线和 JS 管理。**此步验收前保留旧菜单，不在这里提前删除** | 04、09、10、12 |
| 10. 多账号与外部 C# | 按账号顺序运行、预设绑定、受支持渠道切号和 UID 核验；本机 C# 客户端查询/提交/取消 | 两账号目标与记录不串用，切号失败不在错误账号继续；进程外调用与 UI 结果一致。切号和外部客户端分子步骤验收 | 05、11 |
| 11. 基础目标托管 | 手选角色/物品目标、读取必要练度/库存/树脂、精选任务资源、可解释规划和今日安排 | 区分库存目标与周期新增；按优先级共享树脂预算；普通玩家无需研究订阅；识别未知有提示，能调整推荐安排 | 01 |
| 12. 扩大自动识别覆盖 | 逐项补 box 枚举、物品状态、圣遗物信息与策略、可靠采集事件和能力检查点 | 每种新增能力用明确样本验收识别/误判和回退结果；不能以“支持接口”代表已实现识别。**每种能力分别验收，不能整包宣布完成** | 01、03、06、07 |
| 13. 完整替代与收口 | 汇总能力对照、导入差异及回归结果；完成已验收范围内的旧菜单切换，保留原数据 | 用户先确认切换清单，再移除对应旧菜单/重复入口，完成后再验收；剩余缺口明确列出，未满足的原始故事不能标完成 | 全部 |

步骤 1—9 完成后，按兼容清单验收“配置组/一条龙编排可替代”；步骤 10—12 完成托管目标。是否完全替代以实际能力和用户验收为准，不以步骤编号或代码合并为准。

步骤 12 的“更多识别与恢复”是持续扩展，但当前用户故事要求的覆盖范围必须列成明确子项；未做完的部分标为未交付，不能用“后续优化”掩盖缺失。远程 HTTP、多机联机编排和任意并行工作流不进入本计划。

## 验收场景索引

以下保留原概要的关键场景，按当前步骤选取相关项验证，不要求每次重复全部验证。真实游戏结果由用户验收；模型、取消、时间边界和文件故障可先用受控执行器与固定数据验证。

1. **V01** 同一路线在两个计划出现，第一条已确认采集后第二条显示剩余 CD；换账号后不串记录。
2. **V02** 20:00 到点但用户操作电脑，20:10 空闲才开始；超出截止时间则过期。
3. **V03** 运行时鼠标/键盘有用户活动，停止新增输入，续跑前重新准备环境。
4. **V04** 奖励已经领取、记录尚未提交时崩溃，重启后进入核验而不是直接重领。
5. **V05** 日切前开始、日切后领取，以及失败后已经采到部分素材，账本归属正确。
6. **V06** 修改计划/预设不改变正在执行的运行快照；资源版本变化不会静默影响续跑。
7. **V07** 任意入口调用同一动作均显示相同有效参数和来源。
8. **V08** 一万项资源目录按需加载和批量保存；使用固定数据集与基准环境记录首次打开、搜索和整目录添加耗时，验证 UI 可响应。
9. **V09** 旧任务不响应取消时，不得启动下一账号/节点继续争用输入。
10. **V10** 未知界面、被顶号、验证码、UID 错误都能有限结束并留下明确待处理原因。
11. **V11** 运行状态替换前后崩溃、历史归档前后崩溃、磁盘写入失败、备份回退时，进度和 CD 不出现两份相互矛盾的当前记录。
12. **V12** 目录引用更新后只影响新快照；关闭再开启分组不会丢失子项禁用；拖拽与重命名不破坏历史对应关系。
13. **V13** 不引入 Quartz、SQLite；休眠恢复、时区转换、时钟回拨、重复热键均不会无界补任务或重复占用游戏输入。
14. **V14** 带数组/布尔值的 JS 配置跨计划复制后，无需重启即可编辑和执行；误删、误拖可以撤销，粘贴继承差异有提示。
15. **V15** 同一路线由任务树和 JS 子调用启动，结果原因和额度规则一致；父任务汇总不会重复记账，钓鱼未进入和未领奖不会更新完成 CD。
16. **V16** “库存补到 N”“今日新增 N”“角色培养到目标”分别计算；用户中途使用材料或提升角色后刷新状态，不继续按过期缺口分配树脂。
17. **V17** 背包满、计划总时限到达、公共月卡中断及切号失败均有明确终态；旧任务未停止时，次日请求不能抢占输入。详见 US-07、11。
