**每一步的流程固定为：确定本步范围 → 实现和自查 → 提交验收材料 → 等待用户明确验收通过 → 才能开始下一步。** 编译通过、自动检查通过或代理自行判断完成，都不能替代用户验收。需要修改时留在当前步骤修正并重新提交，不跨步推进。

每次提交只附四项：本步完成了什么、如何验收、编译/检查结果、已知限制。验收材料只列可定位的代码/界面入口、待核对行为和已知限制，不提供或维护验收用的 `examples` JSON、预制计划或为实现特制的成功数据。代理默认不启动程序或游戏，真实使用效果由用户验收。实现阶段按项目要求执行 `dotnet build BetterGenshinImpact.sln -c Debug`，程序占用时记录未验证原因，不伪报成功。

2026-10-04 用户明确验收标准：**由用户自行选择真实配置、真实资源和实际使用场景进行验收，并由用户明确给出结论。** 导入使用用户已有的旧配置，新增和编辑通过实际界面完成，执行、停止、历史、调度及游戏效果按用户真实业务核对；不能仅证明代理提供的 JSON 能被当前实现读取或执行。编译、单元测试、静态检查和代理构造数据的通过结果都只属于开发自查，不证明真实数据兼容、界面可用或业务正确，也不能把“待验收”改为“已通过”。用户发现问题后修正实现，不修改用户数据来迎合实现；保留既有用户明确给出的验收结论，之后继续按本标准逐步验收。

若某一步仍过大，在开始该步前列出更小的交付项，**每个子步骤也分别等待用户验收**，不能通过拆子步骤绕过门槛。下表中的步骤依次推进；调整顺序或扩大范围时先更新计划并交由用户确认。
