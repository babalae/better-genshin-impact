# Pulonia：用户故事与设计边界

[返回总览](README.md) · [路线图](roadmap.md)

这份文档是需求基线。原始故事和社区补充统一编号；来源细节放在[调研依据](research.md)，避免阅读需求时被实现细节打断。

**设计的出发点是让玩家少配置、少空跑、知道实际完成了什么。** 任务树、调度、记录和 API 都服务于这个目标。后续增减实体、页面或依赖时，先说明它解决下列哪条故事；不能仅因技术上可以扩展，就增加一层框架或一种配置方式。

实施状态：US-11、US-13 以及下文涉及账户、多实例和路线 CD 的约束，按[实例、账户与路线 CD 统筹设计](../instance-account-model.md)改写，代码已于 2026-11-01 实施（路线图步骤 14），待用户验收，见[统筹设计第 15 节](../instance-account-model.md#15-实施记录)。

US-01—11 依据本次讨论整理，US-12 来自社区反馈，US-13 来自[实例、账户与路线 CD 统筹设计](../instance-account-model.md)（2026-10-31）。保留用户目标，不把建议的实现方式当成唯一解法；编号用于后文追踪。2026-10-04 按用户最新要求收缩 US-02 为程序内定时运行，触发不依赖电脑使用状态。2026-10-31 按统筹设计改写 US-11。

## 用这些故事约束后续设计

1. **默认路径必须短。** 选择角色/物品、确认目标与日程、查看推荐安排、开始运行；共享设置、设置方案、脚本来源和配置继承按需展开。
2. **树编辑器与一条龙页面共用同一计划模型与执行核心，用途只决定界面归属。** 每份一条龙配置是独立的 `PuloniaTaskPlan`，以 `purpose`（General=0 / OneDragon=1）标记在哪个界面出现：普通计划菜单仅列出 General，一条龙配置 ComboBox 仅列出 OneDragon；执行器与底层完整计划目录不区分用途，跨计划引用、校验和资源检查保持可用。任一界面都不另存一份隐式参数，编辑、触发、C# 调用不能再出现多套执行结果。
3. **先完成可替代的任务系统，再逐步扩大识别和规划能力。** 不用“智能规划”掩盖底层没有结果、不能取消、CD 不可信等问题；也不能以只完成执行器为由取消 US-01 的最终托管目标。
4. **公共问题由宿主解决，游戏业务仍由具体能力解决。** 宿主负责配置、时间、身份、记录、输入协调和已知全局中断；材料数据、配队、采集路线和奖励核验留在内容/能力中。社区脚本可以继续提供专业策略。
5. **复杂性要有来源。** 保留 d-v3 的树格式与有用交互，统一使用 `PuloniaTask` 相关命名；不引入 Quartz、SQLite，不增加多机编排、任意并行图或通用规则平台；US-13 的并行只发生在同一台电脑的不同实例之间，同一实例内仍串行。社区已有外部网站、多人同步方案不自动成为本次交付范围。每条复杂规则都要在下方“复杂规则 → 用户故事”表中登记来源；没有来源的规则要么删除，要么写明“按用户决定保留”。

## 边界分级

边界场景按影响分三级处理，与项目约定“首次实现聚焦主流程，暂不处理的场景用注释记录”一致：

| 级别 | 场景 | 处理方式 |
| --- | --- | --- |
| 必须处理 | 可能在错误账户上执行；同一账户被两个实例同时运行；重复消耗不可恢复的资源（树脂、购买、领奖）；丢失用户配置、运行状态或账户进度；游戏输入卡死 | 写完整逻辑 |
| 明确报错即可 | 配置冲突、文件损坏、外部手改文件 | 显示原因，保留现场，不写恢复逻辑 |
| 不处理 | 多处同时编辑同一配置、夏令时、时钟回拨后的去抖、极端数量上限、手改磁盘上的账户图片 | 用一行注释说明 |

“可能在错误账户上执行”按运行账户设置分两种（统筹设计 4.8）：

- **指定账户**：BetterGI 负责。切换前后严格核验 UID，失败不执行业务节点。
- **跟随当前账户**：用户负责让实例当前账户与游戏一致。BetterGI 在开局比对 UID 并提示，不保证；开局读不到 UID 时发现不了，错记的完成记录由用户在账户页清除。

当前对应的做法：

- **必须处理**：指定账户的运行在切换前后核验 UID，失败进入待处理；跟随当前账户的运行不切换、不主动登出，开局比对 UID，不一致只提示；同一账户同一时刻只能被一个运行占用，取得失败时进入待处理；切换前发现目标账户是另一个在线实例的当前账户时，手动运行需用户确认，触发器提交和主实例下发的运行进入待处理；密码只存在 Windows 凭据管理器；快照不可变，触发请求准入时复核截止时间和配置版本；先在写锁内写完成记录，再写节点结果，两步之间崩溃时这份路线按 CD 跳过、不重复执行；实例运行状态原子替换、备份回退、损坏时停止本实例的自动运行；释放租约时释放全部按键；Shell 结束整个进程树。
- **明确报错即可**：坏的计划文件和历史文件跳过并提示，文件不删除；计划和账户目录的修订冲突直接报错；损坏的 manifest 或路线 JSON 让资源检查显示“有更新”，确认更新时被拒绝；JS 工作目录被另一个运行占用时 10 秒后报错；嵌套获取游戏租约直接报错。
- **不处理**：两个页面共用一个编辑会话，不处理多进程同时编辑；触发器只用三个固定偏移，没有夏令时；热键去抖只用单调计时；账户图片不复核内容。

**配置类数据**（计划、设置方案、账户目录、偏好、仓库注册、计划顺序）只需要“原子替换 + 后写者胜”；实例设置（实例当前账户）同样原子替换、后写者覆盖。**实例运行状态** `instances/<目录名>/state.json`（排队请求、活动运行、待归档运行，以及本实例负责的定时触发器的游标）只由本实例写入，需要单写者和事务语义。**账户进度**（完成记录、首领领奖次数）任意实例都可以写，在 `.writer.lock` 内读改写，不丢更新。
