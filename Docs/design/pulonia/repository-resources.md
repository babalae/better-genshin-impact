[返回总览](README.md) · [模型与配置](model.md) · [标识与磁盘路径](identifiers-and-paths.md)

状态：已实施。本文是地图追踪、JS 和键鼠录制从本机仓库读取资源、同步仓库与更新任务资源的合同，2026-10-24 按当前代码核对。早期的多仓库讨论草案已归档（[script-repositories.md](archive/script-repositories.md)），其中仍有效的所有权与身份原则并入下文第一节；选择器像素细节与测试记录见[归档](archive/repository-resources-details.md)。老配置组的订阅文件、安装目录与自动更新入口保持原状。

## 所有权与身份

- **两种分类不能合并成一个枚举**：“官方 / 第三方”描述发布方身份；“远程 / 本地”决定内容由谁维护、程序能否更新。官方身份由应用认可的保留注册决定，第三方不能自行声明为官方。
- **远程仓库**由程序维护本机副本，只通过“同步仓库”更新；**本地仓库**由用户维护，即使目录里有 `.git` 或配置了远端，程序也不 pull、reset 或 clean，只提供“刷新目录”。
- **仓库注册 ID 与名称、磁盘位置分离**：官方固定为 `official`，其他为 `rep_` 加 16 位；改名、切换远端地址或分支不改变身份和目录，已有任务引用不受影响。
- **任务资源引用 = 仓库 ID + 仓库内相对路径 + 已确认的修订**。任务类型已在节点上，不再重复保存；同名资源在不同仓库中互不替换，也不按优先级挑选。
- **资源专用参数、预设作用域和索引**都使用带仓库身份的键 `<repository_id>/<relative_path>`，第三方同名脚本不会复用错误参数。
- **移除仓库**只取消注册，不删除本地文件，也不自动改绑同名资源；已保留的内容继续供已有任务运行。
- **脚本内部依赖**：项目内相对读取以项目为根；跨资源读取（如 `pathingScript.RunFileFromUser`）映射到同一已确认版本的 `repo/pathing`，缺失时明确失败，不搜索其他仓库。

## 仓库管理

添加 JS、地图追踪、录制任务的弹窗资源区顶部有仓库下拉框和“管理仓库”按钮。仓库的添加、同步、重置、移除和配置编辑只在独立的 `PuloniaRepositoryManagerWindow` 中进行，不在任务表单中堆放。打开时恢复该任务类型上次选择的仓库，只解析当前仓库的本机副本索引，不合并多个来源；关闭后刷新并定位所选仓库，所选仓库被移除时回到官方。

- **官方仓库**始终可见，不能移除、禁用或重新定位；clone 目录固定为 `Repos/bettergi-scripts-list`、分支 `release`，渠道（CNB、GitHub、自定义）以 `ScriptConfig` 为唯一选择来源，与旧的官方更新弹窗双向同步。
- **添加远程仓库**：独立模态窗口填写并校验名称、Git 地址和分支（默认 `release`），确认后才创建注册；添加不隐式同步。目录固定为 `Repos/Pulonia/<仓库 ID>`。注册模型保留远端集合与当前远端，第三方界面只编辑当前地址，其余远端原样保留（模型改为单个地址加分支尚未排期）。
- **添加本地仓库**：拖入或选择一个目录或 ZIP，自动识别类型，通过 `repo.json` 校验后立即注册目录或导入 ZIP。ZIP 写入前必须包含唯一仓库根、同级 `repo/` 目录及带 `indexes` 数组的有效 `repo.json`，拒绝路径穿越和符号链接；校验后复用老配置组的本地导入器解压到共享 `Repos` 区再注册。
- **移除**在注册表中持久化 `enabled: false`；显式再次添加同一目录可恢复。
- Git 凭据继续使用 Windows 凭据管理器的 `BetterGenshinImpact.GitCredentials`，不写入注册 JSON。

## 同步与更新任务资源

“同步仓库”只把远端内容更新到本机副本；“更新任务资源”只让计划采用当前本机内容，即改变任务使用版本。两者可单独执行，任务计划页另有“一键同步并更新”。

- 同步器先在临时副本中拉取指定分支并校验索引，成功后在该仓库目录的来源锁保护下替换固定目录，再发布仓库变化事件；失败保留原副本。重置只清理托管 clone，不删除注册和已确认内容。老入口更新官方目录后也只发布同一事件。
- **添加任务始终读取本机内容**：远程仓库读当前 clone，本地仓库直接读用户目录；列表、预览和确认添加都不访问远端。确认时固定当时的本机修订并保留所选资源。已有任务继续使用原 `path`，不猜测来源、不迁移本地修改。
- **一键同步并更新**：收集普通计划与一条龙配置实际引用的仓库并去重，依次同步远程仓库或刷新本地目录，再检查和更新资源；不处理没有任务引用的仓库。进度依次显示“正在同步仓库”“正在检查资源”“正在更新任务资源”。单个仓库同步失败时，若本机副本仍可读就继续用它检查并提示可能不是最新；没有可用副本时跳过其资源。最后汇总成功数、失败数和原因。
- **资源检查**按仓库批量：一轮检查每个仓库只打开一次当前快照，同一已确认修订的归档最多打开一次；指纹按（仓库、修订、路径、类型）缓存，声明版本先查缓存。单项读取失败只记在该项上；损坏的 manifest 或路线 JSON 不会中断整轮检查（内容指纹变化显示“有更新”，确认时保留校验会拒绝）。
- **确认更新**同时核对已审阅的资源指纹和来源修订：确认期间即使只有依赖变化、资源指纹不变，也拒绝接受未审阅的修订。准备失败的项保持旧版本；计划保存失败时更新留在草稿中并显示 `LastSaveError`，可撤销或稍后重试，不自动回滚。

| 内容变化 | 计划更新提示 | 执行内容 |
| --- | --- | --- |
| 路线 JSON | 提示 | 确认前仍用旧路线 |
| JS 根目录 `main.js` 或 `manifest.json` | 提示 | 确认前仍用旧项目和依赖 |
| JS 模块、图片、公共包或其他文件 | 不提示（D11 待定） | 仍用原确认版本 |
| 来源中移除资源 | “来源中已移除” | 已保留的内容仍可运行 |
| 来源检查失败 | “检查失败” | 已保留的内容仍可运行 |

## 三个版本概念

| 概念 | 字段 | 用途 |
| --- | --- | --- |
| 任务使用版本 | `resource.approved_revision`（40 位 Git 提交，或文件式来源 64 位修订） | 运行实际读取的来源版本；同步仓库不会改变它，只有“更新任务资源”会 |
| 资源指纹 | `resource_version`、目录引用的 `source.version` | 只用于判断资源是否有更新、续跑前核对内容；唯一实现 `PuloniaTaskResourceFingerprint` |
| 声明版本号 | JS `manifest.json` 的 `version`，路线 `info.version` | 只用于显示 `1.1 → 1.2`；缺失、相同或不可读时以指纹显示“有更新” |

`PuloniaTaskResourceFingerprint` 提供 `ComputeRepositoryVersion`（在固定快照上计算）、`ComputeFileVersionAsync`、`ComputeJavaScriptVersionAsync`、`ComputeDirectoryVersionAsync`、`ComputeManifestVersion` 等方法，创建任务、运行准备、资源检查和续跑都调用它，2026-10-24 合并后的输出与旧实现逐字节一致。规则：

- 文件资源为内容的 SHA-256 小写十六进制。
- JS 只计算项目根目录 `manifest.json` 与 `main.js`，不递归枚举；两个文件缺失或不可读时资源不可用，不能确认部分或空版本；保留重解析点保护。用户审阅的范围（两个文件）小于实际采用的范围（整个项目及公共包），改用项目子树身份待定 D11。
- 目录引用为“相对路径\0子资源指纹\n”清单的指纹，最多 1 万项。
- Web 页的 `hasUpdate` 不参与判断。`ScriptRepositoryStore` 内部的 `Hash` 只用于来源修订和归档块身份，不是任务资源指纹。

## 引用格式与目录布局

新叶子节点保存 `resource`，目录引用在 `source.resource` 保存同样的值对象：

```json
{
  "repository_id": "official 或 rep_ 加 16 位短 ID",
  "relative_path": "js/自动采集",
  "approved_revision": "40 位 Git 提交或 64 位文件式来源修订"
}
```

资源位置相对仓库的 `repo/` 内容目录。计划 JSON 不保存路线或 JS 正文，运行快照只记录 `resource`，不记录本机路径。

```text
Repos/bettergi-scripts-list/                       官方 clone（与旧入口共享）
Repos/Pulonia/<rep_…>/                             第三方 clone
User/Pulonia/ScriptResources/
├─ repositories.json                               仓库注册：身份、名称、类型、目录、远端集合、当前远端、分支
├─ selection.json                                  JS、地图追踪各自上次选择的仓库
├─ Snapshots/<仓库 ID>/retained.json               修订 → 范围 → 归档块；归档块 → 内容身份
├─ Snapshots/<仓库 ID>/<blk_…>.zip                 归档块
├─ Workspaces/<仓库 ID>/<JS 项目相对路径>/         JS 工作目录；同级 <项目目录名>.lock 为工作目录锁
├─ Previews/<pv_…>/                                一次性预览，用完即删
└─ Locks/                                          sources.<目录键>.lock、registry.lock、retain.<仓库 ID>.lock
```

资源数据归属 Pulonia，与计划、参数和运行记录一起备份；不迁移或回退读取旧 `User/ScriptResources`。目录名和文件名只用短 ID 与可读名称，来源修订、内容身份和指纹只保存在 JSON 中，见[标识与磁盘路径](identifiers-and-paths.md)。

## 文件式来源的修订

本地目录和导入的 ZIP 是文件式来源。浏览只扫描文件元数据并读取 `repo.json`，不做全量正文哈希；修订按 `file-v3` 规则计算：`repo_updated.json` 的写入时间（导入标记，ZIP 导入和 Git 更新每次都会重写，不存在时为 0）、`repo.json` 的 SHA-256，以及各文件的“路径、长度、修改时间”清单。`.git` 与 `repo_updated.json` 本身不计入清单。

正文指纹延迟到使用对应文件时计算，并按（大小、修改时间、导入标记）缓存；其他实例导入 ZIP 后，导入标记变化会让本实例的旧缓存失效。

## 锁与并发

配置类文件（`repositories.json`、`selection.json`）写入时先写同目录临时文件，再用 `File.Replace` 替换（首次建立时移动）；读取以 `FileShare.Read | FileShare.Delete` 打开，读注册和读选择都不取锁，写入方在读取期间替换文件也不影响已打开的句柄。多个写入方按后写者胜。

`Locks` 下的空文件只作为跨进程独占句柄，不保存业务数据：

| 锁 | 粒度与用途 |
| --- | --- |
| `sources.<目录键>` | 每个来源目录一把（键由规范化完整目录派生），同步、重置与读取该目录的短期临界区；同步一个仓库不阻塞读取另一个 |
| `registry` | 只保护注册列表的读改写 |
| `retain.<仓库 ID>` | 保留归档与 `retained.json` 的写入 |
| JS 工作目录锁 | 工作目录同级的 `.lock`，准备和执行 JS 全程持有；等待 10 秒仍被占用时报错“另一个运行（可能来自其他 BetterGI 实例）正在使用脚本……的工作目录” |

锁顺序固定为：工作目录锁 → retain → sources → registry，持有后者时不再取前者。选择记录没有锁，按后写者胜。宿主启动完成后，仅主实例尽力清理当前没有被任何实例持有的锁文件，清理失败不影响启动。

## 保留与读取

- **浏览不制作快照**：列表只解析固定修订中的 `repo.json`；Git 来源直接读提交对象，即使只检出索引也能浏览。
- **预览**只把 `manifest.json`、声明的设置文件和可选的 `README.md` 提取到一次性目录 `Previews/pv_…`，切换选择或关闭弹窗时删除；预览使用索引对应的精确修订，来源不可用时要求刷新。
- **确认添加或更新时才保留内容**：路线保存所选 JSON 或目录；JS 保存完整项目、同修订的公共 `packages` 和 `repo/pathing`（动态路线读取无法静态推断，引用同修订的 JS 共享该路线块）。内容块存为短 ID 命名的 ZIP，`retained.json` 记录各修订的范围与块，Git 子树 ID 或文件内容身份未变时跨修订复用。完整内容块发布后才原子替换索引；块已写入、索引尚未更新时崩溃会留下孤儿块，暂不清理。
- 首次保留时校验 JSON 语法、JS 清单、入口和声明的设置文件，失败则不产生归档和任务引用；资源已被同修订的其他范围覆盖时，路线正文由执行器解析时校验。所有候选资源保留成功后，确认命令才修改计划。
- **运行时不生成提取缓存**：路线和键鼠直接从保留归档读取正文，路线以 `User/AutoPathing` 下对应的逻辑路径识别材料；目录引用在固定快照上列出 JSON 清单。JS 由归档准备工作目录（完整项目及同修订的公共包），版本切换时保留旧、新 `manifest.saved_files` 声明的数据；工作目录中的代码修改不回写归档。工作目录镜像仓库相对路径，嵌套 JS 项目或只差大小写的两个项目路径会落到同一目录，暂不支持。
- 保留版本是执行策略：用户确认后才替换内容，因此已选资源必须保留，以支持来源删除、仓库重置和旧运行续跑。目前不自动清理保留版本；将来清理必须先核对计划、运行快照与保留记录。2026-10-24 起不再读取旧 `objects.git`、整仓 `<版本>.zip` 和 `scopes.json`。

`ScriptProject` 保留原构造入口，Pulonia 传入经过校验的工作目录和固定来源上下文；非 Pulonia 调用继续使用 `User/AutoPathing`。
