# Pulonia 远程仓库资源读取

状态：已实施。本文记录地图追踪和 JS 的本机仓库读取、同步及任务资源更新合同；[多仓库讨论草案](script-repositories.md)中的早期术语不再作为当前界面依据。老配置组的订阅文件、安装目录与自动更新入口保持原状。

## 引用与目录

添加 JS、地图追踪弹窗的资源区顶部保留仓库下拉和“管理仓库”按钮。管理、获取来源及尚未同步/空资源引导均打开独立的 `PuloniaRepositoryManagerWindow`，不再把仓库新增和删除堆在任务表单中。打开后恢复该任务类型上次选择，仅解析当前本机仓库副本的索引和展示其资源，不合并多个来源、不展开所有仓库。关闭管理窗口后刷新并定位所选来源，被移除时回到官方来源。

添加任务与管理窗口的仓库选择器共用展示模型和样式：收起时以约 36px 高度显示来源图标、名称及“官方/第三方/本地”标记，展开时以约 52px 高度补充短来源。官方显示当前渠道，第三方显示主机/仓库及分支，本地默认显示目录末尾两级。同名本地项逐级补足目录，相同名称和远端的第三方副本补充仓库 ID 末尾六位。长文本在固定控件宽度内省略，完整本地位置通过悬停和管理详情查看。渠道变化只更新现有展示项，不重建选择列表或读取资源正文；选项回传原始注册对象，不修改任何存储或任务身份。

下拉使用 ComboBox 原生鼠标捕获关闭机制，箭头区域和选中标记明确展示；打开管理窗口采用独立模态状态，不启动添加任务窗口的加载进度。只有管理窗口关闭后的索引刷新、资源预览或任务确认提取才显示添加页面的进度。

管理窗口只列出注册来源并补入官方仓库，不扫描其他目录自动建立引用。官方使用保留身份，始终可见且不能移除、禁用或重新定位，clone 目录固定为 `Repos/bettergi-scripts-list`、分支为 `release`。官方保留 CNB、GitHub、自定义渠道，以 `ScriptConfig` 为唯一选择来源，与现有官方弹窗双向同步。

仓库下拉只展示添加成功的真实注册。下方统一的“仓库操作”卡片采用两行布局：第一行是“添加远程仓库”和“添加本地仓库”；第二行显示当前仓库名称，远程来源提供“同步仓库”“重置仓库”，本地来源提供“刷新目录”，非官方来源另提供“移除仓库”。进度与结果统一放在操作卡片下方，忙碌时禁用仓库操作；底部只保留关闭，打开目录和已注册第三方的配置编辑仍位于详情区。

“添加远程仓库”打开独立模态窗口，填写并校验名称、Git 地址和分支。确认后创建注册、关闭窗口并在主下拉中选中新项，取消不创建记录，添加不会隐式同步。“添加本地仓库”打开带虚线拖放框的独立窗口，一次接收一个实际目录或 ZIP，点击区域弹出“选择目录 / 选择 ZIP”菜单。来源类型自动识别，通过 repo.json 校验后立即注册目录或导入 ZIP；成功关闭并选中新仓库，失败留在窗口内展示原因。处理期间禁止重复输入及关闭，ZIP 写入开始后等待解压与注册完整结束。

第三方远程来源先保存名称、地址和分支，点击“同步仓库”再拉取；分支默认 `release`，可指定 `main` 等分支，目录固定为 `Repos/Pulonia/<仓库ID>`。官方和第三方使用同一同步语义：只更新本机仓库副本，不修改任何任务使用版本。底层注册模型保留完整远端集合和当前远端，第三方界面仅编辑当前地址并保留其他项，多个渠道的界面仅对官方展示。切换地址、名称或分支不改变仓库身份或目录。

本地添加可以直接引用包含索引的仓库根目录，也可以导入 ZIP。ZIP 在写入前必须包含唯一仓库根、同级 `repo/` 目录及带 `indexes` 数组的有效 `repo.json`，并拒绝路径穿越或符号链接；通过校验后复用老配置组的本地导入器，解压到相同的共享 `Repos` 仓库区，再注册给 Pulonia。直接选择的开发目录不会加入自动更新目标，不提供拉取或重置，只提供“刷新目录”。移除会在注册表持久化 `enabled: false`；本地文件、稳定身份和已保留内容继续用于已有任务，显式添加同目录可恢复。切换仓库不改变旧任务引用。Git 凭据继续使用原 Windows 凭据管理器，不写入仓库注册 JSON。

同步器先在临时副本中拉取指定分支并校验索引，成功后在更新与跨实例来源锁保护下替换固定目录，再发布更新事件。失败保留原副本；重置只清理托管 clone，不删除注册和任务使用版本。老入口更新固定官方目录后只发布同一仓库变化事件，Pulonia 重新检查本机内容，不介入老配置组的安装行为。

添加任务始终读取本机内容：官方和第三方只读取各自当前 clone，本地仓库直接读取用户选择的目录。资源列表、预览和确认添加均不访问远端，也不隐式同步；确认时固定当时的本机仓库修订并保留所选资源。若要获取远端最新内容，用户必须先显式同步仓库。新任务不读取订阅目录，也不会执行自动订阅；已有任务继续使用原 `path`，不猜测来源、不迁移本地修改。

新叶子节点保存 `resource`，目录引用在 `source.resource` 保存同样的值对象：

```json
{
  "repository_id": "32位小写本机注册ID",
  "relative_path": "js/自动采集",
  "approved_revision": "40位Git提交或64位文件仓库来源版本"
}
```

资源位置相对仓库的 `repo/` 内容目录。参数预设的资源作用域使用 `<repository_id>/<relative_path>`，版本切换保留作用域，同名资源在不同来源中相互隔离。计划 JSON 不保存路线或 JS 正文。

```text
Repos/bettergi-scripts-list/                  共享的固定官方 clone
Repos/Pulonia/<仓库ID>/                      固定的第三方 clone
User/Pulonia/ScriptResources/repositories.json   稳定身份、名称、本地位置
User/Pulonia/ScriptResources/selection.json      JS、地图追踪各自上次选择
User/Pulonia/ScriptResources/Snapshots/<仓库ID>/Archives/<内容块ID>.zip
User/Pulonia/ScriptResources/Snapshots/<仓库ID>/<版本>/scopes.json
User/Pulonia/ScriptResources/Previews/<仓库ID>/<版本>/<资源键>/
User/Pulonia/ScriptResources/Cache/<仓库ID>/<版本>/<资源键>/content/
User/Pulonia/ScriptResources/Workspaces/<仓库ID>/<资源键>/
User/Pulonia/ScriptResources/Locks/              跨实例文件锁
User/Pulonia/ScriptResources/SourceVersions/     文件来源的更新代次
User/Pulonia/                               原有计划、参数、运行记录
```

资源数据归属 Pulonia，统一保存到 `User/Pulonia/ScriptResources`，便于和计划、参数及运行记录一起管理和备份。程序直接使用新目录，不迁移或回退读取旧 `User/ScriptResources`；旧数据由用户自行删除。原始拉取来源仍在 `Repos`，添加的本地来源保持自己的位置。

`Locks` 中的 SHA-256 命名空文件只作为跨实例独占句柄，不保存业务数据。BetterGI 宿主启动完成、实例上下文已初始化后，仅主实例尽力清理当前没有被任何实例持有的锁文件；活跃锁因无法独占打开而保留，异常退出产生的残留文件不需要等到正常关闭才能回收。清理与日志记录失败均不得中断程序启动。

`repositories.json` 保存仓库身份、名称、类型、本地目录、远端集合、当前远端和分支；`selection.json` 保存 JS 与地图追踪各自上次选择的仓库。官方渠道与自定义地址继续保存在 `User/config.json` 的 `ScriptConfig` 配置中，保证两个官方更新入口同步。Git 用户名与令牌保存在 Windows 凭据管理器的 `BetterGenshinImpact.GitCredentials` 项中。

仓库注册、版本会话和提取由共享的 `ScriptRepositoryStore` 提供。每次读取会话固定一个版本；索引、检查和提取不重复读取 HEAD 拼接内容。

## 保留与提取

列表只解析固定来源版本中的 `repo.json`，复用仓库 Web 页的资源清单，不遍历 Git 正文、不提取资源、不制作版本快照。Git 来源直接读取提交对象，即使只检出索引也能浏览。文件式来源仅扫描文件元数据并读取索引，版本由索引、元数据与持久化导入代次共同确定，正文指纹延迟到使用对应文件时计算。更新导入会变更代次，覆盖解压后文件大小和时间都未变化的情况。

JS 预览只提取 `manifest.json`、声明的设置文件和可选的 `README.md` 到 `Previews`，不复制代码、图片、模块或公共包。切换选择和取消弹窗会取消旧预览。预览仍使用索引对应的精确版本，来源已不可用时要求刷新，不改读最新内容。

确认添加或更新时才保留实际引用内容，新快照不包含 `.git`、整仓历史或其他 JS 项目。路线保存所选 JSON 或所选目录。JS 保存完整项目、同版本的公共 `packages` 和 `repo/pathing`；动态路线读取、目录枚举不能静态推断，因此所有引用同版本的 JS 共享该路线块。内容块存为 ZIP，固定版本的 `scopes.json` 记录范围与内容块身份；Git 子树 ID 或文件内容指纹未变化时跨版本复用归档。完整内容块发布后才原子发布映射，归档过程核对文件内容，来源重置、更新或重新克隆不影响已批准资源。

旧 `objects.git` 和整仓 `<版本>.zip` 快照继续兼容读取，不自动删除，也不为新确认版本建立整仓对象库。

保留版本是执行策略，并非浏览仓库的技术前提。目前继续采用“用户确认后才替换内容”，因此已选资源必须保留，以支持来源删除、仓库重置和旧运行续跑。若改为随仓库最新内容运行，可以省去旧版本保留，但更新会直接影响任务，不能继续承诺上述行为。取消版本保留需要独立调整执行合同，当前不会自动删除已保留数据。

路线按需提取 JSON；目录引用固定对应版本的 JSON 清单。JS 提取完整项目及同版本的公共 `packages`，动态依赖不会读取最新来源。缓存键包含完整仓库版本，不使用两文件指纹代替版本。

缓存通过临时目录、完整性清单、校验和原子重命名发布。JSON 语法、JS 清单、入口及声明的设置文件校验失败时不产生任务引用。损坏或缺失的缓存只能从原批准版本重建，不能回退到当前来源。提取所有候选资源成功后，确认命令才修改计划。

目前不自动清理保留版本；后续清理必须先核对计划、运行快照与保留记录，不能按当前 HEAD 或缓存时间删除旧版本。

## 同步、更新与运行

“同步仓库”只把远端内容更新到本机仓库副本；“更新任务资源”只让计划采用当前本机内容。两者可以单独执行，任务计划页另提供“一键同步并更新”：收集全部普通计划与新一条龙配置实际引用的仓库 ID 并去重，依次同步远程仓库或刷新本地目录，再逐项检查和更新任务资源，不处理没有任务引用的仓库。

一键流程按“正在同步仓库”“正在检查资源”“正在更新任务资源”展示进度。单个仓库同步失败时，若本机副本仍可读，就继续用该副本检查并提示它可能不是远端最新版本；没有可用副本时跳过对应资源。资源准备与计划保存按项、按计划尽力完成，成功项合并保存，失败项恢复旧引用，最终汇总仓库与资源的成功数、失败数和原因。

| 内容变化 | 计划更新提示 | 执行内容 |
| --- | --- | --- |
| 路线 JSON | 提示 | 确认前仍用旧路线 |
| JS 根 `main.js` 或 `manifest.json` | 提示 | 确认前仍用旧项目和依赖 |
| JS 模块、图片、公共包或其他无关资源 | 不提示 | 仍用原批准版本 |
| 来源移除资源 | 来源中已移除 | 保留内容仍可运行 |
| 来源检查失败 | 检查失败 | 保留内容仍可运行 |

同步成功后发布仓库 ID 与修订事件，页面只检查引用该来源的节点。页面打开、刷新、运行准备及页面可见时的定时检查补做核对。结构化检查状态分别保存当前内容指纹、当前本机仓库修订、任务使用内容的声明版本号和本机内容的声明版本号。JS 从 `manifest.json.version`、路线从 `info.version` 读取声明版本号；声明版本只用于显示 `1.1 → 1.2`，相同或不可读时仍以内容指纹显示“有更新”。Web 的 `hasUpdate` 不参与计划判断。

确认操作同时核对已审阅的资源指纹和来源提交。确认期间即使仅依赖变化、资源指纹不变，也拒绝接受未审阅的提交。批准后采用整个项目及公共包；运行快照独立保存批准引用，正在运行和续跑仍读取各自版本。

`ScriptProject` 保留原构造入口，Pulonia 传入经过校验的工作目录和固定来源上下文。`pathingScript.RunFileFromUser`、文件/目录存在查询、目录枚举及路线文本读取映射到该版本的 `repo/pathing`；缺失资源明确失败，不搜索其他仓库。非 Pulonia 调用继续使用 `User/AutoPathing`。

JS 执行前从缓存准备工作副本，准备和执行全程持有按仓库与脚本划分的跨实例文件锁。版本切换保留旧、新 `manifest.saved_files` 声明的数据；入口和清单采用确认内容。任务参数仍由各计划分别持有，工作目录中的代码修改不回写缓存。

## 验证

保留临时 Git 和文件式来源测试，覆盖同名隔离、仅检出索引、两文件更新规则、完整新项目、旧版本恢复、目录清单冻结、旧宿主读取路线、共享进度、互斥取消、等长同时间文件更新、确认提交竞争和提取失败保持原引用。新增场景覆盖浏览/预览不制作快照、路线只保留所选文件、JS 排除其他资源、公共块跨版本复用以及旧整仓快照兼容。仓库添加只补充来源类型识别、多项拖入拒绝、无效索引不注册和远程草稿确认后才注册的少量测试，不建立 WPF 自动化测试。按用户要求，后续只执行编译验证，不继续运行单测。
