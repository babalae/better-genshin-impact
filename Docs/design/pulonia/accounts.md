## 模型

一次运行由三件事决定：计划决定做什么，账户决定为谁做，实例决定在哪做。账户属于 Pulonia：账户目录、完成记录和首领领奖次数都存在 `User/Pulonia` 下，由 Pulonia 的存储层读写。

| 概念 | 含义 |
| --- | --- |
| 账户 | 一个原神游戏账号，以账户 ID 区分，显示为用户起的名称，带 UID 和服务器。没有登录资料也是账户 |
| 我的账户 | 账户目录初始自带的账户；目录中最多一个账户可以不填 UID，就是它 |
| 实例当前账户 | 用户为实例设置的值：这个实例的游戏现在登录的是哪个账户 |
| 运行账户设置 | 计划的 `account_id`：跟随当前账户（默认，不切换），或指定账户（必要时切换） |
| 运行账户 | 一次运行实际为哪个账户执行。运行开始时确定，写入运行记录 |
| UID 核验 | 指定账户的运行在切换前后读取游戏中的 UID，必须与目标账户一致，否则不执行业务节点 |
| UID 比对 | 跟随当前账户的运行开始时读取 UID，与当前账户比较。不一致只提示，运行照常进行 |
| 账户占用 | 同一账户同一时刻只能被一个运行占用，不论在哪个实例 |
| 账户进度 | 只属于某个账户的执行事实：完成记录和首领领奖次数。不进入计划和快照 |

完整术语和停用的说法见[统筹设计第 2 节](../instance-account-model.md#2-术语)。

- 进度跟着账户走。同一账户今天在主实例跑、明天在云原神跑，用的是同一份完成记录。
- 配置不按账户拆分。需要按账户区分设置时，用不同的计划或设置方案表达。
- 多个实例可以同时为不同账户运行。同一账户不能并行，由[账户占用](#账户占用)保证。

## 账户资料

账户目录 `User/Pulonia/accounts.json` 保存 `PuloniaGenshinAccountSettings`：`revision`（保存时检查冲突）和账户列表。目录至少有一个账户，首次使用时自动建立“我的账户”。默认账号 `default` 和 `multi_account_enabled`（原“显示账号切换步骤”的界面偏好）已删除。

每个账户 `PuloniaGenshinAccountProfile`：

| 字段 | 说明 |
| --- | --- |
| `id` | `acc_` 加 16 位 |
| `name` | 必填，目录内不重复 |
| `uid` | 完整 9 到 10 位，目录内不重复。新增账户必须填写；只有“我的账户”可以留空 |
| `server_time_zone` | 服务器时区，取值与触发器相同：`UtcPlus8`（国服、亚服、港澳台）、`Europe`（欧服）、`America`（美服）。新增账户时默认取通用配置中的服务器时区 |
| `login_mode` | `Automatic`、`Image`、`ListText`、`Password`；`Automatic` 依次尝试图片、列表文字，密码作为备用（删除 `LoginMode` 待定 D6） |
| `image_path` | 相对 `User/Pulonia` 的账户标识图片，只允许位于 `account-images/` |
| `list_text` | 账号列表 OCR 匹配文字 |
| `credential_reference` | Windows 凭据目标名；只有 `Automatic` 与 `Password` 保留 |

`login_mode`、`image_path`、`list_text`、`credential_reference` 合称登录资料，都是可选的。只有需要 BetterGI 自动切换到这个账户时才填写。

- 填写 UID 的方式：手动输入，或在账户页点“从当前游戏读取”（要求本实例游戏停在主界面）。
- 列表顺序可以调整。
- 修改 UID 时，狛荷屋中该账户的数据目录随之改名；新 UID 已有狛荷屋数据时拒绝修改。
- 删除账户时，一并删除它的账户进度、凭据、不再被引用的账户图片和狛荷屋记录，删除前列出这些数据并确认。以下情况拒绝删除：
  - 仍有计划指定该账户。有计划文件读不出时也拒绝，因为无法确认是否被引用。
  - 它是某个实例的当前账户，需先把这些实例改为其他账户。
  - 账户正被运行占用。

### 我的账户

- 首次使用时自动建立，放在列表第一位。只有一个账号的用户始终只用它，不需要任何设置。
- 目录中最多一个账户可以不填 UID，初始的“我的账户”就是这个账户。没有 UID 时，它不能被计划指定，不做 UID 比对，也不出现在狛荷屋。填写后这些功能自动可用。已填的 UID 只有在没有其他账户缺 UID、也没有计划指定它时才能清空。
- 改名、调整顺序或删除都按普通账户处理，没有其他特殊身份。
- 它是普通账户，不是旧“默认账号”那种“当前登录的任何账号”的别名。进度只记在它自己名下。

### 凭据

- 密码只存在 Windows 凭据管理器，目标名按账户固定：`BetterGenshinImpact.Pulonia.Account.<账户ID>`；改密码时覆盖同一条目。
- 由存储层 `PuloniaTaskStore.SaveAccountSettingsAsync` 管理：先耐久保存 `accounts.json`，成功后才写入本次填写的凭据，再删除目录不再引用的旧凭据。目录保存失败时不触碰任何凭据，不会留下孤立条目；凭据写入失败时提示重新填写。
- 账户被删除、或登录方式改为图片或列表文字时，保存后删除其旧凭据。
- 运行快照只记录凭据目标名。排队或续跑的运行在登录时读取**当前**凭据：改密码后旧运行用新密码；凭据被删除后旧运行无法再用密码登录。

### 账户图片

- 每次导入或采集都新建 `account-images/<账户ID>-<yyyyMMdd-HHmmss>.png`，同秒重名追加 `-2`、`-3`，以排他方式创建，从不覆盖。
- 因为文件不会被覆盖，运行快照只记录 `image_path` 就能固定图片内容，不再冻结图片版本或在运行前复核指纹。用户手改磁盘上的图片属于不处理的场景。
- 删除账户时一并删除不再被引用的图片；账户仍在时被替换的旧图片暂不清理。
- 导入图片按 1080p 账户标识裁剪图处理，其他分辨率优先用“采集当前账户图片”。

## 实例当前账户

- 每个实例保存一项设置：本实例的游戏现在登录的是哪个账户。存在 `User/Pulonia/instances/<目录名>/settings.json` 的 `current_account_id` 中，值为 `null` 表示“未确定”，实例目录名见[统筹设计 6.1 节](../instance-account-model.md#61-实例键)。
- 这是唯一按实例保存的 Pulonia 设置。它描述“这个游戏环境登录着谁”，不进入计划和快照。
- 初始值：
  - 实例首次使用时，取账户列表的第一个账户。只有一个账号的用户就是“我的账户”，永远不用修改。
  - 新建云原神实例时，如果目录有多个账户，在新建窗口里选择，默认第一个。
- 修改入口：
  - 本实例标题栏的账户徽标，以及账户页顶部。
  - UID 比对不一致的提示中，可以一键改为读到的 UID 对应的账户（如果目录里有）。
  - 主实例还可以在标题栏实例列表和“运行于”中修改子实例的当前账户。设置是共享文件，不经过 IPC。
- 修改立即保存，原子替换，后写者覆盖。正在运行的任务不受影响，下一次运行开始时生效。
- BetterGI 只在两种情况下自己改写这项设置：
  - 指定账户的运行切换并核验成功后，改为目标账户。
  - 切换中途失败时（例如已登出、停在登录界面），改为“未确定”。之后跟随当前账户的运行会进入待处理，直到用户重新选择。

## 运行账户设置

普通计划和一条龙都用同一个计划字段 `account_id`：

| `account_id` | 界面显示 | 含义 |
| --- | --- | --- |
| 空（默认） | 跟随当前账户 | 不切换，为实例当前账户执行 |
| `acc_…` | 指定账户：乙 | 为乙执行。游戏中登录的不是乙时，先自动切换到乙 |

- 取代 `accounts`，改为单值，两种计划都支持。字段见[模型与配置](model.md#计划-puloniataskplan)。
- 只能指定填写了 UID 的账户，因为切换和核验都要按 UID 找到目标。
- 定时、热键、手动运行和主实例下发都使用计划的设置。触发器不再有 `account_id`，不能覆盖计划的设置。
- 不含游戏节点的计划（只有 Shell、C#）不确定运行账户。

## 运行开始时确定运行账户

含游戏节点的运行，在执行第一个节点前确定运行账户。实例当前账户在这时读取最新设置，而不是在提交时读取：队列中前一个运行切换了账户，后面跟随当前账户的运行就为切换后的账户执行。

### 跟随当前账户与 UID 比对

1. 运行账户就是实例当前账户。当前账户为“未确定”时，运行进入待处理，提示先设置本实例当前账户。
2. 取得[账户占用](#账户占用)。
3. UID 比对：当前账户填写了 UID，且游戏此时停在主界面时，读取 UID。只截图，不按键，最多约 3 秒。

| 比对结果 | 处理 | `uid_check` |
| --- | --- | --- |
| 一致 | 记为“UID 一致” | `matched` |
| 不一致 | 提示后继续运行，进度仍记在实例当前账户名下 | `mismatched`，另记读到的 UID |
| 读不到（不在主界面或识别失败） | 记为“未比对”，不提示 | `skipped` |
| 当前账户没有 UID | 不读取，记为“未比对” | `skipped` |

不一致时的提示：

- 遮罩日志输出警告，本实例弹出通知：“本实例当前账户是甲（UID 尾号 1111），游戏中读到尾号 2222。本次仍按甲记录进度。”
- 目录中有 UID 为 2222 的账户时，通知带“把当前账户改为乙”按钮，修改从下一次运行开始生效。
- 运行记录写入警告和读到的 UID，执行记录列表用提示色标出这次运行。
- 标题栏账户徽标显示提示色，直到当前账户被修改或下一次比对一致。

跟随当前账户的运行只在开始时比对一次，节点执行中不再读取 UID。比对只提示不阻止，因此：

- 只用一个账号的用户，即使从未填写 UID，也永远不会被拦下。
- 从七圣召唤对局等特殊界面开始的任务，开局读不到 UID，照常运行。
- 用户在游戏里手动换号、但没有修改实例当前账户时，运行仍按设置的账户记录进度。账户填了 UID 且开局在主界面时，用户会收到提示；否则 BetterGI 发现不了。错记的完成记录可以在账户页清除。

### 指定账户

先取得目标账户的占用，再按[账户准备与 UID 核验](#账户准备与-uid-核验)切换并核验。核验成功后把实例当前账户改为目标账户，之后才执行业务节点。

### 运行记录中的账户

| 字段 | 内容 |
| --- | --- |
| `account_id` | 运行账户 |
| `account_source` | `instance_current`（实例当前账户）或 `specified`（计划指定） |
| `verified_uid` | 指定账户时为核验通过的 UID；跟随当前账户时为空 |
| `uid_check` | 跟随当前账户时为 `matched`、`mismatched` 或 `skipped`；指定账户时为空 |

服务器偏移也在这时按运行账户的服务器写入运行记录，见[账户与路线 CD](#账户与路线-cd)。

### 续跑

续跑沿用原运行的运行账户：

- 原运行是指定账户的，按指定账户的规则核验原 `verified_uid`。
- 原运行是跟随当前账户的，要求本实例当前账户与原运行账户相同，不同时提示先修改；相同则照常做 UID 比对。

### 谁负责账户正确

[Pulonia 需求](requirements.md#边界分级)中“可能在错误账户上执行”这一必须处理的边界分成两种：

- 指定账户：BetterGI 负责，切换后严格核验 UID，失败不执行。
- 跟随当前账户：用户负责实例当前账户与游戏一致，BetterGI 比对 UID 并提示，不保证。

| 场景 | 读取 UID | 不一致时 |
| --- | --- | --- |
| 指定账户：切换前 | 回到主界面后读取 | 切换；不能切换时进入待处理 |
| 指定账户：切换后、节点开始时 | 读取 | 进入待处理，不执行业务节点 |
| 跟随当前账户：运行开始 | 只在主界面时读取，不按键 | 提示，继续运行 |
| 跟随当前账户：节点执行中 | 不读取 | — |
| 账户页“从当前游戏读取” | 只在主界面时读取 | — |

## 账户准备与 UID 核验

只用于指定账户的运行，普通计划和一条龙都适用。账户准备是服务级前置阶段（`PuloniaTaskService.PrepareGenshinAccountAsync`），不是任务树节点；计划含启用的游戏节点时执行。

1. 取得目标账户的[账户占用](#账户占用)；取得失败时直接进入待处理，不切换，避免切换后才发现目标账户正在别处运行。然后取得游戏任务租约；租约取不到按账户准备失败处理。
2. 回到主界面读取当前 UID。等于目标账户的 UID 时不切换，跳到第 6 步。
3. 不等于时判断本实例能否切换：
   - 实例是本机 PC 官服窗口（主实例或桌面分身），且目标账户有登录资料：先做[切换前检查](#切换前检查)，再切换。
   - 实例是云原神，或目标账户没有登录资料：不运行，进入待处理：“游戏中登录的不是乙，本实例不能切换到乙”。界面在提交前按实例当前账户预先提示。
4. 切换：进入账户选择 → 按登录方式用图片模板、账号列表 OCR 或密码登录 → 回到主界面 → 核验。最多两轮，总预算 180 秒，响应等待与轮询间隔 500 ms。
5. 核验 UID：主界面连续两帧新截图 OCR 得到相同的完整 9 到 10 位 UID，且等于目标 UID，不使用相似度。第 2 步的读取也用同样的方式。
6. 核验成功后把实例当前账户改为目标账户。核验 UID 与“切换账户”节点结果一起写入本实例的 `state.json` 后，才开始执行业务节点。

此后每个需要游戏的节点尝试在取得输入后再次核验该 UID（D7 待定是否只在准备和恢复后核验），核验失败时运行进入待处理。验证码、二次验证、明确的密码错误、登录态失效、UID 不符或候选不唯一时都进入待处理，不执行业务，也不把结果记到目标账户。切换中途失败、游戏已登出或停在登录界面时，实例当前账户改为“未确定”。

切号器（`PuloniaGenshinAccountSwitcher`，接口 `IPuloniaGenshinAccountSwitcher`）由 `AccountSwitchStateMachine` 的按钮模板与 `SwitchAccountMultipleMode` 的列表 OCR、密码和验证码识别移植而来，与业务共用输入所有权和取消令牌。只支持 PC 官服本机窗口；B 服不做专门检测，会在模板匹配阶段失败而不会误操作。云原神实例不能切换账户。子实例的运行由子实例自己的协调器执行，切换与核验在该子实例的游戏中完成。

接口调整：删除 `PrepareAsync` 对默认账号“读到任意 UID 即返回”的分支；新增只读、不按键的 `TryReadUidAsync`，供 UID 比对和账户页“从当前游戏读取”使用。它只在主界面读取，与核验一样要求连续两帧新截图得到相同的完整 UID。

## 账户占用与切换前检查

### 账户占用

- 同一账户同一时刻只能被一个运行占用，不论在哪个实例。游戏同样不允许一个账号同时在两处登录。
- 运行在确定运行账户后、执行第一个业务节点前取得占用，运行结束时释放。排队中的运行不占用。
- 实现：运行期间以“允许他人读、不允许他人写”的方式打开 `User/Pulonia/accounts/<账户 ID>/run.lock`，写入实例键、运行 ID 和开始时间。进程退出时由系统释放句柄，崩溃不会留下占用。
- 取得失败时，运行进入待处理，不排队等待，因为这几乎总是设置错误（统筹设计 A7，已决定）。提示内容：“账户“我的账户”正在云原神 A 运行。多个实例同时运行时，请为每个实例设置不同的当前账户。”
- 界面提前检查：手动运行，或在“运行于”、触发器执行实例中选择多个实例时，若目标实例的当前账户与正在运行的账户重复，或几个选中实例的当前账户相同，提交或保存前提示，并在提示里直接修改各实例的当前账户。实际做法：手动运行时弹出说明，用户选“否”后展开“运行于”，在那里修改各实例的当前账户，没有单独的账户编辑对话框；保存定时触发器时只说明问题，用户可以坚持保存。

这条规则是“多个实例同时运行时要求区分账户”的入口。只用一个实例的用户永远不会遇到它。

### 切换前检查

- 切换到乙之前，如果另一个在线实例的当前账户是乙，这次切换会把那边挤下线：
  - 在本实例界面手动运行：弹出提示，用户确认后继续。
  - 触发器提交和主实例下发：不切换，运行进入待处理。
- 在线判断：每个实例运行期间以同样的方式打开 `User/Pulonia/instances/<目录名>/online.lock`，其他实例尝试打开失败即视为在线。不经过 IPC。

### 什么时候需要设置账户

| 情况 | 用户需要做什么 |
| --- | --- |
| 只有一个账号，在主实例、桌面分身、云原神之间轮流使用 | 什么都不用做 |
| 有多个账号，在同一个实例里手动换号后运行 | 换号后把标题栏的当前账户改成对应账户。忘了改时，如果账户填了 UID，运行开始会提示不一致，可在提示中一键修改 |
| 多个实例同时运行 | 为每个实例设置不同的当前账户。没设置时，提交前会提示，选“否”后可在展开的“运行于”里设置 |
| 让 BetterGI 自动切换账号 | 为目标账户填写 UID 和登录资料，并把计划设为“指定账户” |

## 账户与路线 CD

- 路线 CD 不单独存储，由两部分推算：刷新规则属于计划设置，运行时固定进快照（`refresh_rule`）；完成记录属于运行账户的进度。
- 完成记录（原“账本”）按账户存放在 `User/Pulonia/accounts/<账户 ID>/route-completions.json`，每个账户的每份路线只保留最新一条，不再有作用域键。
- 判定时只读运行账户的完成记录。地图追踪节点需要游戏，所以含地图追踪节点的运行一定有运行账户。
- 日切时区取运行账户的 `server_time_zone`，在运行开始确定运行账户时写入运行记录，续跑沿用；不再在入队时按通用配置填写。通用配置的服务器时区只作为新增账户的默认值，以及旧功能和 JS `ServerTime` 的时区。
- 首领领奖次数移到 `User/Pulonia/accounts/<账户 ID>/boss-rewards.json`，按运行账户记录，不再用空字符串或 `default` 作键。
- 任务树 CD 标记、运行预览和路线 CD 表单：指定账户的计划按该账户显示，跟随当前账户的计划按本实例当前账户显示，日切时区取该账户的服务器。目录有多个账户时，页面顶部的“CD 按账户：乙 ▾”可以临时查看其他账户，只影响本页面显示。
- 错记的完成记录可以在账户页的“路线 CD”中清除。任一实例都可以清除，在 `.writer.lock` 内读改写，不能撤销，也不影响运行历史。

完成记录的格式、写入顺序和跨实例读取见[结果、CD 与存储](results-and-storage.md#文件级路线-cd)。

## 界面

这里只列摘要，详细界面见[界面 · 账户页](user-interface.md#账户页)。

- Pulonia 导航新增“账户”页，所有实例都显示。它取代 `PuloniaGenshinAccountsWindow`：原“新一条龙 → 更多 → 账号管理”和“切换账户”面板里的管理按钮都改为跳转到账户页。

- 触发设置删除“账号参数资料”下拉框和“运行账号”说明，定时触发器增加“执行实例”多选；热键触发器没有这个选项。
- 执行记录增加“实例”和“账户”两列；运行信息显示执行实例和运行账户，例如“乙 · 本实例当前账户 · UID 一致”“丙 · 计划指定 · 已核验 UID”。

## 与狛荷屋的关系

狛荷屋不再维护自己的 UID 列表：

- UID 下拉框列出账户目录中填写了 UID 的账户，显示为“名称（UID）”，顺序与账户列表一致。打开页面时默认选中本实例当前账户。
- 删除狛荷屋的“新增 UID”浮窗，改为“管理账户”，跳转到账户页。
- 账户菜单只保留“清空库存记录”。删除账户只在账户页进行，会一并删除狛荷屋记录。
- 导入交换文件时，文件中的 UID 不在账户目录里，就提示“创建账户“账户 尾号 5678”并导入？”，确认后先建账户再导入。
- 数据仍按 UID 存在 `User/AccountRecords/<uid>/`，格式不变；`InventoryStore` 不再从目录名枚举 UID，改为由页面传入账户目录中的 UID。
- 狛荷屋通过 `IPuloniaAccountService` 读取账户列表、订阅账户变化。依赖方向是狛荷屋依赖 Pulonia 账户服务，反过来不依赖。
- UID 修改和删除账户时，`PuloniaAccountService` 通过扩展点 `IPuloniaAccountDataHandler` 让狛荷屋改名或删除数据目录。接口定义在 Pulonia，狛荷屋的实现是 `AccountRecordsAccountDataHandler`，依赖方向不变。
- `User/AccountRecords/` 下有数据、但账户目录里没有对应 UID 的目录不会显示，也不会自动建账户。要继续查看，在账户页新建填写该 UID 的账户。

`IPuloniaAccountService` 由应用服务层的 `PuloniaAccountService` 实现，负责账户目录、实例当前账户、账户占用、切换前检查、UID 比对和账户进度读写；存储仍由 `PuloniaTaskStore` 负责，见[统筹设计 5.7 节](../instance-account-model.md#57-命名与代码对照)。
