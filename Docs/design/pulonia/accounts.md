# Pulonia：多账号

[返回总览](README.md) · [用户故事](requirements.md) · [路线图](roadmap.md)

多账号决定“为谁执行”，对应 US-11。2026-10-24 从原 `scheduling-and-managed.md` 拆出并按当前代码改写，原文见[归档](archive/scheduling-and-managed.md)。范围：PC 官服、单个 Windows 交互会话内顺序切号（路线图步骤 10.1，已实现待验收）。

## 默认账号与账号绑定

- **默认账号**（ID `default`）表示当前登录账号，免配置：不填写登录资料和 UID，执行时不切号、不主动登出。
- 每份一条龙配置绑定一个运行账号，缺省为默认账号；`accounts` 中启用的绑定超过一个时拒绝运行。`Plan.Accounts` 改为单个账号 ID 待定 D5。
- 普通计划没有账号准备，也不核验 UID，触发器的 `account_id` 不会切号。按账号替换预设（`preset_selections`）已随共享设置删除，这个字段目前没有参数用途，去留并入 D5。
- 定时、热键、手动运行和续跑都使用配置绑定的账号，触发器不能单独覆盖；手动请求指定了不同账号时拒绝。
- BetterGI 多实例不是多账号模型：同一交互会话内按顺序切号，不并行。

## 账号资料

`User/Pulonia/accounts.json` 保存 `PuloniaGenshinAccountSettings`：`revision`（保存时检查冲突）、`multi_account_enabled`（“显示账号切换步骤”的界面偏好）和账号列表。每个账号 `PuloniaGenshinAccountProfile`：

| 字段 | 说明 |
| --- | --- |
| `id` | `acc_` 加 16 位；默认账号为 `default` |
| `name` | 显示名称 |
| `uid` | 非默认账号必填，完整 9—10 位；同一 UID 只建一份资料，可供多个配置复用 |
| `login_mode` | `Automatic`、`Image`、`ListText`、`Password`；`Automatic` 依次尝试图片、列表文字，密码作为备用（删除 `LoginMode` 待定 D6） |
| `image_path` | 相对 `User/Pulonia` 的账号标识图片，只允许位于 `account-images/` |
| `list_text` | 账号列表 OCR 匹配文字 |
| `credential_reference` | Windows 凭据目标名；只有 `Automatic` 与 `Password` 保留 |

### 凭据

- 密码只存在 Windows 凭据管理器，目标名按账号固定：`BetterGenshinImpact.Pulonia.Account.<账号ID>`；改密码时覆盖同一条目。
- 由存储层 `PuloniaTaskStore.SaveAccountSettingsAsync` 管理：先耐久保存 `accounts.json`，成功后才写入本次填写的凭据，再删除目录不再引用的旧凭据。目录保存失败时不触碰任何凭据，不会留下孤立条目；凭据写入失败时提示重新填写。
- 账号被移除、或登录方式改为图片或列表文字时，保存后删除其旧凭据。
- 运行快照只记录凭据目标名。排队或续跑的运行在登录时读取**当前**凭据：改密码后旧运行用新密码；凭据被删除后旧运行无法再用密码登录。

### 账号图片

- 每次导入或采集都新建 `account-images/<账号ID>-<yyyyMMdd-HHmmss>.png`，同秒重名追加 `-2`、`-3`，以排他方式创建，从不覆盖。
- 因为文件不会被覆盖，运行快照只记录 `image_path` 就能固定图片内容，不再冻结图片版本或在运行前复核指纹。用户手改磁盘上的图片属于不处理的场景。
- 被替换或随账号删除而不再引用的旧图片暂不清理。
- 导入图片按 1080p 账号标识裁剪图处理，其他分辨率优先用“采集当前账号图片”。

### 账号管理窗口

“新一条龙 → 更多 → 账号管理”打开 `PuloniaGenshinAccountsWindow`。窗口内是独立草稿，点击“保存账号设置”后一次保存；关闭时只取消本窗口的图片采集。移除账号前检查：有任何计划文件读不出时拒绝（无法确认是否被引用）；有计划仍绑定该账号时拒绝。移除在保存后生效，同时删除其凭据。

## 账号准备与 UID 核验

账号准备是服务级前置阶段（`PuloniaTaskService.PrepareGenshinAccountAsync`），不是任务树节点。一条龙计划含启用的游戏节点时执行：

1. 取得游戏任务租约；租约取不到按账号准备失败处理。
2. 读取当前 UID：默认账号直接采用；指定账号已登录时跳过登出。
3. 否则切号：进入账号选择 → 按登录方式用图片模板、账号列表 OCR 或密码登录 → 回到主界面 → 核验。最多两轮，总预算 180 秒，响应等待与轮询间隔 500 ms。
4. 核验 UID：主界面连续两帧新截图 OCR 得到相同的完整 9—10 位 UID，且等于目标 UID，不使用相似度。
5. 核验 UID 与“切换账号”节点结果一起写入 state.json 后，才开始执行业务节点。

此后每个需要游戏的节点尝试在取得输入后再次核验该 UID（D7 待定是否只在准备和恢复后核验）。验证码、二次验证、明确的密码错误、登录态失效、UID 不符或候选不唯一时都进入待处理，不执行业务，也不把结果记到目标账号。续跑时核验历史运行的实际 UID，默认账号也不例外。

切号器（`PuloniaGenshinAccountSwitcher`，接口 `IPuloniaGenshinAccountSwitcher`）由 `AccountSwitchStateMachine` 的按钮模板与 `SwitchAccountMultipleMode` 的列表 OCR、密码和验证码识别移植而来，与业务共用输入所有权和取消令牌。只支持 PC 官服本机窗口；B 服不做专门检测，会在模板匹配阶段失败而不会误操作。子实例执行时，切号与核验在该子实例的游戏中完成。

## 账号与路线 CD

文件级路线 CD 的作用域键为 `cn/world/{身份}`：

- 未切换账号（默认账号，以及所有普通计划）身份为 `default`，代表“当前登录账号”，普通计划与一条龙默认账号共享 CD；
- 切换到指定账号时身份为核验后的 UID。

身份不依赖计划名、节点 ID 或账号资料 ID。此前一条龙使用核验 UID、普通计划使用资料 ID 的旧账本键因此失效，相关路线文件可能多跑一次。详见[结果、CD 与存储](results-and-storage.md#作用域与键)。

编辑时的任务树标记和运行预览按同一规则选作用域：普通计划与一条龙默认账号为当前登录账号；一条龙绑定指定账号时按账号资料的 UID 预测，运行时以核验后的 UID 为准。路线 CD 总览把 `default` 显示为“当前登录账号”，UID 显示为账号资料名。

## 界面

- 新一条龙“配置”标题旁常驻“运行账号”按钮（绑定非默认账号时显示），点击修改绑定；绑定的账号资料被删除时提示重新选择。
- “更多 → 显示账号切换步骤”只控制清单首位是否显示不可拖拽、不可删除的“切换账号”准备项；绑定始终生效，关闭显示不会停止切号。
- 一条龙触发设置显示“运行账号”说明，而不是可选的账号下拉框。
- 执行记录的“来源 / 作用域”只显示账号；节点结果中可见实际核验 UID。
