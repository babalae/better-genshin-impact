> 归档于 2026-10-24：以下为 `user-interface.md` 中的步骤 2、步骤 5 实现记录与 10.1 账号准备段落原文，属于过程记录，不代表当前实现。当前界面基线见 [user-interface.md](../user-interface.md)。

## 新一条龙账号准备（步骤 10.1，待验收）

“更多 → 账号管理 / 多账号设置”提供默认账号及可选的真实账号资料。默认账号沿用当前登录态，用户不填写任何登录信息即可执行；多账号显示缺省关闭。启用显示后，清单首位呈现不可拖拽、不可删除的“切换账号”准备项，右侧选择当前配置绑定账号；这不是持久化任务树节点，原八项默认任务不变。显示开关只控制界面，已经保存的账号绑定仍有效。单配置定时和热键遵循同一账号绑定，不允许触发器单独覆盖。

账号管理支持完整 UID、自动/图片/列表文字/密码方式、图片导入或采集，以及可选 Windows 凭据。窗口内编辑为独立草稿，点击“保存账号设置”后生效；关闭时取消本窗口的采集，不取消其他入口任务。移除账号前检查已保存计划引用，历史图片及凭据保留供续跑。实际效果由用户用真实账号验收。

步骤 10.2 的连续运行窗口与批次定时接管尚未交付，范围与规则见[开发计划](development-plan.md)。

## 步骤 2 实现入口

主菜单“任务计划”现已接入 `PuloniaTaskPlanPage`。页面左侧保存多个计划编辑会话，计划支持右键重命名和拖拽排序，顺序写入 `User/Pulonia/plan-order.json`。右侧“任务”页签使用 `TreeView`、GongSolutions 拖拽和可双向绑定选中项的 Behavior 编辑同一配置树。树结构命令集中在节点右键菜单，不保留顶部新增工具条、手动保存按钮或行内复制/删除按钮；结构变更以有上限的变更前快照撤销，不引入事件溯源。自动保存期间仍可继续编辑，新变更不会被较早的保存副本覆盖；撤销恢复内容时沿用最新磁盘修订，避免后续自动保存产生伪冲突。

节点配置弹窗使用严格 JSON 保真处理数组、布尔值、null 和数值；分组执行次数属于明确的结构配置，使用独立数字输入框，不混入公共参数 JSON。共享参数预设是一份按任务类型、可选资源 ID 和参数格式版本约束的命名参数集合，用于让多个节点或多个计划复用同一套配置；它不包含任务结构、执行顺序或计划引用。有效来源预览按共享预设、祖先分组覆盖、节点显式参数的顺序合并，因此局部显式设置始终优先。步骤 2 页面只负责为兼容节点选择和刷新已有预设，预设的创建、重命名与编辑入口仍待后续参数管理界面，不应让空下拉框看起来像任务模板功能。能力默认值要等执行器或资源清单注册后纳入，不在界面中猜测。执行记录和触发方式页签仅保留后续入口，本步骤不创建运行状态或调度逻辑。

## 步骤 5 实现入口

“任务计划”的新增菜单直接打开 `PuloniaTaskCreationDialog`，不再设置独立“任务库”菜单或全量资源聚合页。任务树右键只表达“要创建哪类任务”，具体内置能力、资源、名称、目录方式和参数都在类型专用弹窗中完成；确认结果作为一次编辑写入，取消不会先插入占位节点。弹窗明确提示当前内容来自本机仓库副本：官方、第三方列表只读本机 clone，本地仓库读取用户选择目录；添加过程不访问远端、不隐式同步，确认时固定当时的本机仓库版本并保留资源。弹窗使用注册能力的 Schema 生成布尔、枚举、文本与 JSON 字段，只保存相对能力默认值真正变化的显式覆盖；JS 的 `settings` 例外地由所选脚本自己的设置定义生成，不要求用户编辑原始 JSON。

资源索引只在用户选择路线、JS 或录制回放任务后扫描当前类型的目录结构、文件属性和 JS 项目清单位置，最多索引一万项并跳过重解析点；不会在进入主页面时扫描全部资源。搜索只过滤缓存且带短防抖，详情在选中后读取。地图追踪索引转换为可折叠目录树，仍支持目录引用和文件选择；JS 按需读取清单以定位设置定义和推荐名称，README 由原生 Markdown 控件直接按文件路径渲染，不做字符截断。路线与录制资源不在列表阶段解析 JSON 正文。非树形列表启用 WPF 容器回收，刷新由用户显式触发。“获取更多资源”复用现有脚本仓库，关闭后自动刷新当前类型；路线录制编辑、JS 和录制回放工具仍从各自原页面进入。

路线与录制目录默认建立固定版本的目录引用，也可确认后一次性展开为保留目录结构或扁平的普通任务；展开过程先完成有限完整枚举，超过安全上限时整体拒绝，不能静默只添加部分文件。单资源、展开叶子和目录引用均保存内容指纹，运行准备检测到变化后拒绝执行；用户可在任务树节点菜单查看旧、新指纹并显式更新。这样吸收 d-v3 “先选资源再创建”和集中预览的优点，同时保留 Pulonia 的单一任务模型、版本快照和原子编辑基线，没有把旧 GearTask 流程复制进来。
