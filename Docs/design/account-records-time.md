# 狛荷屋库存上报时间约定

## 单一业务时间

- 库存上报只使用 `RecordedAt`（交换文件中为 `recordedAt`），表示该库存总数实际采集或经用户确认的时间，与 OCR、接口、脚本等获取方式无关。
- 字段必填，使用带时区的时间文本，例如 `2026-10-28T12:00:00+08:00`。内部统一存为 UTC。
- 不使用发送、接收、文件修改或导入时间代替实际记录时间；缺失、无法解析、缺少时区或晚于本机时间超过五分钟的记录不采纳。
- 增量的 `RecordedAt` 表示变动实际发生时间，同样必填。
- 接收时间仅用于事件追溯与重复上报统计，不参与库存新旧和核实判断。

## 库存与核实

- 比当前确认库存更早的记录，或同一时间数量、到期批次不一致的记录，按库存冲突处理。
- 上报记录时间必须严格晚于该物品全部待核实增量的发生时间，才能完成这轮核实；相同时间无法判断先后，不自动核实。
- 增量与已有确认库存同时间时拒绝并提示先后不明；脚本须保留实际采集精度，不统一改写为发送时间。
- 无法覆盖待核实增量时，保留原确认库存与待核实事件。
- 合法的新库存记录更新数量并核实增量后，将该物品积压错误归档，合并为 Warning，提示“曾有错误，当前数量已核实”。保留原始错误证据；重复旧记录不作为新的核实。
- 人工确认使用提交时刻，按既有规则归档相关错误、终止未完成核实，不改写已经完成的核实结果。

## 交换文件标准

- 交换文件使用 `format=BetterGI.AccountRecords`、`version=1`，库存记录和增量的业务时间字段为 `recordedAt`。
- 库存记录或增量中出现 `verifiedAt` 即拒绝导入，包括值为 null 的情况。
- `recordedAt` 按统一规则校验，不以当前时间兜底。
