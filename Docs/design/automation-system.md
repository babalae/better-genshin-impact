## 核心决策

1. 使用 `BetterGenshinImpact.Pulonia` 命名空间和 `PuloniaTask` 相关实体；保留 d-v3 的 `root_task / children` 树格式。
2. 一条龙是同一份任务计划的简洁视图；托管生成计划，树编辑器手工编辑计划，所有入口复用同一执行语义。
3. 主链保持“入口 → 任务服务 → 类型执行器”，文件存储旁路提供支持。允许集中构建只读执行树；具体形式在模型阶段用样例验收，不再禁止第二种运行时表示，也不照搬层层转发的转换/调度链。
4. 触发、空闲准入与资源 CD 分开；开始执行前固定版本、解析有效配置，运行状态与编辑模型分开。
5. 游戏会话与截图按需获取，Shell 和纯计算任务不强制启动截图器；首版串行执行，共同管理输入所有权。
6. 完成结果必须附带证据，执行结束不自动等于采集或领奖成功；支持节点级续跑和有限异常恢复。
7. 不引入 Quartz、SQLite、ORM 或通用工作流框架。使用 .NET 调度循环、现有热键和 JSON 文件；当前不要求新增第三方库。

## 开发约定

**每一步完成实现与自查后，提交给用户验收并停止；收到明确通过后才能开始下一步。** 子步骤遵守同样规则。编译成功不能代替用户验收；当前整理文档不代表开始实施。

基础任务系统先可用，再补可靠调度、迁移、多账号和目标托管。完整 box、库存与圣遗物识别按能力分步验收，缺失能力明确标记。具体步骤与验收记录只维护在[开发计划](pulonia/development-plan.md)，其他文档不另存一套进度。
