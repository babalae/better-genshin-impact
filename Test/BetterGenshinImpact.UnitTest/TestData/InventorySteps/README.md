# 库存分步导入样例

使用空测试账号 `990280168`，依次导入 `steps/00` 至 `steps/11`，不要覆盖补充字典，期间不归档或手工修改。

- 00～06：库存、两轮增减核实、错误、分类及到期批次。
- 07～08：没有确认库存时的增减，以及首次确认库存。
- 09～11：须臾树脂同时存在错误、过期待核实、提醒、增减待核实和历史完成事件。最终三条错误合并、两条待核实增减合计 +1；表格亮红灯，底部展示五类卡片。

点击状态灯固定提示，再滚动检查各卡片。归档提醒不应影响错误及待核实事件；重复导入 11 不应新增事件。

`rules/warning-rules.json` 是可选测试规则，安装到独立测试数据根后还可验证数量和临期提醒。不要覆盖日常使用的规则。

这些 JSON 使用固定绝对时间；将来重放时，未来时间错误与到期检查的结果可能改变。`expected.json` 记录生成时的预期；`extend_delta_steps.py` 可依据第六步重新生成 07～11，但不会更新 00～06 的时间。不要混用不同生成轮次的数据。
